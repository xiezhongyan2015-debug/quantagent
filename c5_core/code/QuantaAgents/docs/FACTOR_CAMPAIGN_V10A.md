## 启动、查看、停止与恢复

在 PowerShell 中设置这三个路径。入口脚本会定位自己的研究代码，无需修改旧版本的默认入口。

```powershell
$campaignPython = '/Users/leslie/Downloads/中证500量化60min/c5_core/code/QuantaAgents/.venv/Scripts/python.exe'
$campaignEntry = '/Users/leslie/Downloads/中证500量化60min/c5_core/code/QuantaAgents/scripts/run_factor_campaign_v10.py'
$campaignRoot = 'F:\V10A_Factor_Research'
```

| 命令 | 作用 |
|---|---|
| `init` | 建立冻结协议、参考库和初始状态。已有研究根目录时返回现有状态，不清空记录。 |
| `start` | 初始化后启动持续研究，包括提案、校准、批次研究、复盘及通过工程审查后的版本切换。 |
| `status` | 读取版本、阶段、批次、各类计数、最佳六年最差年度 IC、目标差额、成本与阻塞原因；不调用模型或重算行情。 |
| `stop` | 写入停止请求。控制器在检查点退出，模型网关也检查停止信号；已经开始的一次数值计算可能需要先返回。 |
| `resume` | 清除用户停止标记，从现有账本和检查点继续，优先恢复已保存的模型回执和计算结果。 |

首次启动：

```powershell
& $campaignPython $campaignEntry start --root $campaignRoot
```

只初始化、不开始研究：

```powershell
& $campaignPython $campaignEntry init --root $campaignRoot
```

查看状态；此命令可在另一个 PowerShell 窗口执行：

```powershell
& $campaignPython $campaignEntry status --root $campaignRoot
```

请求停止：

```powershell
& $campaignPython $campaignEntry stop --root $campaignRoot
```

停止、进程中断或外部条件恢复后继续：

```powershell
& $campaignPython $campaignEntry resume --root $campaignRoot
```

主运行采用单一控制器锁。已有运行时，通过 `status` 查看，通过 `stop` 停止；不要同时开启第二个 `start` 或 `resume`。锁文件存在本身不能证明进程仍在运行，程序使用操作系统释放的锁判断实际占用。

另有 `prepare`、`calibrate`、`run`、`factor-batch`、`combination-batch`、`review`、`advance` 分阶段入口，供定向诊断使用；`--limit` 只影响两个批次入口的本次数量，不能改变验收条件、版本最低规模或资源上限。日常操作优先使用上面的五个命令。

每版先研究，再以结果证据复盘。窗口、权重调整属于研究批次，新增公式属于结构修订。只有实现、调度、数据接口、算子或组合机制发生实质变化，才进入下一框架版本。

工程宿主把补丁放入独立副本，运行固定的定向测试和原验收器测试，再通过另一次真实模型调用作独立实现审查。当前自动补丁范围限定在候选生成、选拔、组合、数值与缓存实现，以及确实接入现有计算路径的新算法模块。验收器、目标、年份、标签、协议、控制器关键保护、模型网关、资源保护和固定测试不在自动修改范围内。仅改文字、窗口常数、权重常数，或增加未接入计算的模块，不能发布新框架版本。

通过审查后，程序保存上一版本的完整快照和最低规模是否完成，建立下一版的继承目录，清零下一版的研究计数并更新活动指针。命令行入口随后重启到新的隔离工作区，避免在旧进程中继续使用已经导入的旧模块。以后仍可从上面的 V10A 入口启动或恢复，它会跟随活动指针。补丁失败时保留修改、测试、错误和成本，上一活动版本继续有效；需要回滚时恢复上一活动指针。

数值候选通过开发期检查后，最终仍交给**原始冻结独立验收器**重新读取固定来源、重放公式或组合更新规则并重算六年结果。后续研究版本无权自行签发金融达标结论。发现验收器或其固定来源有缺陷、身份改变时，应记录阻塞，不自动修改标准继续验收。

## 固定目标与计数口径

单因子要求同一个固定无监督公式，在 2019—2024 六个完整年度中，日度截面 **Pearson IC 的年均值每年都严格大于 0.05**。方向由 2016—2018 确定并固定。

组合要求同一个完整方案，在相同六个年度中，预测的日度截面 **Pearson IC 年均值每年都严格大于 0.10**。成员和权重可以按事先固定的规则更新，但每次更新仅使用当时已经完整退出的标签。固定价量条件交互可以作为单因子；多个登记因子的聚合及有监督预测器按组合验收，保留完整来源。

两条路线均使用下一开盘起五交易日未排名收益 `open[t+6] / open[t+1] - 1`、历史沪深300信号日池、每年末六个信号日净化。每个有效截面至少 100 只股票，每年至少 200 个有效日，评价覆盖至少 80%。不得年度翻方向、取绝对值、拼接年度冠军、删除失败年份，或以 RankIC 替代 Pearson。区间、分组收益、头部收益和搜索次数完整保留，但不额外替换用户的点估计门槛。

每版最低规模为 300 个主要因子及 200 个不同且完整的组合规格。V10A 的全部 46 个旧定义作为参考重评，其余至少 254 个主要候选须为新增定义。参考清单有 46 项不代表这 46 项已经完成有效重评；实现失败和数值重复会造成实际计数缺口。后续版本分别报告新定义和继承重评。

以下项目分别记账，不能凑研究最低规模：控制项、定义重复、数值重复、实现失败、校准案例、年度预测次数、权重更新次数。高度相关另作冗余诊断，不能与数值完全相同混为一类。组合仅在完整规格实际可评价、且不属于数值重复时计入完成数量。失败的 dense46 规格仍保留，不计作完成组合。

最低规模完成后，每次扩展增加 50 个因子与 40 个组合。连续两个扩展批次同时满足“最佳六年最差 IC 改善不足 0.001”和“没有新增通过共同样本增量检查的互补项”，则结束本版搜索并进入框架复盘。每版最多 3,000 个主要因子、2,000 个组合、6 小时数值运行；达到上限仍需保存结果并复盘。最低规模未完成时明确标记缺口，不能称该版研究已完成。

组合首版覆盖 4、8、12、24 个成员，保留全部 46 因子的稠密 Ridge 对照；方法为训练方向等权及 Ridge，正则值为 0.001、0.01、0.1、1。默认目标是当日去均值的原始五日收益，旧排名收益目标作为匹配对照；全部输出用未排名收益评价。拟合更新包括 2016—2018 拟合后固定、按季度更新的滚动三年窗、按季度更新的自 2016 年起扩展窗。候选池、成员选择、预处理、目标、窗口、正则和更新规则均在计算前登记。

2019—2024 已全部曝光，可用于后续版本反馈。最终即使通过，也只称“六年历史达标”。独立样本外稳定性与交易盈利继续单列为未证明。2025 数值不加载。

## 真实模型与数值程序的分工

主任务为 Astra ultra，生成与控制、数值与组合、独立审计三个子代理使用 Astra xhigh。研究节点通过已有真实 CodexGateway 调用 Astra xhigh：提出少量结构与参数范围、诊断失败、实施有依据的修复、批次复盘、提出框架补丁，以及独立审查补丁。

程序负责参数展开、去重、因子计算、组合生成与拟合、共同样本检查、统计、缓存、调度和成本记录。每个参数点不单独调用模型。质量、互补、条件三条因子池路线保留各自用途；低边际 IC 不能直接淘汰有共同样本增量的因子。

每次模型调用先登记稳定动作编号。恢复先检查已保存的原始回答、事件、退出记录和运行身份，不为了重现已有回答再次付费。只有确认前一次已终止且没有可恢复回答，才允许登记新的独立尝试；残留回答或退出状态不明时继续等待。不能把模型自述当作真实调用、身份或费用证明。

模型网关账本累计实际 token、失败与未知用量；推理 token 属于输出，缓存输入属于输入，不重复相加。开发主任务和子代理的团队回执另外保留，不能把研究网关用量称作全部开发成本。CPU、墙钟、采样内存、磁盘占用及进程中断留下的未知测量分别报告；没有账单时货币费用保持未知。

## 失败、等待与中断恢复

| 状态或问题 | 应如何理解与处理 |
|---|---|
| `waiting`，内存或磁盘不足 | 保存检查点后等待。释放其他程序占用或为 F 盘补充空间后执行 `resume`。不删除原始研究、失败证据或旧结果。 |
| `waiting`，模型额度、超时或依赖不可用 | 保留原始调用。外部条件恢复后执行 `resume`，先走回执恢复；仍缺少回执身份或退出证据时继续等待，不盲目复制动作重新调用。 |
| `fit_unavailable` / 实现失败 | 当前定义或规格没有完成有效研究。保留失败原因，进入限定修复或后续框架诊断；不能以空预测、零值或任意填补冒充成功。 |
| `framework_patch_rejected` | 本次工程补丁未通过。保留副本和成本，活动版本不变；下一次恢复可基于失败证据开展新的有界修订尝试。 |
| `framework_activated_restart_required` | 新框架已通过工程门槛，入口即将重启到其隔离工作区。它不是金融目标完成状态。 |
| `stopped` / 存在 `stop.request` | 用户请求停止。执行 `resume` 才清除停止请求并继续。 |
| `historical_target_accepted` | 仅在原独立验收器确认来源与完整重放，并确认同一实体六年全部过线后出现。仍不证明独立样本外稳定性或交易盈利。 |

首次按单进程进行小批校准，再依据实测私有内存与余量决定是否允许两个计算进程。始终保留至少 6 GiB 系统可用内存、10 GiB F 盘剩余空间。现有校准选择为一个计算进程，不因 CPU 空闲自行增加进程。

进程中断后保留已登记的尝试、部分输出、原始回执和成本。活动进程被强制终止时，未完成的总时长或未取得的内存峰值仍是未知，不记成零。缓存键绑定实际数据、列序、窗口、共同样本与目标；缓存损坏需要保留诊断并从可重建层恢复。发现冻结文件哈希变化时，先处理来源完整性阻塞，不能手改身份文件消除报错。

## 已知限制：dense46 共同训练样本不足

真实数据组合校准已记录一个明确限制：全部 46 个旧因子一起进入稠密 Ridge、使用 2016—2018 固定训练窗时，模型得到 `fit_unavailable`，原因是 `insufficient common training days/cells`。各成员取共同有限值、历史池与可用标签的交集后，训练支持没有达到程序规定的下限；当前内部训练要求至少 60 个合格日、每个合格日至少 100 只股票，并满足相应共同单元数。

这与最终验收“每年至少 200 个有效日”是不同层面的要求。失败表示该稠密规格当前无法完成有效拟合，不能解释为其 IC 达标或不达标，也不能通过静默删成员、填零、放松共同样本或降低覆盖要求把它算成完成。

同次校准的四成员原始/排名目标与三种更新规则、训练方向等权均保存了重放证据；这只验证相应计算路径。校准汇总虽然为流程 `complete`，但 `all_declared_fits_available` 为 `false`，而且 `study_counted` 为 `false`。因此，校准完成既不意味着所有规格可用，也不增加正式研究最低规模。

后续应据保留证据定位造成共同训练样本收缩的定义、日期、缺失或常量情况，再提出可反证的处理机制；如需改变组合机制，应形成新登记方案并经过工程与独立审查。当前应继续保留 dense46 的失败对照。

证据：[组合校准汇总](F:/V10A_Factor_Research/verification/combination_calibration_001/summary.json)；[dense46 具体报告](F:/V10A_Factor_Research/verification/combination_calibration_001/combo_c26e22b3a2890a52082bcdd5/report.json)。

## 何时可以结束持续目标

只有原始独立验收器对同一个固定因子或完整组合方案完成来源核对、完整重放和六年重算，确认每一年都严格过线，才可以结束持续研究目标。工程测试通过、候选数量达到最低规模、历史最好值提高、单个年度达标或某个队列跑完，都不是结束条件。

后续版本数量不设上限；任何版本均可能继续失败。资源或权限阻塞应如实显示并保留恢复入口，不能保证有限时间内一定达到金融目标。
