# A 股真实研究与架构评测协议草案

版本：2026-09-05 / draft-1。本文是下一阶段的冻结协议草案，不是已运行的验收结果。具体数据时期与资产池必须根据数据盘点填入 manifest 并冻结；不能把本文中的建议配置解释为现有执行器已经支持。

## 目标及当前阶段

目标是提高固定 `gpt-6-astra / xhigh` 系统在明确预算内，独立研究并提交可执行、样本外净 Sharpe 大于 1 策略的概率。每一轮都允许得到负结果、放弃不成立的策略或报告证据不足。发现一次 Sharpe 大于 1，或在同一历史区间反复修改直到超过 1，都不等于系统稳定达到目标。

本阶段首先完成一个真实 A 股任务的端到端联调。只有数据隔离、工具执行、成交核算、调用成本及策略复现均通过，才进入冻结的架构比较。历史比较之后还需要冻结系统在新增时期的模拟执行证据；本文不授权实盘部署。

| 阶段 | 要回答的问题 | 可接受结论 |
|---|---|---|
| 真实案例联调 | 模型能否获取证据、诊断、修改、复现并交付完整策略？ | 工程通过；策略失败；执行证据不足 |
| 开发题架构筛选 | 哪一种单一机制修改值得正式花费？ | 保留或放弃候选；仅开发证据 |
| 冻结架构比赛 | 同模型、工具和资源条件下，候选能否跨题、跨随机运行改善产出？ | 支持改进；不支持；证据不足 |
| 新时期模拟观察 | 历史结论能否在冻结之后继续成立？ | 新增执行证据；失效或失效待诊断 |

## 第一真实案例

选择“下跌后的价格修复/趋势反转”日线任务。公开初始定义为：研究 A 股在一段下跌后出现企稳迹象时，是否存在覆盖成本的后续收益，并形成可以执行的选股、仓位和退出规则。量价关系、流动性、市场环境和失败交易都可以研究；不把任何均线天数或已知历史因子作为答案。

首轮采用相同起点的诊断改进赛：给两个架构相同初始代码、相同开发数据、相同初始失败报告。这样先检查“读取失败 → 解释 → 用实验区分解释 → 修改”的能力。之后再加入只给普通定义的开放研究赛，避免把初始实现偏好误当架构能力。

初始资产池优先使用数据中已经可靠保存的历史沪深 A 股可交易池。若采用历史指数成分，必须保留生效区间与公告可得时点；若只有当前成分或当前存续股票列表，首轮只能标记条件化研究联调。为了减少首轮执行歧义，可以预先限定普通沪深主板股票并排除买入时已知的 ST、新上市不足 120 个交易日及退市整理股票。该限定只代表首题范围，不代表全 A 股结论，也不能删除持有后转 ST 或退市股票的损失。

先用日线接通完整资金回测。L2 数据另行做覆盖与字段审计，再为同一任务增加盘中形成过程、主动买卖、订单流和成交容量证据。L2 不能仅凭字段名“主力资金”获得经济含义：必须保存买卖方向算法、撤单处理、时间戳定义与聚合口径。

### 数据冻结清单

运行前生成 `case_manifest.json`，至少包括：

- 案例 ID、任务家族、开放定义/相同基线类型、题目完整文本及哈希、初始代码哈希。
- 原始数据来源、物理文件清单与哈希、字段与单位、最早/最晚日期、交易日覆盖、股票覆盖、已退市股票覆盖、缺失率和异常记录。
- 股票池生成规则、上市退市和历史 ST 状态来源、历史成分来源、可得时点。
- 原始价格、调整因子、成交量/成交额及其单位；价格用于信号还是现金结算的明确区分。
- 开发、确认、最终时期边界与预热区间；每个区间的访问权限与是否已被任何旧研究查看。
- 成交规则、费用日历、初始资本、仓位约束、容量情景、基准、Sharpe 口径、程序版本。
- 工具白名单、单次/单轮预算、上下文与模型配置、已知局限、`integration_only` 标记。

先核对现有数据覆盖，再选连续时期。旧项目、历史对话和已有日志中已经观察的行情/答案属于开发污染范围，不能因为本次进程首次读取就重新称为未知测试集。缺少真正未用时期时，保留“历史回放验证”名称，并等待新增数据形成前向证据。

## 两层隔离

### 每题内部的时间隔离

开发期允许反复观察并做完整实验；确认期是受限的开发资源，调用次数明确登记；最终期只在策略代码、参数、资产池规则和执行配置冻结后，由固定评测服务调用一次。

建议完整任务至少保留 252 个真实交易日作为最终期，并在开发期提供至少两个不同市场时期。短于此长度的任务可以做工程或机制检验，但不参与本草案的稳定性达标统计。一个日历年度不是足够统计功效的保证。

预热只允许读取最终期开始前的数据。标签、未来收益、退出日期等字段不得跨边界进入模型；如果模型使用重叠持有期标签，应从训练尾部去掉其结果落入验证区间的记录。隔离长度按标签真正覆盖的未来区间和执行延迟确定，不按一个通用天数猜测。

冻结策略在最终期逐日运行，可以使用当时已经发生的新行情，不能读取该日以后的数据。静态矢量运算需用未来扰动测试验证：改变日 t 之后数据，不得改变 t 及以前信号、持仓和成交。全样本归一化、事后全样本选池与向后填充都要拦截。

最终期默认从全现金开始，并报告这是实验评测初始化；不利用最终期结尾选择最优清仓。期末未成交持仓要按既定估值和退出约束处理，不能把涨跌停/停牌持仓按任意可成交价清掉。

### 架构之间的题目隔离

元研究员只能使用开发题的轨迹和结果设计架构。正式留出题应包含未参与调优的机制家族，而不只是同题换提示词或换股票。任务集版本由固定控制器持有，架构每次比赛只能提交一个版本。

候选读过本题基线轨迹后，再在本题与基线比较，属于开发联调；不能记作盲测胜出。正式比赛先冻结基线和候选，再各自从相同题目独立启动，不分享其他队伍轨迹、最终分数、跨运行策略记忆或人工技巧。

真实隔离由数据服务权限和工作目录落实。研究子进程不能读取全量原始数据、隐藏结果、主账户配置、其他架构工作区或写入评测器。提示词里的“不要看”不构成安全边界。GUI 中查看最终结果的人之后提出的修改同样会消耗这份留出的独立性，应登记污染。

## A 股执行协议与现有接口

现有日频接口 `src/quanta_agents/local_parquet_backtest.py::run_target_weight_backtest` 接受目标权重、历史成分表、资本、费率、滑点、交易单位及卖出成本变更日；信号在下一有行情交易日开盘执行。它已有原始价格涨跌停判断、ST/退市字段要求和禁止退市整理加仓处理。`prepare_target_weight_backtest_market` 可复用同一行情做费用与延迟对照。

本次另加入可选的 `raw_share_lots=True, min_commission=5.0` 模式，旧调用默认不启用。新模式以 `raw_shares = adjusted_units * qfq_ratio` 换算股数，按买入增量/部分减仓的原始股数取整，完整退出允许调整后的残股；校验原始与复权开盘价一致，不再以当日最终收盘和成交量判定开盘可交易。最低佣金对共同 `buy_cost` 部分取下限，卖出附加费率 `sell_cost-buy_cost` 另收，避免最低佣金覆盖掉印花税；佣金组成仍需对实际账户费率核验。新模式包含初始资本回撤高水位与现金约束。新增执行测试与原有日频测试共 69 项通过。

`src/quanta_agents/event_parquet_backtest.py` 中分钟事件结果已有“A 股 T+1 限制、事件研究不代表当天完整买卖”的说明。该类事件平均未来收益不能直接成为可交易策略 Sharpe，必须汇入资金、库存和时间一致的回测。

以下是正式评测必须满足的语义；缺项在报告中置 `execution_valid=false` 或限定为联调，不能在模型高 Sharpe 时豁免。

| 项目 | 固定要求 | 本轮代码审阅发现的待核实点 |
|---|---|---|
| T+1 与资金 | 当日买入 A 股不能当日卖出；库存按可卖批次记录，卖出所得现金用途按规则处理 | 日频下一开盘、先卖后买能避免多数当日买卖，但开放 L2/盘中后需显式库存批次 |
| 信号与成交 | 收盘后信号最早下一交易时段执行；开盘价成交只是待校准模型 | 不能用次日全日成交额决定次日开盘订单量；不能用信号日最终 L2 决定当日更早成交 |
| 停牌与涨跌停 | 无成交数据不虚构成交；限价触及时区分买卖方向和排队；拒单、部分成交和未成交保留 | 当前开盘触及涨停阻买、跌停阻卖是保守近似，未模拟队列；涨跌停规则需完整日期化 |
| 股数与复权 | 信号可用一致的复权收益；现金账必须对应真实价格、真实股数、分红送转和拆并股 | 新模式已修正原始股数交易单位；分红送转仍采用调整价近似，没有独立公司行动现金/股数账，正式验收需补齐 |
| ST、退市与幸存者 | 使用当时已知状态；禁买规则不删除已持仓损失；退市终止及后续价值处理预先规定 | 仅有 is_delisting 禁加仓不等于退市全过程结算已完成；当前存续池不能替代历史全池 |
| 费用 | 佣金与最低收费、税费按交易日生效；费用是否已经包含规费明确，不重复收 | 可选最低佣金与卖出税费变化已落地；共同费率拆分和全部历史税费仍需核验 |
| 容量 | 固定全资本，限制单股集中度与交易参与；报告未成交/部分成交导致的持仓路径 | 现有接口未发现真实深度/参与率限制；不可只在结果上减一个固定成本就宣称容量验证 |
| 日历与估值 | 公共交易日历包含现金日和持仓缺行情日；停牌延用估值需标注，重大公司事件单独处理 | 不能通过活跃股票有行情日的交集删去亏损日或低活跃日 |

交易规则需要按时期版本化。上交所 2026 年规则于 2026-07-06 生效，主板风险警示股票涨跌幅规定也发生变化；不能把当前规则覆盖到旧回测。[上交所 2026 交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[修订说明](https://star.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml)

普通 A 股的买入交收限制以交易所规则为依据；这里不把可当日回转的其他证券类别混入股票策略。[深交所 2023 交易规则，第 3.1.4–3.1.5 条](https://docs.static.szse.cn/www/lawrules/rule/allrules/bussiness/W020230217564423808793.pdf)

创业板在 2020-08-24 有涨跌幅制度切换，且当时已有退市整理个股存在例外；简单按代码和切换日处理所有股票还需核查特殊状态。[深交所 2020-08-21 说明](https://www.szse.cn/aboutus/trends/news/t20200821_580924.html)

证券交易印花税自 2023-08-28 减半，历史费率表必须反映这一切换。[财政部、税务总局公告 2023 年第 39 号](https://m.mof.gov.cn/czxw/202308/t20230827_3904226.htm)

首轮可先以人民币 100 万、无杠杆、仅多头、固定 100% 总资金为参考资本，明确 10% 单股上限。费率与滑点须由数据盘点确定并写死，不根据策略回测结果调低。建议同时报告原定基础成本、双倍变动交易成本和延迟一交易日三种情景；这些是压力测试而非真实成交的替代证明。日线只能以信号时点已知的过去成交额做参与率筛选；实际成交容量仍要由可用 L2/竞价成交数据或保守执行窗口进一步验证。

## 固定指标与失败分母

主策略指标为完整资金每日净收益的年化 Sharpe：252 个交易日、样本标准差、显式年化无风险利率 2%，每日按 `(1+0.02)^(1/252)-1` 扣除；另报无风险为零的敏感性值。所有现金日、持仓等待日、费用与未成交造成的收益均计入。该选择与现有日频接口默认值一致；与合成 MVP 的零无风险分数应分开展示。

同时报告复利年收益、最大回撤、波动、换手、资金利用率、交易笔数、平均持有期、费用、未成交比例、容量曲线、年度/预注册子期结果、基准超额收益及行业/规模暴露。策略原始 Sharpe 和相对基准的信息比率分开，不因纯多头赶上上涨市场就宣称发现独立 alpha。

每次正式任务运行只允许在隐藏评测前提交一个最终策略。先固定开发期选择规则，才允许研究很多候选。架构比较的基本单元是“任务 × 独立研究运行”，不是挑出的交易、最优年度或最佳一次结果。

单次有效成功定义为：提交合法、数据/执行门全部通过、最终期达到预注册最少覆盖、净 Sharpe 严格大于 1，并满足预注册的风险与容量要求。正式冻结前确定最低 30 个退出批次、最终 252 个交易日、最大回撤不超过 25% 等实验政策值；这些仅是本系统的建议验收政策，不是普适统计定理。相关交易不能按笔数伪装独立样本。

以下情况均记入原定运行总数并报告原因：无有效提交、越权、代码错误、没有交易、预算终止、未恢复失败、最终负收益、数据污染。成功率分母不排除它们。供应商基础设施故障可独立报告，但不能只补跑失败一方并删除第一次尝试；若预注册允许补跑，双方规则一致、原尝试与成本保留。零波动、全现金、样本不足不能因为数值处理获得达标。

不为异常失败强行制造一个无限负 Sharpe。比较时优先使用包含失败的有效成功率；有效策略的 Sharpe 分布作为另一指标，同时报告覆盖率。若需要综合排名，失败惩罚和截断分数须在见结果前固定。

## 架构赛、随机性与多次比较

所有研究角色、元研究角色及任何模型评审角色固定同一 Astra/xhigh 配置，禁止静默模型降级。记录真实请求参数和供应商返回身份；无法独立验证时明确标记。两方拥有同一工具能力、可见数据、实验执行速度配额和预算原则。不要让候选多获得隐藏诊断或给基线刻意贫乏工具。

第一候选只改一个机制：在决定修改前提出可竞争的解释，并获取能区分解释的证据。基线使用充分工具、简洁循环，不强迫它省略自然会进行的诊断。候选应允许某些问题无需多角色争论即可解决；是否增加角色、评审或上下文重置都分别做后续消融。

建议先在开发题做 1 个成对联调，再做 2–3 个开发题小批筛选，估计调用成本、失效率和效应波动。全部费用使用同一模型，离线 fixture 只验证工程。开发筛选允许逐轮查看结果，但不得把其最优分数作为正式统计证据。

进入正式批次时冻结一个基线和一个候选，初始计划为至少 6 个留出案例、覆盖至少 3 个机制家族、每题各 3 次独立研究启动，共 18 对。案例家族可覆盖反转、延续/突破、相对强弱；L2 机制另设独立批次。该数量是首个评测批次，不是保证统计功效的承诺。

同题不同启动用于估计模型随机性。模型无确定性 seed 时，运行 ID 不是 seed；记录不可完全重演的限制。双方以题目、重复编号配对并交错/随机安排运行顺序，冻结顺序清单，以减少供应商时段、版本漂移和资源竞争偏差。模型/网关版本改变时停止合并，另建批次。

正式主要终点是候选相对基线“有效成功率”的配对差；Sharpe 的中位数、低分位、费用、token 和时间作为完整分布报告。任务按预注册权重聚合，不能事后按有利家族改权，也不能每题挑最优架构拼成虚构单一系统。

不把 18 对或几百笔交易都当作独立金融证据。区间估计需要保留同题重复的聚类关系，以及各策略在同一市场日期的相关性；针对收益序列可同步抽取连续日期块，对架构随机性按题目簇重采样。块长和敏感性方案在开发期确定。家族只有三个时，跨家族外推的不确定性仍很大，明确报告。

“本冻结批次初步稳定达标”的建议政策为：候选有效成功率至少 2/3、有效策略 Sharpe 中位数大于 1、成功率的预注册单侧置信下限超过 1/2，并且工程/执行门通过。宣称“架构改进”还要求配对成功率增益的置信下限大于 0。两种判定分别输出；高成功率的旧基线可使候选达标但没有改进，改善了一个很弱的基线也可能尚未达标。实际样本很可能只能给出证据不足。

正式推断一次性在预定批次结束后开展；查看中途分数后决定追加到显著，必须事先采用序贯检验/消耗显著性预算，否则本批降级为开发证据。多候选比赛需在冻结时确定多重比较校正方法或另用完全独立的最终批次，不能反复挑战同一留出集直到出现赢家。

DSR 等方法可作为搜索偏差诊断，但必须登记所有候选尝试，并说明候选相关性与有效试验数不确定性；不能用它补救未来信息、成交虚构或反复窥视留出的错误。[Bailey 与 López de Prado，Deflated Sharpe Ratio 原论文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

## 每轮两问、自检与故障归因

每次改进完成后，固定执行器要求生成 `self_review.json` 和简明 GUI 卡片。两问是用户要求的持续工作检查，回答要有证据而不是自我评分奖励。

1. **这一步做得怎么样？** 记录预期、实际、开发证据哈希、反例、是否解决原失败类型、是否引入退化、哪些检查通过/未通过，以及是否拥有足够证据归因。
2. **下一步该做什么，如何改进？** 提出一个信息价值最高的下一实验，说明不同结果将分别支持/否定什么解释，预计成本、停止条件与下一步的边界；也允许“保留当前结果并停止”。

自检至少区分数据缺陷、实现错误、执行假设错误、经济机制失效、样本不足、研究流程缺陷和基础设施失败。策略变差不自动归罪于模型，架构解释精彩也不自动晋升。用户人工提供想法后，整条影响范围记录 `human_assisted=true`；不混入原定自主能力统计。

正式运行中两问只能读取该运行开发证据。查看隐藏结果后的两问属于评测总结，不能再传给同一批次的研究 agent 或用它修正冻结策略。

## token、时间、资源与 GUI

预算采用“正常研究预算 + 事故熔断”两层。首轮沿用现有可配置上限做短联调；完成成本实测后再给正式批次预注册更宽预算，不因正常长推理、负实验或没有找到高 Sharpe 自动中止。所有元设计、失败、重试、评审和研究调用都入账，分角色展示并纳入总成本。

预算前登记、在途预留、回执对账；缓存包含在输入中、推理包含在输出中，不重复计数。未知用量保持未知并预留；不可当作零。每轮记录模型 token 和可得的账户额度快照，账户并发任务未隔离时不能把周额度差精确归给单轮实验。

防事故包括：总预算/总活动时长、在途调用数、每步重试数、重复任务去重、循环签名与无进展检测、子进程超时、磁盘/内存/进程上限、检查点及恢复幂等。无进展检测应触发检查/换实验或停在安全点，不因连续几次否定结果就判死循环。

GUI 实时显示当前任务与架构版本、研究步骤、供应商公开推理摘要、假设—实验—证据链接、代码/参数差异、实际回测产物、两问自检、token/时间/预算、在途未知用量、失败和重试、数据污染和评测成熟度。无供应商 usage 时显示“待回执”，公开摘要不可包装成模型完整隐藏思维链。

暂停、停止、恢复和人工消息沿用账本状态；重启不重新支付已完成调用。暂停模型调用不等于供应商已经停止计费，需要区分请求取消、子进程结束和确认用量。

## 本轮联调的完成标准与下一步

联调完成只要求：一个冻结真实数据案例；双方至少完成提出/诊断/修改/冻结提交；隔离执行的策略可从产物复现；所有失败与费用保留；下一时点成交及关键 A 股规则有定向验证；GUI 能看到证据、两问及控制状态；独立结果报告明确分数及局限。收益低于门槛也可以完成工程联调。

自检后依次决定：修复数据/执行硬错误；补足能改变解释的研究工具；冻结一个可归因的架构变化；扩展开发题；最后开始独立正式批次。每轮只扩大已验证部分的能力，不把这一份草案或一次成功调用当作“稳定产出 Sharpe 大于 1”的目标已完成。
