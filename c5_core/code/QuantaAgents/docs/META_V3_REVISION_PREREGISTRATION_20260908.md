# 修订实验的事前登记校验

已复现并修复一个研究证据问题：某个可执行规则已经出现在本任务保存的普通候选结果或已登记批次中，仍可获得新的 `preregistered_revision_v1` 记录。原执行入口已能拒绝重复规则，本轮没有证明重复账户运行或金融成绩造假；修复针对的是“事前修订”标签和原候选身份。

原登记只核对基线、诊断和修订程序，并要求修订不同于基线，没有核查它是否已在其他候选中出现。现在登记和执行共用 `_require_new_executable`：已有普通候选（包括失败结果）、仅改说明文字的同一规则，以及已登记批次里的候选，都保存原始引用并拒绝新的登记。尚未执行的批次也保留原候选身份，不能另建普通候选机会。不同的新规则仍可登记，既有登记/执行次数和预算不扩大。

`validation/revision_preregistration_001` 已关闭，183 个清单文件。修改前 7 项检查中 5 项失败、2 项通过；修改后相同测试源码的 7 项全部通过，共 14 次调用。覆盖已有成功/失败结果、改写说明、实际公共工具生成的未执行批次登记、新规则、旧材料哈希变化，以及原有重复执行拒绝。没有修改断言获得通过。

生产修改限定在 `research_tools.py`：登记前调用共享检查，将执行入口的原检查提取为同一方法，并更新公开工具说明。测试采用明确标记的保存结果夹具和内存中的可信历史/摘要，不是实际模型回执或执行账户；批次登记真实调用公共工具，但没有启动候选工作。新增原生 Job、账户、模型、网络及真实/封存行情读取均为 0。本轮未重新验证完整原生进程或新候选资金执行路径。

这个判断使用精确的可执行语法哈希，不识别所有经济等价表达式，也不是跨任务或全项目的暴露审计。历史已见结果不能被本次新登记当成未知验证集；原失败和旧执行去重保留。成功登记仍只表示可以开展实验，不自动判断原因、挑最优策略或证明收益。
