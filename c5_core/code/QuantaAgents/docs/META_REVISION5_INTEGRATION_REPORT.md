## 税务、性能和运行恢复

税务适配器支持所限定个人账户的三档持有期限，以及按日终净变动/FIFO 的税务库存。成交批次与税务批次分开，同日卖出回补不能直接按每笔卖出征税。自然月/年边界和非整分舍入的推断、假设保留于 [适配器说明](META_CORPORATE_ACTION_ADAPTER_V5.md)。

独立审查对真正第四版、第五版 legacy、第五版 Merkle 执行 97 个有效事件，覆盖全部 9 类处理器，每步经济状态一致；10 个非法输入在三个版本共 30 次原子拒绝。原平安旧日志可重放，新的三税档同日回补案例最终现金 10,046.65 元，与独立公式一致。

局部拷贝和 Merkle 状态承诺替代反复深拷贝全历史，同时兼容旧日志。历史固定基准中 1,500 买加 1,500 卖从 20 秒内无法完成变为约 1.01 秒完成；未完成工作量不拿耗时直接相除。性能文件绑定早先源码，不冒充最终源码同次压测；当前字典复制和检查仍有线性成本，税务全历史扫描仍可能成为长组合瓶颈。见 [独立经济与性能审查](META_RAW_LEDGER_PERFORMANCE_REVIEW.md)。

旧失败调用已有完整回答、完成事件和 37,974 token，随后本地内存分配失败。第五版可在两个最终回答副本一致且完成事件自身用量完整时复用结果；明确失败、工具违规、身份不符、内容冲突、缺失用量都不能恢复。原 schema 验证保留，没有模型重试，也未改旧批次失败状态。独立审查发现的空错误消息、旧完成继承和旧用量拼接问题已修复。最终输出量未知时保留 None，原预算未知预留接管。

第五版冻结后又发现异常新轮开始的提前拒绝路径仍可能携带前一轮完整用量。回答拒绝正确，但费用完整性还需降级；该项在第六版修复，第五版证据保持不变。见 [恢复审查](META_COMPLETED_RESPONSE_RECOVERY_REVIEW.md)。

## 验证与两问自检

先完成 561 项联合测试，76.96 秒；之后仅网关补用量完整性修复，最终网关和运行时 45 项定向回归通过，13.42 秒。两次源码身份、JUnit 和唯一差异文件都保存于回执，不写成最终源码一次 561 项联合通过。上述离线测试与记账回放没有调用研究模型。

**这一步做得怎么样？** 完整旧批次复核与原价组合集成通过，找到工具机会混杂及持仓诊断不足，修复了真实故障暴露的回答丢失风险。尚无合格策略，更没有稳定样本外成功率；公司行动覆盖和完整成交语义仍有缺口。

**下一步该做什么，如何改进？** 第六版接通可对账的持仓诊断与固定动作日程，禁止提交时新增未测试策略，允许明确报告证据不足。双方同一工具、起点、日程、Astra/xhigh 和预算；离线验收后冻结短开发消融。2024–2025 最终期保持封存，继续扩展执行数据和公司行动来源。具体见 [下一轮实验设计](META_NEXT_ARCHITECTURE_EXPERIMENT_DESIGN.md)。
