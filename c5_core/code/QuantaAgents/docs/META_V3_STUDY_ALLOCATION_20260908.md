# 整个研究的固定分配与终稿保护

2026-09-08，第 028 阶段。第 027 阶段独立复核已通过；本阶段把跨目录的模型和工具配额纳入研究开始前的完整分配，并接通尚无工具证据时的合法弃权路径。

新研究可显式声明 `allocation`，版本为 `fixed_trial_grants_with_explicit_headroom_v1`。所有 trial 必须有冻结的工具预算；研究总模型 token 必须覆盖所有 trial 的 stage_tokens，总调用数必须等于各 trial stage_calls 之和，工具各维总量必须覆盖所有 trial 的相应配额。多出的 token 或工具量是预声明的超额余量，不能产生额外试验、额外调用或预算转移。没有 allocation 的旧范围明确未集成，不自动迁移、不改写旧付费范围。

同一声明案例、同一重复序号下，不同架构使用相同的整个 trial 模型、时间和工具上限。架构内部任务拆分与 task 层上限可以不同；没有把相同资源条件误写成固定角色数量。声明哈希本身仍不证明案例独立、架构科学差异或数据新鲜度。

每个 trial 在领取前就保留完整额度。未领取、费用未知、执行失败或已经提交终稿，都不会把剩余额度转给另一个 trial。原 Ledger 对同目录内每个未结束 task 的终稿 token、调用和时间保护仍在；本层保护其所在 trial 的整体额度，补上跨目录归属。

实际超额全部保留：例如两组各 400 个 token、全研究 900，第一组实付生成测试费用 450，则超额为 50，占用预声明的 100 余量，第二组仍有原来的 400 配额。若全研究只有 800，同样的 450 超额会使新增模型准入停止，保留明确的 `study_model_headroom_exhausted` 原因。不能声称任意供应商超额下仍可保证终稿；nominal 预留不是供应商计费硬上限。

研究级工具余量耗尽时，模型决策和实际调用准入同步收紧为 close_only；终稿仍可使用原先划定的模型额度。工具入口也在实际预留事务内重查整个研究的状态。若状态检查后另一 trial 才提交超额回执，模型实际预留点再次检查，拒绝过时准入，不产生本地或共享的新调用记录。

这一过程暴露了终稿路径的必要缺口：没有任何历史工具调用的 trial 被迫直接结束时，原 final 要求至少一个已有工具 evidence ID，无法提交合法弃权。工具合同现在提供 `input:<case hash>`，明确表示已经冻结并提供给模型的案例输入。只有弃权报告可以引用它；不能作为已评价程序、资金成交或历史来源完整性的证据。策略终稿仍须引用完成资金执行的程序，原检验条件不变。
