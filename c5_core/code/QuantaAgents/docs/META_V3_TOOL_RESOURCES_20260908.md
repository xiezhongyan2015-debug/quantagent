# 登记范围中的工具配额与应用测量

2026-09-08，第 027 阶段。第 026 阶段独立复核已通过，范围仍限声明机会归属和案例费用视图。本阶段把工具生产者接入同一登记库，尚未完成全栈资源比较。

新登记 trial 可显式冻结 `tool_budget`，包括 actions、candidates、scan_cells、comparisons、wall_ms、controller_cpu_ms、retained_output_bytes。预算属于整个 trial，其下多个普通任务共享。没有该字段的旧工程范围保留原行为，并明确返回未集成；不能据此进入正式比较。登记时验证字段、整数类型和界限，完整 trial 仍绑定原计划指纹。

`ResearchTools.execute` 在进入原工具生产者前，通过 `tool_resources` 写入 canonical `tool_actions`。入口要求该工具属于当前 applying 模型调用，输入案例匹配冻结内容，并核对共享模型调用的 intent 与已结算回执指纹。候选、诊断比较及逻辑扫描配额先预留，正常返回或普通失败后保存实际测量。中断或测量提交失败保留未知，不能靠重放得到免费工具机会。复制目录、删除登记库或修改本地回执不能跳过入口。

普通策略尝试预留一个候选和保守的六张 stock-day 表；程序无效或重复仍保留这笔逻辑占用。批量登记按有界参数网格预留全部候选、表达式/执行扫描和声明比较，包含无效和重复候选。批量执行要求同 task 的已计量登记，执行、查阅只计各自应用资源，不再次扣候选和扫描配额。超出预算或连有界声明都不成立的请求在生产者前拒绝，不新增工具占用；此前模型调用费用仍在原账上。

模型可见自己的 trial 剩余额度语义，菜单随额度收紧。现有终稿方法不经搜索配额入口；普通工具停止后仍保留模型终稿入口和原有 nominal closing 机制。这不绕过原账本的未知调用/应用阻断规则，也没有新增整个 study 的终稿资源分配。

测量边界必须保留：

- wall_ms 是原工具生产者调用期间的实际经过时间；controller_cpu_ms 是该期间控制器进程 CPU 时间，可能包括其其他线程。不是子进程 CPU，也不是跨并发研究可无重叠相加的总计算账。
- retained_output_bytes 是本次工具目录和相关批量目录的保留文件净增长，不是物理读写量。逻辑 scan_cells 也不是实际 IO 或独立研究样本。
- 实际超额全部记录，后续准入停止；这是准入和事后测量，不是本阶段新增了操作系统硬限制。底层已有批量时限/输出阈值仍按原实现运行。
- 初始化、提示构建、最终报告验证、独立 fixed/random 控制入口、子进程 CPU、物理 IO 和其他外部生产者尚未全部纳入。计量提交中断目前保守保留未知，不自动猜测测量值或重跑。
- 历史登记库没有自动迁移路径。生产 canonical registry 尚未创建，旧已关闭付费范围不重跑。

预先冻结的验证范围为 `validation/tool_resources_001/plan.json`，上限 32 次测试执行、零真实模型、零账户 worker、零真实/封存行情读取。

完成 26 次测试执行，13 个不同用例均最终通过：11 项新工具检查及 2 项受影响旧入口/批量登记检查。不是 26 次全绿；保留了全部失败和对应源版本。

1. 首轮 12 项中 5 通过、7 失败。新测试夹具在账本 reserve 回调内再取本地 history，造成同库写锁自锁；工具生产者尚未进入。这是夹具缺陷。改为预先读取 history 后仅重跑 7 项，6 通过。
2. 剩余断库用例误断言必须向外抛错；原运行时会保存没有子进程的应用失败。改为核对 failed、缺库原因、零工具记录及无工具产物，仅重跑该项，通过。产品实现没有为夹具修改异常语义。
3. 自检新增实际准入反例：本地回执被改写、共享回执不变时，初版工具入口仍执行。修前保存 `applied != failed`，补上 canonical intent/proof 绑定后，同一反例及 4 项受影响正常路径全部通过。
