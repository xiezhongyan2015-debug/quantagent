# V3 盘口至现金、持仓账本的接口

2026-09-07。新增有限盘口订单到原股数账本的持久接口，并用已保存的真实八股订单检查准入。**八条买单都因必要来源未齐而拒绝，完整 100 万元参考本金保留，成交、费用和库存均未产生。** 原先的盘口参考匹配量没有被冒充为已持有股份，也没有据此创建次日卖单。

这是资金接口与拒单路径的实际联调，不是零收益策略回测；`portfolio_pnl=null`、`execution_valid=false`、正式案例分母为 0。没有联网、调用研究模型、发送真实订单或移动资金。

## 新增行为

- 一个订单吃多个真实价格档位时，按订单总成交金额计算一次费用；最低佣金不会被逐档重复收取。各档以原价、整数股数进入现有账本，不把非整分的平均价强行四舍五入后乘总股数。
- 买单按下单决策时已经可用的现金，检查全部请求数量按限价计算的金额及费用。相同时点的其他订单保留其足额资金预留，不能把稍后部分成交释放的资金提前给同一决策时点的订单使用。下单后才到账的现金也不能倒过来证明下单时资金充足。未最终确定的税款会阻止继续动用相关账户资金，不把临时零税额当成最终零负债。
- 同一源盘口的每档已使用数量持久保存。第二个订单只能使用剩余的情景额度，重复提交同一订单则返回原回执；同一订单 ID 换参数、同一源盘口标识换内容会被拒绝。
- 买入批次沿用原账本 T+1。全额退出可卖残股的请求可以保留非整手股数；未上市股份不能提前卖出，上市前的权利也不会随普通持仓清仓被删除。
- 已知、事前固定的分红、税款及股份上市事件可独立推进。新订单被拒绝，不会抹掉已登记权利或应收；卖出后仍保留应得分红，直到明确付款事件到来。
- 每笔订单先保存意图，再将所有价格档位的账本事件、盘口消耗和回执一起提交。提交前中断保留待核对意图及此前账户，不自动重新匹配；提交已完成但确认丢失时，从保存回执恢复，不重复扣款。

新增接口为 `src/quanta_agents/meta_v3/l2_cash_account.py`，复用冻结的原股数内核。它供可信控制器使用，目前未配置为已完成全年研究任务的执行后端，也没有正式收益晋级权限。历史来源的真假仍须由上游核对，代码中的准入状态不是真实性认证器。

## 验证与边界

最终相关检查 **14 项通过**：9 项资金接口检查及原 5 项盘口检查。涵盖多档费用与现金、重复盘口、T+1、资金事前约束及同时间订单预留、下单后到账的现金、持仓遇未知条件中止、提交前后中断、应收分红、未上市股份和残股、未知及尚未最终确定的税款。首次失败结果保留；无成交金额的类型处理已修复，付款测试也改为原账本要求的完整现金与税款字段。

合成核算例子中，170 股按 10.00 元、230 股按 10.01 元匹配，名义金额 4,002.30 元；按测试示例费率合计收费 5.04 元，只扣一次最低佣金。次日按示例买盘卖出，完整 10 万元测试本金变为 99,979.32 元。该负差保留。**这些数字是工程夹具，不能当成真实股票收益或 2026 年实际券商费率。**

真实八股拒单联调使用的是税款与决策资金边界进一步收紧前的同一开发版本，当时 12 项检查通过；源文件和测试已保存至该范围的 `source_snapshot`。后续修复了临时零税额和下单后资金到账可能放行订单的问题，最终 14 项检查通过。真实联调没有任何成交或公司行动事件，八条订单在来源准入检查即被拒绝，没有触及这些资金分支，因此没有重跑旧订单；重放该已结束范围应使用保存版本。

当前接口支持事前明确的公司行动账本事件；尚未把供应商事件自动转换成与实际持仓相符的动态事件，也没有完成新来源资料到研究入口的自动接线。它不证明历史接收延迟、官方数量单位、证券状态、实际费用或全区间公司行动覆盖。后续仍需取得实际触及股票日及持仓存续期的资料，再配置新的研究任务使用这段接口；不能只修改准入标签就宣告执行有效。

两问自检：现在盘口、费用、现金、T+1、权利和恢复已有可运行的接口，真实来源不足会留下明确拒单，而不是生成虚假持仓与收益。距离目标仍缺合格执行资料、动态事件接入和新的冻结研究及前瞻证据。若恢复出现额外入金、同一盘口重复成交、每档重复最低收费或卖出后权益消失，应立即保留失败账本并修复；本轮未观察到这些检查中的违规结果。
