# 未确定送股税负的现金保护

2026-09-08。新增 `stock_tax_cash_bound.py`，**11 项定向检查通过**。它为未确定的送股税负保留现金，防止把税款预留重新花掉。它没有推导新股税龄、生成实际应缴税额或放行正式策略；普通/批量混合分配接入和原目标仍未完成。

## 已实现的保护

对每项已登记、已激活的送转行动，根据原登记股份数计算现金税和送股税的预留上界，分别保留组成部分及其来源。已核实来源为股本溢价的转增不进入送股税基。

若登记原股数量为 N、每原股现金为 c、送股比例为 b、输入面值为 v，预留上界为：

`N × [向上取分(c × 20%) + 向上取分(b × v × 20%)] − 已记录实付税款`

这采用明确的数学包络：待补税原股可以划分为任意整数数量的组，各组现金税与送股税的非负金额分别舍入，舍入结果不高于向上取分。因此该上界可以比真实税款更大；它不是精确税额或历史税法认证。不能把它当作费用记入收益。

- 原股、待上市新股及已上市新股被卖出，都不会直接清除原登记权益对应的未核实税负。
- 实付税款使现金和剩余预留等额下降。未经本模块验证的 `tax_final` 或零税额声明不能释放预留。
- 来源政策不匹配、遗漏送转行动、重复适配器或实付税额超过声明的包络时拒绝计算。
- 现金应收和股份估值不能成为可花现金。若还存在未纳入计算的现金分红税务行动，全账户可花金额返回空值，并列出遗漏行动。
- 函数不修改账户，不输出税后净值，也不代替新股税务取得日及日终净额规则。这里识别实付税款为账本中的现金流出，不认证该税款的计算依据。
