# 跨目录试验槽位与模型费用准入

已实现共享试验登记、普通输入建账入口及模型调用费用准入，并完成定向工程验证。相同冻结机会不能仅通过更改试验名称、槽位标签、目录或呈现顺序重新取得预算。这是全流程资源管理的一部分；工具搜索、扫描、计算、输出及元设计费用尚未统一接入，完整架构比较继续不准入，正式成功分母仍为0。

`study_registry.py`使用控制器固定位置的SQLite登记表。试验计划在任何研究建账前登记所有槽位、目标目录、输入和来源摘要、架构标识、重复序号、预算与持续时间。重复语义机会、重复槽位和已登记目录会被拒绝；领取时间只能写入一次，没有自动退还或重领接口。每个槽位从自身首次领取时计时，重启不能更新截止时间。

普通输入入口新增`study-freeze`与`study-status`，既有`create`和`create-batch`可带`--study-id`及`--trial-id`。输入、预算、目录和时长不匹配时，在占用槽位前拒绝。`Ledger.create`把完整阶段计划摘要绑定到登记表；后续账本准入始终查询已登记目录，不能因删除本地绑定而降级成独立研究。复制阶段到另一个目录也不能使用原槽位派发。

模型预留在本地调用提交之前写入共享账本。本地提交中断时，共享预留仍占用机会，后续不能自动生成新调用替代。收到经现有核验流程确认的回答后，再记录实际输入加输出token；失败工作和实际超额也完整计入。共享回执写入中断可由相同保存回执恢复，幂等核对不重复加费。该登记层不替代供应商端执行证明，也没有把请求配置升级为模型身份确认。

自检发现两处窗口：共享账本在阶段检查后消失时，预留入口原来可能跳过登记；在回执登记前消失时，原来可能静默返回。两项反例先失败，修复后均拒绝跳过登记。后一情形保留已经确认的本地费用，恢复同一共享账本后再核对，不抹去费用。

验证保留全部版本与结果：11项槽位/费用检查通过；3项普通入口检查、1项双控制器争用和8项受影响的原账本检查通过；两个新丢失窗口反例修前失败，修后连同相关回归共8项通过。总33次用例执行、25项不同用例，未超过50次预定上限。没有重跑旧资金、提案或身份调查套件。普通入口的“检查输入—合法弃权”使用明确的生成回答夹具，40测试token不属于真实供应商费用，也不能证明自主研究或身份认证。

所有登记表与研究阶段均位于本轮隔离测试目录，生产登记表尚未创建。本轮实际项目模型调用、token和策略账户运行均为0。原authentic_001的75份文件未变；V3仍57次真实调用、1,427,801已知token、0研究未知预留，旧V2另存。

目前能力边界：登记表依据可信控制器提供的案例、架构与输入摘要识别机会，不能独立证明任务族有效或市场样本独立。改变真实协议、来源、输入或预算会产生不同语义，仍需独立暴露历史及修订准入管理。没有把这些变化冒充已禁止的一切重跑。旧未登记工程阶段保持旧分类，不能凭这一改动转为正式研究。全栈工具计量、研究/元设计平台用量与供应商费用归属、全研究预算分配及公平配对仍待完成。

证据：`validation/study_registry_001`，包括建账与共享账本的前后源码、4份原始测试报告、两个失败反例、入口生成夹具、旧文件核验及当前真实账本汇总。本阶段待父任务独立复核。
