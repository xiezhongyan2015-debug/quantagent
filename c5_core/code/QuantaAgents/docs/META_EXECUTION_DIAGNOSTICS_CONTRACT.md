## 已有 diagnose 的真实口径

冻结代码 `meta/ashare_case.py::diagnose` 接收策略、诊断表达式和 1–20 的整数观察期。它对开发期合资格事件计算 `open[t+h+1] / open[t+1] - 1`，用整个开发期特征分位数分五组，返回毛事件收益、按年分组和同日高低组差。临近截点、没有完整观察期的事件被排除；没有加载下一分区价格。

该结果是事件描述：事件日期包含合资格信号日，不等于组合实际建仓日；没有真实组合仓位、逐单最低佣金、买卖受阻和延迟退出；同一个股票和重叠期限产生的观测相互依赖。全开发期分位数也是事后描述边界，不能移植成当时可交易阈值。`backtest` 中持仓可以延续多个更新周期，旧诊断没有精确匹配这种退出路径的接口。

本批候选四次完整研究因此都跳过了 `diagnose`。新工具不要求模型为已有成交再猜一个观察期限，直接描述执行器实际留下的路径。原事件诊断仍可用于提出解释，但不能代替组合结果。

## 现有档案可以恢复和不能恢复的内容

| 项目 | 可靠性与边界 |
|---|---|
| 逐日组合净损益、现金、持仓总市值、费用 | 可直接读取并用成交现金流独立对账；保留所有现金日 |
| 逐股票调整单位持仓数量、加减仓日期、连续持仓长度 | 可按 CSV 原顺序累积，允许多次买入与部分卖出；仅是冻结模拟器的调整单位 |
| 逐股票加权平均成本、卖出实现损益 | 可按冻结执行器规则重建。买入成本包括当次费用和不利成交价，卖出实现损益已扣卖出费用 |
| 全组合每日未实现损益 | 可由持仓总市值减全部成本基数恢复，因而可把已实现损益接回每日净损益 |
| 已完整清仓的持仓段净损益与费用 | 可按该段所有买卖现金流计算，覆盖正负全部持仓段。一般情况下不能把未完结持仓从总体删掉 |
| 目标名单和权重、下一个市场日的意图 | 可恢复原始目标；不能将目标当成交持仓。资格变动可能改变实际目标，现金、价格限制和整手也会改变成交 |

| 每股每天毛损益、隔夜/日内分解、MFE/MAE | 不可恢复。没有完整逐股开收盘估值与日内价格路径；禁止插值凑出曲线 |
| 原始股份数量与登记、送转、红利、税款、FIFO 税龄 | 不可恢复。当前 `raw_shares` 是每单复权比率换算，缺少独立公司行动/现金/批次事件 |
| 市场/行业/风格收益贡献、容量与真实成交 | 不可由这三张表得到。不能从股票代码或几笔亏损猜测确定原因，相关字段返回 unavailable |

连续持仓段的极长尾可能来自持续入选、交易受阻、缺数据或其他机制；当前档案不能区分。工具应返回“持仓 140 日，原因不可用”，不能自动写成“停牌 140 日”。

## 两套必须逐日成立的可加总恒等式

令 `P_t` 为日末持仓总市值，`C_t` 为当日佣金与附加卖出费用，`S_t` 为订单中已记账的不利成交差额。`F_t` 是当日所有卖出按参考价计算的金额，减去所有买入按参考价计算的金额。定义：

```text
F_t = Σ_sell(reference_price × adjusted_units)
      − Σ_buy(reference_price × adjusted_units)
G_t = (P_t − P_(t−1)) + F_t
net_pnl_t = G_t − C_t − S_t
cash_t − cash_(t−1) = F_t − C_t − S_t
```

`G_t` 命名为 `same_filled_path_reference_pnl_cny`，意为**保持实际模拟成交数量不变的参考价路径变动**。它不是零成本重新回测，不产生“无成本 Sharpe”：现有数量、资金占用及后续可买数量已经受费用和滑点影响。把费用加回只能形成会计桥接，不能证明取消成本以后策略如何重新持仓。

第二套按冻结执行器的加权平均成本恢复。`K_t` 是所有未卖调整单位的成本基数，`U_t = P_t − K_t`；`R_t` 是当日卖出的已实现净损益。

```text
买入：K_new = K_old + turnover + commission
卖出：R_order = turnover − commission − sold_units × average_cost_before_sell
卖出：K_new = K_old − sold_units × average_cost_before_sell
net_pnl_t = R_t + (U_t − U_(t−1))
```

`R_t` 已含成本，不再减一次佣金或滑点。按卖出年归组的已实现损益不能直接解释当年组合收益，必须同时保留当年未实现损益变化。对每年、全期以及任意固定连续分区，都用这些可加总金额对账，不将 Sharpe 相加。

样本结果（元）：

| 年份 | 同成交路径参考价变动 G | 佣金等 C | 滑点 S | 净损益 |
|---|---:|---:|---:|---:|
| 2017 | 232,183.24 | 62,427.72 | 78,369.04 | 91,386.49 |
| 2018 | -331,637.60 | 48,125.67 | 59,781.91 | -439,545.18 |
| 2019 | 130,447.58 | 38,875.14 | 48,391.91 | 43,180.52 |
| 2020 | 161,786.59 | 42,586.69 | 52,978.86 | 66,221.04 |
| 2021 | -42,461.62 | 35,637.86 | 43,965.70 | -122,065.18 |
| 全期 | **150,318.19** | **227,653.09** | **283,487.41** | **-360,822.32** |

所有成交费用构成很大的负项；2018 和 2021 的参考价路径本身也为负。因此证据同时支持继续研究交易频率/成本和价格路径，不能断言只要降费即可解决策略问题。此处是金额描述，尚未作因果归因。

逐日两套净损益恒等式最大残差分别约 4.59e-10、4.83e-10 元；现金重建最大误差约 1.20e-9 元，逐单实现损益误差约 3.64e-11 元。末期成本基数的约 -7.28e-11 元残差是浮点计算结果，保留原值并标注在容差内，未篡改旧账。

## 最小接口与输出结构

建议作为控制器新动作 `execution_diagnose`。它只引用同一运行已经完成的开发回测产物；模型不能传任意文件路径、时间切片、股票白名单、最佳观察期或另一个架构的档案。第一版不接受模型指定分组、费用、成交规则或资本变更。

```python
def execution_diagnose(
    artifact_ref: ExecutionArtifactRef,
    *,
    policy: ExecutionDiagnosticPolicy,
) -> ExecutionDiagnostic:
    ...
```

`artifact_ref` 由控制器登记表解析，包含运行 ID、回测步骤、策略哈希、执行 ZIP 哈希、源码身份、数据投影身份、固定 split 和起止日期。它必须指向已完成且属于当前分支的 `backtest`。相同输入和策略规范化后产生相同诊断缓存键；复用诊断不新增回测，也不伪记模型调用。

`policy` 在批次开始前冻结，模型不可编辑，最少含：版本、初始现金和空持仓状态、完整开发区间、逐日/全期现金绝对误差 1e-6 元、库存零容差 1e-8 调整单位、CSV 行序作为交易序号、持仓长度固定桶 `[0, 1–4, 5, 6–10, 11–20, >20]`、固定日历年分组、展示长度上限。这些桶用于描述完整路径，不能变成选优条件或删样本门槛。

输出必须含以下稳定字段：

| 字段 | 必需内容 |
|---|---|
| `identity` | 工具/策略/源码/数据/ZIP/policy 哈希、开发区间、评测完成时刻和诊断生成时刻 |
| `scope` | `development_only`、`adjusted_unit_simulator`、原执行有效性继承值；不能由算术通过改成 true |
| `integrity` | 原文件摘要、日期/字段/行序检查、全部订单覆盖率、两套对账最大残差、原始浮点残差、不通过原因 |
| `coverage` | 全部交易日、空仓日、股票、买卖订单、目标行、关闭/未关闭持仓段、不可解析数；分母不能只写成功部分 |
| `pnl_bridge` | 全期与全部年度的净损益、同成交路径参考价变动、费用、滑点、已实现损益、未实现损益变化、对账残差 |
| `holding_path` | 连续持仓段定义、完整段数、右截尾段数、固定长度桶、追加/减仓段数、跨度分位数；明确非 FIFO 与非独立样本 |
| `inventory_artifact` | 每日非零调整单位数量及成本基数完整表的内容摘要和控制器内部引用；不伪造缺失的每股市值 |
| `spell_artifact` | 所有关闭与未关闭段的完整明细引用；分支固定、无按盈亏裁剪，模型摘要只显示事前规定的时间顺序样例 |
| `unavailable` | 每股日估值、拒单原因、税龄、风格归因、日内极值、容量等缺失项分别写 `null` 与来源缺口，不能填 0 |
| `interpretation` | 固定工具口径解释，不由另一个模型生成“原因”；将会计事实与待检验机制分开 |

本地最小实现完全可以离线构建：解析三张 CSV、按股票按交易行累积调整单位与平均成本、识别连续持仓段、对齐完整市场日、计算上述两套恒等式、输出全量明细与有长度上限的摘要。没有拉取行情的依赖，也不需要训练模型。源账含不支持的现金流或初始持仓而缺少基数时应返回 `unsupported`；字段破损或对账失败返回 `invalid`，不得静默跳过订单后继续给结论。

## 防止诊断变成新的选样或调参入口

1. **共同分母。** 日损益以全部固定开发日为基础，含现金日、缺失报价期间的原模拟估值和终点未能卖出库存。买卖与持仓段明细包含赢家、输家和未完结段；不只取最差 20 单，也不删除无信号或成交失败的股票日。
2. **期限事后观察仅用于研究。** 工具描述已完成回测的持仓长度，不能把事后知道的清仓日作为因子输入。任何由诊断提出的新退出规则必须在新回测开始前写明，不能挑最优持仓期限后补写解释。
3. **截尾显式。** 未平仓段返回右截尾标记与已观察时长，不填最终收益/退出日。关闭段长度分布必须同时显示关闭与截尾数量；不能据仅关闭样本宣称整体持仓时间。
4. **日期和数据权限。** 请求只能解析当前分支的开发产物，拒绝确认/最终期或来源身份不一致的引用。诊断整体的可用时间是该回测完成之后，不能把诊断统计挂在历史交易日伪称事前已知。
5. **完整股票轨迹。** 使用订单中所有股票以及全部目标意图，不用当前成分股重新过滤历史持仓。没有独立资格、停牌和退市事件时，报告缺口，不依据缺少成交推断停牌或删除该股票。
6. **匹配口径。** 关闭持仓段按会计现金流给出净损益；年度解释包含当年未实现变动。常见长期持仓、多次加仓、部分卖出不强制拆成独立胜负交易。费用既不重复扣，也不随“毛损益”重新优化资金。
7. **反事实与实证分开。** 无成本回放、市场/行业控制、相反信号及退出机制改动都属于新实验，需要新策略/对照定义与预算记录。第一版工具不自动尝试这些改动，不生成一个看似因果的总分。
8. **不从这一工具证明 alpha。** 同一市场、重叠持仓段和开发期重复搜索依赖性仍在。固定分桶改善可解释性，不能成为多重筛选后的样本外胜率或架构晋升证明。

## 下一版最低验证要求

实现应至少验证：本真实样本两套恒等式；多次加仓与部分卖出；跨年持仓的已实现/未实现桥接；期末未平仓及现金日；同日多单原始顺序；浮点尾差与实质负库存的区分；有记录的新买即卖在调整单位层面被识别；缺列、负数/非有限值、重复日或不单调日期拒绝；ZIP/策略/数据身份篡改、跨分支和留出引用拒绝；未知字段保持 null；删掉亏损成交必须触发对账失败。

隔离实现后，先对所有冻结开发档案做完整离线诊断回归，保留失败运行的已经完成回测；这不会改变策略成绩或重新消耗研究模型。新一轮架构比较时，双方仍用 Astra / xhigh 和相同调用预算，将“新增执行诊断可用”作为单一改动，观察模型是否更能提出并验证不同机制的实验。工程回归和诊断使用率只作过程指标，最终仍以合格冻结样本外净收益、执行有效性及独立重复为准。

## 第六版的实际纯函数接口

实现在 [execution_diagnostics.py](../experiment_traces/meta_ashare_revision6/src/quanta_agents/meta/execution_diagnostics.py)，测试在 [test_meta_execution_diagnostics.py](../experiment_traces/meta_ashare_revision6/tests/test_meta_execution_diagnostics.py)。控制器负责把上文 `artifact_ref` 解析成以下参数，函数本身不接收不受信的模型路径，也不访问引擎、行情、网络或模型。

```python
build_execution_diagnostics(
    daily: pandas.DataFrame,
    trades: pandas.DataFrame,
    target_weights: pandas.DataFrame,
    *,
    capital: float,
    identity: Mapping[str, Any],
    policy: ExecutionDiagnosticPolicy | None = None,
) -> dict

diagnose_execution_zip(
    path: str | Path,
    *,
    expected_sha256: str,
    capital: float,
    identity: Mapping[str, Any],
    policy: ExecutionDiagnosticPolicy | None = None,
) -> dict
```

`identity` 必填 `split="development"`、`start/end`、64 位小写十六进制 `datahash/strategy_hash/source_hash`、`accounting_mode="adjusted_price_units_approximation"`、`execution_valid=False`。可追加运行/步骤、诊断实现源码摘要等可序列化身份。元数据被复制，原始 DataFrame 和输入 identity 均不变。来源之间的真实性及当前分支权限由控制器核验；纯函数验证格式、开发日期边界和会计一致性。ZIP 包装还核对整个压缩文件摘要，只接受三个准确成员，限制总解压大小，并在同一个打开的文件句柄上校验和读取。

返回顶层 `identity/scope/integrity/summary/tables`，还含版本、输入表/策略/policy 摘要和诊断结果摘要。**模型仅接收 `summary` 与必要身份；`tables.daily/inventory/spells` 全量落盘。** `target_weights` 同时支持 DatetimeIndex 和 CSV 导出的首日期列。

无当日持仓却存在非零持仓市值、未记账现金流、卖出超过现有库存、非有限数据、损益不对账等情形抛出 `ExecutionDiagnosticError`，不会删订单后出结果。输入有效但当前资料不存在的信息位于 `summary.unavailable`，值为 null。观察到同日卖出新买调整单位时保留完整结果并在 integrity 标记，执行有效性仍为 false。

模块保留传入档案的全部日期、空仓日和未平仓段，但**没有读取独立交易日历，不能认证档案是否漏掉一个无交易的现金日**。`independent_market_calendar_completeness_verified=False` 明确保留这个边界；完整日期序列的来源与受信快照身份由控制器和档案摘要约束。新增日历完整性认证需要独立输入，不能由范围首尾或交易日数量猜测。

当前定向测试 **42 项通过**，覆盖真实首例、加仓/部分卖出、跨年实现与未实现桥接、右截尾、空仓、同日多单、身份及 ZIP 摘要篡改、大小限制、缺列/坏数据、未记现金流、负库存与输入不可变。

## 两问自检

**这一步做得怎么样？** 已从按时间选定的真实失败策略中取得完整结构证据，并在隔离模块中恢复两套组合损益桥接和连续持仓长度；明确不能恢复逐股日估值、未成交原因、原始股份和税龄。没有把调仓周期当作持有期，也没有用已平仓赢家代替整个组合。

**下一步该做什么，如何改进？** 完成控制器身份/权限接入、全部真实档案与联合回归，再冻结一次同预算架构比较。原价/公司行动执行器应增加逐股估值和订单意图/拒绝事件，待字段存在后另增版本，逐步把会计路径诊断扩展到可检验的经济原因。
