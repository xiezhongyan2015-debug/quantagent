## 对账本设计的具体影响

- 分别保存登记、除权、派现、股份上市字段，以及来源公告日期、内容哈希和精度。不得把“日期相同”硬编码为通用规则。
- 登记后卖出股票，不会自动消除已登记的分红权利；持仓和权利应分开记账。现金应收可以参与资产估值，但未达到冻结的可用时点前不能用于买入。
- 原公告分别说明了普通受托账户与自行派发对象，不能把同一到账安排推广到所有股东。具体账户尚未声明时，应保留适用范围。
- 送股与资本公积转增保留独立字段，税项按已声明账户类型和对应时期规则实现。平安公告含按账户先进先出计算持有期的补税说明；本次只取证，不宣称税引擎已完成。
- 安集公告的零碎股份按账户余数排序分配，同余数有随机顺序。仅有每股送转比率时，不能声称知道某个虚拟账户最终获配的非整数尾数。整数结果可精确计算；非整数情形须按事先冻结政策处理，并保留不确定性及敏感性检验。

历史回测不要求某个真实账户曾经执行同一策略。后续适配器应明确区分 **公告安排、仿真入账、真实交割观察**；在日级派息时点不足的情况下，可事先规定下一交易日才使用该笔现金，并明确这是保守仿真假设。不能凭假设伪造实际到账记录，也不能把缺失状态或上市日期默认为已核验。

## 下一轮工作

先为冻结股票池与开发时段建立事件覆盖表，保留全部预案、实施、更正、撤销和缺口；从结构化索引定位原公告，并对照除权价格与股本变化检查漏项。索引缺行不等于没有公司行动。可先以固定小样本完成“事件表 → 原始股份/权利账 → 日线执行”的真实数据回放，再扩展覆盖，不直接抓取全市场后假定完整。

这一步做得怎么样：已从“本地没有完整表”推进到两个可复核原始样本与历史索引线索，保存了失败来源；没有修改冻结数据、读取最终时期价格或计算新策略收益。

下一步该做什么，如何改进：将事件字段接入隔离版账本的仿真适配器，补齐日级到账规则、账户税项及缺失事件检测；验收完整覆盖后再重新评价策略，保持原版本失败结果可追溯。
