# V3 深度诊断和结构性迭代：当前缺口与实施优先级

2026-09-07。父任务转达用户反馈：模型的迭代创造力不足，常停留于表面解释，未能综合信息深入诊断，也未主动运用票池构建、截面组合、指增或趋势等适当结构。本任务继续作为唯一实施主控；父任务不并行修改。

当前不能把这些表现仅归因于模型。已核对的工具契约仍由控制器预先限定股票和字段；`develop_strategy` 等动作固定最多 3 次，容易被原版、删除条件对照和一个持仓基准用尽。已有 `cs_rank` 和最多 16 股的小范围组合表达能力，尚不等于模型能够主动取得适当票池、基准资料或新的工具。普通输入入口已有六类动作，缺少可登记、可执行、可追溯的资料或能力扩展路径。

2019 年白云机场开发轨迹中，12.65% 原策略、5.76% 删除条件对照和 22.46% 持续半仓基准是三项比较；未发生经多轮修改提高收益的完整过程。识别反复进出是问题线索，尚不能替代机制归因、区分实验、针对性修改及相对冻结原版的验证。原结果、费用与暴露继续保留，不重复付费复述。

优先实施顺序：

1. 将工具机会分配纳入新任务的冻结研究政策，允许为诊断、原版/对照、修订和收尾按任务需要分配。共享预算、未知调用阻断和真实模型收尾门保持强制；不能修改正在运行或已结束范围的限额。
2. 增加能够综合多份已准入资金与诊断证据的执行归因工具。明确周转/成本、持仓暴露、基准差异、拒单或容量、公司行动、时期集中度等可计算证据及其未知项，避免工具替模型预定根因。
3. 增加结构性修订与区分实验的事前登记。绑定原版程序和证据、竞争解释、预期可区分结果、修改内容和对照；修订结果必须回连冻结原版，失败与内部变体不得消失。
4. 接通研究器提出资料、股票池、基准或工具扩展的请求，由可信控制器在新的有界开发范围登记决定和执行。模型不能自行修改评分、原范围、预算或留出权限。可用资料支持后才执行；请求、准入、实现、模型实际使用和有效独立结果分别记账。
5. 用新的 Astra/xhigh 实际轨迹验收“多类证据→机制判断→区分实验→结构性修改→相对原版验证→终稿或弃权”。不奖励角色数、假设数量或复杂度。简单结构足够时可以保留，证据不足时可以弃权。

股票池、截面选股、基准与风险控制、趋势机制属于可提出的研究结构，不是必须凑齐的方法清单。当前没有合格期货数据、合约乘数、保证金、换月和结算执行语义，不能将股票回测改名为 CTA；指数增强同样需要对应指数、成分与基准数据，以及主动风险和成本的共同口径。

本轮已将正在运行的来源核查封存到 `experiment_traces/meta_framework_v3/l2_public_source_001`。9 次直接读取均已结束，无在途请求；取得 8 个供应商事件日历页面和一份科博达公告原件。日历的返回条数一致不证明完整公司行动覆盖，原执行义务未自动放行。后续工作先推进上述研究能力，不重复这一来源范围。

正式目标保持不变：实际成本后冻结样本外净 Sharpe 严格大于 1、跨案例/机制家族/独立重复、风险容量覆盖、预注册统计门及冻结后的新增数据/纸面验证。执行接线和工程检查均不构成这些结果。
