# 新测量协议的原始回执不可降级修复

2026-09-08，第 030 阶段，回应独立复核问题 `029-C01`。第 029 阶段的原始记录和 `changes_requested` 结论保留，等待父任务复核本修复后追加闭环。

根因是 `tool_measurements.saved(required=False)` 把缺少 canonical 回执行或回执表都解释为“无原始测量”。当 `tool_actions.metrics` 已有数值时，trial/study 状态回退信任这份派生汇总；启动恢复只扫描未投影行，所以已经投影的行也不再检查原始回执。校验正文损坏的测试没有覆盖“正文被完全移走”。

隔离修前反例实际复现。每个源版本只产生一次正常工具测量，再准备第二个生成模型回执作为未执行的后续工具意图。三个 canonical 数据库副本分别保存：移走原回执行、移走整张原回执表，以及移走原回执后把派生测量全部改为 0。原始行/表均保存在副本里的 preserved 表，没有改旧实验。

同一测试中的 15 个边界探针，覆盖三种破坏各自的 trial 状态、study 状态、启动恢复、实际工具预留和实际模型预留函数。修前全部未拦截。探针只触及准入和隔离账目，没有派发供应商或再次运行工具生产者。15 个探针不是 15 个独立测试或研究样本。

修复采用明确且冻结的协议区别：

- 新登记的 `tool_budget` trial 自动写入 `measurement_protocol=original_tool_application_measurement_v1`，完整字段纳入原 trial/study 指纹。新范围不能请求旧协议或空标记，也不能从冻结 spec 中删标记来降级。
- 当前协议下，原始回执表必须存在；已经投影的测量必须保留对应原始 canonical 回执。行或表丢失都不能回退信任派生汇总。
- 表存在、原工具尚未取得原始回执且 metrics 未填的正常中断，仍是未知；没有把未知数字写成 0 或补猜历史消耗。
- 启动恢复检查全部工具行，已投影行不再绕开原始回执校验。trial/study 状态、模型和工具的实际准入边界使用同一规则。
- 未标记的旧版工具范围只读保留历史投影，并明确显示不是当前测量协议；不开放新的模型/工具准入、投影恢复或自动协议转换。没有工具预算的更早登记基础保持原有工程兼容，不冒称已集成全栈工具计量。

验证预先冻结于 `validation/measurement_anchor_fix_001/plan.json`，最多 32 次测试执行、零真实模型、零账户/策略 worker、零真实或封存行情读取。实际 9 次测试执行、8 个不同用例：修前 1 个测试失败，修后 8 项全部通过。

原三个副本反例的 15 个探针修后全部拦截。额外覆盖新登记显式降级、删除冻结标记、旧版投影只读、正常执行中断、只有未锚定本地副本、合法幂等恢复，以及未配置工具预算时的旧基础费用行为。旧版投影检查使用明确构造的生成夹具，没有迁移或改写原第 029 阶段及旧付费范围。

这证明相同删除反例已被实际边界拒绝；不证明过去真实漏计已经发生。原第 029 阶段的 13 项通过仍真实，但其覆盖不足由本反例补齐。旧 75 个真实提案范围文件、第 029 阶段 208 个验证文件和 57 次 / 1,427,801 已知 token 供应商账均保持原样；本阶段没有新增真实供应商费用。

本轮原计划的“已返回工具结果因计量中断被记失败后的证据可见性”依赖原始回执真实性，因此先处理该缺陷，结果可见性工作尚未实现。后续仍需补足它及剩余全栈生产者计量，再回真实构建性研究；可信资金执行、来源覆盖、独立重复、冻结样本外和新增前瞻门没有放宽。实际模型身份未确认，`full_stack_comparison_admitted=false`，正式成功分母 0。
