修复将控制计划的共同构造移入 `_frozen_plan`，冻结和实际授权使用同一套派生规则。授权从 canonical case、producer contract、source pins 和原始 deadline 构造预期计划，逐一比较所有计划字段及完整 budget；扫描预约还须与原始 producer intent 相符。本地 plan 与 controls 相互一致不能替代该绑定。创建时间仅允许在原始生产意图开始至当前时刻/原截止时间之间，不会创建新研究时钟。

035-C02：旧生产器只检查共享 process headroom；共享模型或工具超额时，仍能预约 process intent，并通过实际生成所用的 `_active` 门。反例使用明确标注的生成额度状态，保持真实 canonical slot 预约路径，但用仅预约的测试派发器阻止 OS 启动；没有制造供应商超支。修复在外层派发前与实际工作授权处均复用 `study_allocation.admit_tool`，同时执行 model/tool/process 三项额度检查。拒绝后没有新 process intent，正常余量对照仍可预约。实际生成调用 `_active` 在写 producer intent 之前，控制执行也再次经过同一门。
