# 原始整数股份与公司行动账本内核（revision3）

日期：2026-09-06。状态：**独立内核已实现，44 项合成事件测试通过；尚未接入回测，也没有修订任何已有收益。公司行动覆盖和正式执行门仍为 false。**

实现位于 `experiment_traces/meta_ashare_revision3/src/quanta_agents/raw_share_ledger.py`，测试位于同一隔离副本的 `tests/test_raw_share_ledger.py`。主 `src`、现行模型调用、8769 服务与正在执行的批次均未操作。本次没有加载真实行情、读取最终评测区间或运行新策略回测。

## 1. 为什么需要独立账本

[首轮执行审计](META_ASHARE_FIRST_RUN_EXECUTION_AUDIT.md)显示，第 4 轮 1,003 笔全平订单中有 988 笔原始股数不是整数，例如 11,100.443477 股。现行账本的现金与净值算术能够重算一致，但持有“调整价单位”，每日乘复权比例并不能得到真实的股份变更和分红现金账。把这些尾数直接舍弃、全平四舍五入，都会更改经济结果，不能冒充修复。

本内核保存原始整数股份，并把登记权益、现金应收、实际可用现金、待上市股份和可卖库存分开。所有变更只能来自有身份和时间的明确事件；不读取或解释 `qfq_ratio`。已有研究近似收益保留原状。

## 2. 当前数据仍不能证明完整历史执行

[数据审计的 2026 新增章节](META_ASHARE_DATA_AUDIT.md)记录：当前冻结 2015–2025 数据中没有找到完整的公司行动到账、股份上市和账户税负事件源。2026 腾讯日线覆盖 5,133 股、132 日，存在 3,362 条公司行动注释，但缺少现金到账日、红股可卖日、公告可得时点和完整事件状态；它们全部事后采集于 2026-08-11。不能把采集时间冒充历史公告可得时间，也不能由除权日自动补齐派息和上市日。

另有两份已保存的一手实施公告可用于定义字段，不能据此宣称整个历史区间完整：

- [平安银行 2019-031 实施公告](https://resources.pingan.com/app_upload/file/bank/68fc6c5a274445a7bda66befd789dd89.pdf)分别明确登记、除息、代派资金划入安排，并区分账户适用税负；个人差异化税负依账户持有期与先进先出计算，可能在卖出后补缴。它支持把现金应收、到账与税款应付拆开，而非把收到税前红利视为最终免税。
- [安集科技 2026-040 实施公告](https://star.sse.com.cn/disclosure/listedinfo/announcement/c/new/2026-06-03/688019_20260603_XFHB.pdf)分别列出登记、除权、现金发放和新增股份上市日期。其转增零碎股份分配涉及多个账户排序及随机排列，单账户不能自行推断四舍五入结果；公告还说明此次资本公积来源与税务口径，不能将所有“送股/转增”概括为同一种免税事件。

已读取的本地 PDF、逐页文本和下载身份保存在 `experiment_traces/meta_corporate_action_sources/20260905T175154Z/`；清单为 `source_audit.json`。本模块不联网，也不重新抓取这些资料。

## 3. 状态与事件契约

`RawShareLedger` 从零现金开始。构造时必须提供唯一有序的交易日列表、日历来源与日历可得时间。现金使用 `Decimal`，金额与原始成交价接受最多两位小数的字符串，股份必须是正整数或事件允许的零整数；浮点数量、浮点金额、小数股份、非有限数和隐含舍入全部拒绝。

本内核登记的是明确成交回报，不是委托。因此整数零股成交可以入账；买单是否满足该板块申报数量、部分成交是否可能、价格限制及容量，由上游撮合层另行检查。不能把本模块通过当作 100 股委托规则或可成交性已通过。成交费必须由上游明确提供，内核不自行推断最低佣金、印花税或冲击成本。

每个事件包含且仅包含：

| 字段 | 含义与要求 |
|---|---|
| `event_id` / `kind` / `data` | 唯一事件身份、允许的事件类型、该类型的严格字段 |
| `effective_at` | 经济上生效的时刻，必须带时区 |
| `available_at` | 此条证据在该重放中可得的时刻，必须带时区 |
| `source.ref` / `source.sha256` | 来源引用及内容身份；不会自动下载或验证来源真实性 |
| `source.verified` | 适配层明确作出的核验声明，必须为布尔值 true |
| `source.evidence_type` | `documented`、`observed` 或 `simulated` |
| 模拟来源额外字段 | `assumption_ref`、`assumption_sha256` 指向已冻结的模拟假设 |

`apply(event, as_of=...)` 显式给出处理时刻。生效时间、证据可得时间和日历可得时间不能晚于处理时刻；处理时刻与已接受经济事件顺序均不能倒退。读取状态和估值也不能早于当前状态的证据处理时间。因此事后获得的事件不能直接在过去时点被读到。当前内核不证明来源所声称的历史 `available_at` 是真，也不证明提供的交易日历完整。

三类来源不能互换：

- `documented` 表示发行人/交易所文件确认的计划、实施日期或规则。文件上写了派息日，并不等于某账户已有一条到账回报。
- `observed` 表示经过适配层核实的账户成交、到账或股份分配观察。来源身份仍需外部证据支持，填一个 true 不是独立审计证明。
- `simulated` 表示由已冻结假设生成的历史仿真事件，必须保留假设身份。例如根据实施公告规定的日期与保守可用现金规则生成支付事件。它不会被重命名为真实观察。

目前所有资金、库存和账户权益变更都要求 `observed` 或 `simulated`；发行人计划不能直接过账。日历和估值证据可以保留 `documented` 分类。

| 事件 | 入账行为与拒绝条件 |
|---|---|
| `cash_deposit` | 明确入金增加现金和外部资金流，不能当成投资盈利。 |
| `buy_fill` | 扣除原始股数 × 原价及明确费用；实际现金不足则整体拒绝。建立独立整数库存批次，下一明确交易日才可卖；缺下一交易日则拒绝。 |
| `sell_fill` | 必须列出库存批次分配和股数，合计等于成交股数；超卖、未知批次、当日新仓或未上市库存拒绝。这里只核对库存分配，不声称税务 FIFO 已实现。 |
| `record_entitlement` | 记录登记时持股数及各批次快照，必须与当时账本股份一致；后续卖出不删除权益。登记时尚不计现金应收，避免含息价格与应收重复计价。 |
| `activate_entitlement` | 除权日确认明确税前现金应收和明确整数送转权益；要求晚于登记日期。`share_kind` 区分送股、资本转增、混合、无股份；不从比率推断分配，也不据类型自动推断税。 |
| `cash_dividend_paid` | 明确税前支付总额 = 净现金到账 + 已扣税。应收减少，只有净到账增加可用现金；只支持整笔应收一次支付，重复或金额不一致拒绝。 |
| `tax_assessed` | 明确记录该事件账户总税负与是否最终确定；不能低于已缴税。已经最终确定的税负若需纠错，当前协议拒绝，须扩展显式纠错流程。 |
| `tax_paid` | 在已知应付税额内扣实际现金；无应付、超额或现金不足拒绝。应收红利不能当现金缴税。 |
| `bonus_shares_listed` | 根据独立明确的上市可卖事件，把待上市整数股份转为可卖库存；不要求与派息同日，不自行默认除权日，不作为当天新买股票再套 T+1。仅支持一次完整上市。 |

**登记时点仍有一个明确外部契约**：`record_entitlement` 只校验提供事件时刻的账本原始库存与给定数量一致。它不自行识别官方登记日、不强制交易所收市时刻，也不推断登记后同日是否还有成交。适配层必须在正确登记收市快照上生成该事件，并保证当日成交顺序；这不是完整的 point-in-time 核验。

待上市股份保留经济权益，但不能卖；上市时创建批次的 `booked_at` 与 `sellable_at`，其 `acquired_at` 设为 null，避免把上市日误当买入日或税务持有期起点。登记批次快照和原购买批次保留，可供以后税务谱系适配器使用；当前没有自动分配送转股份的税务成本与持有期。

## 4. 净值、现金和税款

估值只接受当前估值时刻可得的、同一时刻的明确原始价格。持股或待上市权益缺少价格、价格仍是旧时刻、证据尚不可得时，估值失败，不前向填充。没有持股/待上市股份的纯现金账户不需要价格。

```
资产总额 = 可用现金 + 已持有原始股份市值 + 待上市股份权益市值 + 未收税前现金红利
已知应付税 = 已评定税负 - 已实际缴纳/扣缴税款
净资产 = 资产总额 - 已知应付税
```

最后一式只在所有已激活公司行动的税负均明确且最终确定时返回数值；否则 `net_asset_value=null`，同时列出未解决税项。`tax_due=0` 必须明确提供，不能由“本次未扣税”推出。确定的税款由应付转为实际扣款时，现金和负债同时减少，净资产不应再减少一次。

待上市股份按同股票原始价格计经济权益价值，这只是明确的估值口径，不代表可立即变现，也没有估计锁定期折价或事件撤销风险。部分派现、部分上市、配股认购、拆并股、税款退款、限制股、退市清算和公司行动撤销/纠错尚未实现；需要这些情形时不能静默套用现有事件。

输出区分 `cash_available`、`cash_receivable_gross`、`known_tax_payable`、`net_nav_confirmed_for_recorded_events` 与事件来源类别。**即使合成路径算术完全一致，`company_action_coverage_complete=false`、`execution_valid=false` 仍固定不变。** 一个完全遗漏、没有任何输入事件的分红，无法仅从账本内部被检测到；完整性必须由外部证券/日期覆盖清单证明。

## 5. 幂等、重放与运行边界

同 `event_id` 且事件内容完全相同的请求返回 duplicate，不再次划账；不同内容复用该 ID 则拒绝。新 ID 的重复派息、重复登记/激活或重复上市同样按权益状态拒绝。所有事件在状态副本上执行，任一校验失败不改变余额、库存、时间或日志。

每条日志保存事件、处理时刻、事件哈希、前一日志哈希、状态哈希及本条哈希。`replay(genesis, journal)` 按冻结日历和顺序重做，并核对每个状态/链条；导出的快照与日志都是副本。哈希链依赖可信的外部起点/终点，不能抵御攻击者把整条链及终点一起改写；这不是数字签名或持久化事务数据库。

乱序经济事件拒绝，晚到更正必须明确重建，而不是修改已发布净值。估值返回对应日志 head；估值是只读计算，不自动形成持久化冻结记录。适配层仍需把估值与 head 一起存档并控制发布边界。当前类没有跨线程锁、多进程提交、磁盘 WAL 或服务接口，调用方必须串行执行。

单个事件有 2 MB 上限，完整状态和日志哈希没有这个人为截断。零库存批次和历史权益保留以便审计；每次入账复制并哈希当前全部状态，内存和计算成本随历史增长，尚未进行多年全组合压测。**不能直接据这 44 项小样本测试把它接到 1,217 日完整组合并宣称容量/性能已准备好。** 后续可做追加日志、持久化检查点与受验证的聚合索引，不能先删掉税务/权益谱系来节省内存。

## 7. 下一步适配路线，不要求历史真账户曾交易该策略

历史仿真可以且应当使用明确、冻结、可审计的模拟账户。可行路线是：

1. 建立证券/日期/事件组件的覆盖清单和来源身份，分清实施公告中的日期、公告公开时刻、下载时刻、账户观察与撤销/修改状态。对未覆盖事件和缺上市日期显式报告，而非按收益好坏选择忽略。
2. 在看新结果前冻结账户类型、时期适用税则、税务 FIFO/持有期及来源。适配器利用本内核保存的购买批次、登记快照、卖出路径，生成带假设哈希的税额评定与扣缴事件；尚未最终确定的税负可以另输出保守上界/区间，不能把当前 null 偷换为零。
3. 使用实施公告规定的派息日期构造保守现金可用时间，例如预先规定派息日期后的下一交易日才可购买。必须标记 `simulated`，并测试替代到账延迟的敏感性；实际可卖日期缺失时仍不能默认除权日。
4. 公告比率 × 登记整数股份正好得到整数时，冻结适配器可计算精确的股份权益，无需真实账户交割单。遇到零碎股分配则保留上下界/情景差异，或取得足够规则和分配证据后明确产生整数结果，不能自行四舍五入并称为真实。
5. 先用已知完整的小批事件联调原始股数、现金、税负与可卖时间，再做多年路径压测和并行研究账/执行账对账。对差异逐条归因，不修改旧输出、删除损失或把分红重复加入复权收益。完成这些以后才能讨论替换当前执行器；策略收益与架构稳定性仍需独立的冻结评测。

## 8. 每轮两问自检

**这一步做得怎么样？** 已把“调整单位推导原股数”的已知问题拆成一个独立、可重放、不会把应收当现金或把待上市当可卖的账本内核。44 项合成路径通过，未知税负与缺数据的限制显式保留。它验证了给定事件的账务守恒与时序拒绝行为，没有证明真实历史完整、价格可成交、策略获利或系统能稳定产出 Sharpe 大于 1。

**下一步该做什么，如何改进？** 优先建立小批完整实施公告到模拟账户事件的冻结适配器，接入账户类型/时期税务 FIFO，分别核对原股数、现金应收、到账、送转上市和净资产；随后补覆盖清单与持久化/长路径性能验证。在完整性和差异归因通过前，保持研究近似输出原样、`execution_valid=false`，不把内核完成提前升格为整个执行层已经修好。
