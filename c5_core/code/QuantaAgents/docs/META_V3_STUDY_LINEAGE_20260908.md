# 跨研究机会归属与案例暴露视图

2026-09-08，第 026 阶段。第 025 阶段独立复核没有新增阶段内问题；本阶段落实其对已声明缺口提出的四个具体反例。

登记入口现在按声明的 `case_hash + architecture_hash` 锁定一整组重复。首次登记必须一次性列出该组全部重复；即使原槽位尚未领取，也不能分到另一研究、追加重复或替换。目录、研究标签、槽位标签、输入、源版本、时间和预算修改均不能重新获得该组机会。检查和写入位于同一个 SQLite 写事务，并发提交相同组的不同重复也只有一份登记成功。

这是保守的不可变登记规则：不提供原位修订、退款、失败替补或旧范围自动迁移。既有预声明兄弟槽位仍可领取，旧槽位的失败、未知预留和已知费用不变。新案例或新架构可以作为新的声明登记；这不证明案例或架构在科学意义上不同。哈希的内容归属仍由控制器声明，伪换哈希、历史数据的实际重叠、不同案例标签下的同样机会以及正式前瞻样本判断尚需正式协议层约束。

`study-status` 增加只供控制器查阅的 `case_history`：按同一声明案例跨研究引用原 trial/call 身份，显示外部已领取次数、已知费用和未知预留，以及全案例汇总。它不复制费用，不把外部费用转入新槽位可用预算；多个研究的案例视图可能重叠，不能相加。该视图是当前登记历史，不是不可变的“登记时已暴露”证明，也未向模型公开其他研究的策略内容。新架构保留同案例旧账，`formal_freshness_verified` 始终为 false。
