## 相同量能成绩是否来自复用输出

四次量能运行有各自的创建请求键、各自调用目录和 `--ephemeral` CLI 请求。整个批次 **91 个 `thread.started` ID 全不相同，91 份完整响应的规范化哈希也全不相同**。调用文件中的提示词哈希、请求、事件输出、消耗和成功回执逐一对应。量能同架构两次重复的首轮提示词相同，后 11 轮提示词各不相同，所有同轮响应也不相同。

量能基线两次最终提交的是完全相同的公式：放量阳线事件、前期低波动排序、10 只、每 20 日调仓、80% 名义仓位。路径不同：第一次还检验了长期趋势条件，第二次检验了 15 日更新。第二次 15 日版本开发 Sharpe 为 -0.043428，模型因它没有通过此前声明的跨年度改善标准，仍冻结 20 日版本。这是有说明的取舍，不能擅自以最高分覆盖其提交。

量能候选两次最终公式文字中的负号分别写作 `0 - x` 和 `-x`，其余条件相同：阳线、前期成交额横截面较高、前期低波动排序，10 只、20 日、80%。两次最终 `daily.csv`、`trades.csv` 和 `target_weights.csv` 的内容哈希分别完全相同，说明收敛到相同执行结果。中间实验顺序不同，第一次测试高波动反向对照，第二次测试当日涨跌幅排序。

因此，现有本地证据支持“独立启动并分别产出，最后收敛”，没有发现控制器复用模型输出。缓存输入只是被报告的前缀缓存，不能解释为输出缓存。服务端是否使用独立随机性无法从这些记录证明。所有请求都锁定 `gpt-6-astra / xhigh`，但提供方事件未同时确认这两个设置，成功回执的 `model_verified` 均为 false；此次没有把请求参数伪称为服务端设置证明。

模型有实质改动与对照，不能将失败概括为没有创造力或原地循环。相对强弱候选第一轮重复最终转向大流通市值对照，取得开发年化 9.55%、Sharpe 0.454，但回撤 33.77%；这并未证明相对强弱机制或独立 alpha。量能候选两次都删除原放量条件后才达到各自最佳成绩，最终年化仅 1.77%，回撤 47.40%。五份最终提交使用低波动排序，另两份使用市值和换手近似，搜索确有向常见风格收敛的现象。

输入占总 token 约 96.3%，完整运行首轮输入约 1.4 万，末轮约 5.6–5.7 万。控制器逐轮发送累计研究史，后续调用大部分成本来自读取已有材料。压缩上下文可以作为后续单独实验，但在本批尚没有质量不下降的证据，也不应边运行边修改来省 token。

## 下一项架构改动建议

优先增加一项**基于实际持仓路径的亏损归因诊断工具**，保持 Astra / xhigh、调用预算、案例和评分固定，作为新版本可单独归因的改动。现有证据最直接指出的缺口，是事件收益诊断与真实组合执行没有共同口径，导致候选完全放弃诊断。

工具以控制器已经执行的组合为输入，返回实际持有期分布、分年份损益和敞口、买卖及未成交原因、逐段持仓毛变动、已付费用，以及能精确对账的归因残差。模型不需要猜测“20 日调仓是否等于持有 20 日”，也不必用事件毛收益代替组合净收益。解释应指向下一项可被推翻的实验，例如收益是否只来自大市值风格，或退出阶段是否吞掉入场优势。市场/风格反事实需使用事前规定的共同样本和成本，不从最差损失中事后删除个股。

这项建议不是已证实的改进。新工具需独立版本冻结，在旧诊断和新增执行诊断之间做相同模型与预算的配对比较，观察是否产生更多机制不同且获得净收益支持的策略，而不只增加解释文字。当前复权单位账仍不能支持正式执行认证；归因原型可对已有档案验证代数对账，正式策略评测须接入已完成公司行动、整数股、交易约束和容量核验的执行器。
