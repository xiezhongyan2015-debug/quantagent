# 现金分红公告到模拟账户事件：revision4 小样适配器

日期：2026-09-06。**已完成一条有明确边界的现金分红适配路径；32 项新增测试与 44 项原账本测试合计 76 passed。原始股数账本没有修改，主源码、revision3、模型研究调用和现行批次保持冻结。**

产物位于 `experiment_traces/meta_ashare_revision4/src/quanta_agents/corporate_action_adapter.py`，测试为该副本的 `tests/test_corporate_action_adapter.py`。它提供公告事实、冻结假设、FIFO 税务谱系和模拟到账事件，尚不是完整 A 股公司行动数据适配层。`company_action_coverage_complete`、`execution_valid` 始终为 false。

## 已实现的第一条路径

小样来自已保存并人工核对的[平安银行 2019-031 权益分派实施公告](https://resources.pingan.com/app_upload/file/bank/68fc6c5a274445a7bda66befd789dd89.pdf)：每 10 股派 1.45 元，登记日 2019-06-25，除息及代派资金划入安排为 2019-06-26，没有送转。适用账户收窄为内地个人、公开转让市场取得的无限售股份；公告明确该类账户差异化红利税与账户先进先出，不适用于 QFII、深股通、限售股或其他账户。

`load_pingan_2019_031(pdf_path)` 先校验文件为 PDF，并要求 SHA256 精确等于 `ed23cd9c216f3bfc14b808a5d1dc51de9fabc8c0d2136c7c0672dae41b62d509`，才返回与该文件逐页核对过的事实。没有自动 OCR、网络抽取、模型解析或从文件名猜事实。不同文件不能借用这份公告的“已核实”身份。

通用 `CashDividendAnnouncement` 数据结构保留来源、税则、账户类型、现金比例、送转类型/比例、配股与实施状态。其他事实可以由后续经过核实的抽取器生成，但 dataclass 本身不会证明事实为真。送转、混合分配、配股、提案、撤销/未知状态、其他税则和账户类型均显式抛出 `UnsupportedCorporateAction`，不把不支持的公司行动从覆盖清单中删除。

## 税期与 FIFO 的依据和收窄范围

税务总局网站保存的[财税〔2012〕85 号通知](https://shanghai.chinatax.gov.cn/zcfw/zcfgk/grsds/201211/t400938.html)规定持有期计算至转让交割前一日，并按账户先进先出认定先取得的股份先转让。[2015 年官方政策解读](https://shanghai.chinatax.gov.cn/zcfw/zcjd/201509/t419000.html)再次说明该口径和自然月/自然年定义。不能用固定 30 天或 365 天直接替代完整税期判断。

本版只处理**已实现卖出且买入日期到卖出日期相差 1–28 个自然日**的明确短期档，适用公告已说明的 20% 税负。它是完整“一个月以内”规则的保守子集，不声称超过 28 天必然属于另一档；29 天及以上统一 unsupported，不猜月底、二月、闰年或满一年边界。

从日历日期计算的差值对应买入日至卖出前一日的持有时间。例如 2019-06-24 买、06-26 卖，计 2 天。实现按照购买时间、同时间则按购买日志顺序选择旧库存，并从完整买卖日志复核每次已有卖出的批次分配。发现非 FIFO 历史会拒绝，不悄悄改写账户税务谱系。

登记事件保存 `registered_lots`。只有登记快照中的股份，在登记后卖出时计入该次分红的税负；登记后新买股份不新增此次股息权益。部分卖出只确认已实现的税额，余下权益税负不最终确定；账本净资产仍为空。全部登记权益已卖出、每笔都处于支持税档，才生成 `tax_final=true`。

每次累计税額和现金红利总额必须已经精确到分。不执行任何未核实的税务舍入。例如该公告 1 股应收 0.145 元、单卖 1 股对应 0.029 元税额，当前都拒绝；100 股应收 14.50 元、税 2.90 元可以精确处理。这一限制必须保留为不支持项，不能为了得到完整曲线自动舍入。

## 明确区分公告日期、模拟可得、应收和可用现金

冻结策略 `cash-dividend-fifo-short-28d-v1` 包含以下约定，其内容、公告事实与日历一起计算 `assumption_sha256`：

| 时点/组件 | 本版规则 |
|---|---|
| 公告日期只有日粒度 | 采用该日期之后的下一已提供交易日 00:00 作为**模拟**可得时刻；小样为 2019-06-21。 |
| 真实文件采集时刻 | 单独保留为 2026-09-05，不伪装成 2019 年已经观测到的发布时间。 |
| 登记快照 | 2019-06-25 15:00，基于该时点的账本股份，包含登记日买入；若随后又出现同一股票当日成交，则激活/税评定/结算阶段拒绝，要求重建完整收盘快照。 |
| 除息应收 | 2019-06-26 08:00，确认毛红利应收，税负未知；此时不增加现金。 |
| 现金可购买时刻 | 比发行人安排的派息日保守延迟至下一个已提供交易日 08:00；小样为 2019-06-27。 |
| 已实现红利税 | 卖出后由 FIFO 证据生成累计评定，不把“派息时暂不扣”视为最终零税。 |
| 模拟扣税时刻 | 已知应付税不早于上述保守到账时间扣收；已先派息、后来卖出的路径，评定后再明确生成扣款。该扣款时间也是冻结模拟，不是券商真实观察。 |

所有账户变更来源均标记 `simulated`，引用原公告哈希和冻结假设哈希。发行人材料在 manifest 中仍是 `documented`。这个“下一交易日”安排是公开透明的模拟策略，不能证明文件确实在历史时刻可得、日历事前完整、没有后续撤销公告或现金真实到账。

日期校验、相同冻结日历、登记收盘顺序和 ledger 的 `effective_at / available_at / as_of` 校验共同约束当前路径；没有自动完成整份证券历史的 point-in-time 证据核验。超过当前账本处理时刻的已知资料不会被默认为历史可得。

## 接口与事件顺序

```python
spec = load_pingan_2019_031(pdf_path)
adapter = CashDividendAdapter(spec, trading_days, price_basis="raw")
manifest = adapter.manifest()

# ledger 先记录 06-24 的入金与买入。
record = adapter.record_event(ledger)
ledger.apply(record, as_of=record["available_at"])
activation = adapter.activation_event(ledger)
ledger.apply(activation, as_of=activation["available_at"])

allocations = adapter.fifo_sale_allocations(
    ledger, quantity=100, sale_at="2019-06-26T09:30:00+08:00"
)
# 调用方按 allocations 记录明确原价、费用的 sell_fill。
assessment = adapter.tax_assessment_event(
    ledger, as_of="2019-06-26T09:30:00+08:00"
)
ledger.apply(assessment, as_of=assessment["available_at"])
tax_evidence = adapter.tax_evidence(ledger, as_of=assessment["available_at"])

settlements = adapter.settlement_events(ledger)
for event in settlements:
    ledger.apply(event, as_of=event["available_at"])
```

事件工厂不修改账本。必须先保存生成的事件，再按顺序应用；恢复或重试使用已保存的同一事件，由账本提供幂等。对已经完成的阶段重新生成，工厂会明确拒绝，避免从改变后的持仓状态制造新的权益或再次到账。

`tax_evidence` 输出登记批次、已卖/剩余登记权益、每笔购入/卖出日期、持有天数、税率、未舍入税额、当前账本 head 和假设哈希。结算前还会复核：当前已实现 FIFO 税负必须和账本累计评定一致，防止漏评税、仍用旧评定或用任意零税最终化绕过税款。激活日期、毛应收和股份组件也必须与这份现金公告一致。

先派息后卖出的情形使用 `tax_payment_event(ledger, as_of=...)` 生成后续扣款。仍持有时不自动税负最终化；尚无评定、无应付或未到保守现金可用时点会拒绝扣款。

## 不重复计入复权收益

适配器只接受 `price_basis="raw"`；传 `qfq`、`hfq`、其他调整模式直接拒绝。它不读取行情、不计算股票价格收益、不处理复权因子，也不向旧回测 PnL 添加分红。只有外部明确的原价成交回报与这些现金事件一起进入原始股份账本。

这个参数检查不能单凭字段名证明调用方实际传入的数值一定是原价；上游仍须提供数据字段来源、原始价格证据及费用/撮合契约。禁止把已有前复权策略净值拿来再加本适配器的分红现金。

## 待办与两问自检

后续首先核实自然月/自然年边界、各历史时期规则和账户税务舍入，再扩充税档；不能把 unsupported 自动转换为免税。然后建立带证券/日期/事件状态/缺失项的覆盖清单，补公司行动修改和撤销，支持送股与不同来源资本公积转增的税务谱系、零碎股分配、上市日期和其他权益组件。新组件必须保留到账/可卖的独立时点。

更多真实实施公告应先作为机械会计对账样本，覆盖部分卖出、跨税档、登记日变动和派息前后处置；在实现真正完整的原价执行回放前，不解除 `execution_valid=false`。性能、持久化、完整费用、交易状态及撮合/容量仍需另行验证。

**这一步做得怎么样？** 从“原始股份账本可以接受明确事件”推进到了“一份有身份的真实公告可生成可重放的模拟事件”，并能追溯原股批次与短期红利税。范围受支持税档、精确分金额和现金分红限定，失败不会被消失或当作零税。真实原价小样账务通过，但没有声称历史覆盖和可执行性已经通过。

**下一步该做什么，如何改进？** 完整化历史税期/舍入证据及公司行动覆盖契约，再逐个加入复杂经济路径。保留机械样本与策略收益验收的分工，先发现并解释账差，再决定如何接入研究系统；不为产出 Sharpe 大于 1 而替换、舍弃或重写不利现金流。
