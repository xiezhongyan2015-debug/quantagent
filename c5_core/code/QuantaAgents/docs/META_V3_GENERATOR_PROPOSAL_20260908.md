## 已接通的路径

控制器先保存共同模板、明确顺序的参数轴、固定与随机候选、种子、来源及预算，再创建隔离的模型提案任务。模型只能查看输入、登记一批候选、查看候选表和提交终稿；该阶段没有策略执行、收益诊断、来源扩展或额外登记机会。

请求只提供共同模板与允许参数域，不提供控制组种子、所选候选或结果。提案任务结束后，封存入口逐一核验全部调用，包括终稿和失败应用对应的调用，不只核验选中的登记响应。请求模型/effort、调用身份、输出、schema、原始事件摘要和每次输入/输出 token 必须与账本一致。

每个预留槽位保留来源候选，按域内、域外、无效或未提出分类。重复候选继续占位，少提候选不获得补位机会。模型来源来自已核验的调用链，不能凭 `origin` 字符串获得独立生成器身份。模型程序进入共同域的判断沿用事前固定的可执行模板语法身份；这仍是共同模板中的参数提案，不衡量任意因子或程序创造力。

固定、随机与新增模型账户路径共用现有 `research_batch.run → batch_worker → program_execution.develop`。模型缺失或域外槽位不会执行，保留状态和扫描预留。任一组有未解决执行意图时，三组均不能新增扫描。模型回执、历史或放行记录改变，也会拒绝执行。

工程测试中的生成回执替身只用于验证这些控制流程。封存函数不接受调用方传入的验证结果，而是直接调用冻结的保存完成验证器；另有测试确认只有生成标记文件时会被实际验证器拒绝。这些测试不能证明供应商真实性，本轮真实调用提供了单独的本地完成证据，仍不构成独立供应商请求认证。

## 新的真实提案校准

这是生成数据上的窄提案任务，模板由控制器提供，不能计为从普通描述自主发现新因子。共同模板为：

`where(pct_change(close, {{window}}) > {{threshold}}, {{weight}}, 0.0)`

事前窗口域为 `[1,2,3]`，阈值域为 `[-0.01,0,0.01]`，权重域为 `[0.1,0.2,0.3]`，共 27 种组合，每组预留 3 个候选、144 个扫描单元、完整 100 万元资金。提案调用上限为 4 次、60 万名义 token，保留每次未知调用及终稿的 80,000 token 预留；只允许一个新范围，不重抽种子、不重试未知、不为得到更好候选补开目录。

| 调用 | 实际动作 | 已知 token |
|---|---|---:|
| 1 | 查看输入覆盖 | 13,228 |
| 2 | 登记候选批次 | 15,644 |
| 3 | 核对完整候选表 | 15,562 |
| 4 | 提交合法弃权终稿 | 17,885 |
| 合计 | 全部已应用、无未结调用 | 62,319 |

模型选择单日窗口与 0.1 权重，对比 -0.01、0、0.01 三个阈值，对应共同域索引 `[0,3,6]`。它明确区分了阈值信号集合的算术包含关系与实际成交、持仓或净收益排序，没有宣称盈利。三个候选都符合冻结模板，登记校验错误为零；144 是预留量，不是已执行扫描量。

本次模板沿用了原工程夹具的 `Nonzero fees` 文字失效条件。模型如实保留，并在终稿中指出有费时会触发这个声明。这是此次输入设计的限制，不能把这些提案交付为有效的有费交易策略。失效条件属于文字声明，不能冒充执行器已经自动验收了费用；本次实际拒绝执行的原因是缺少运行时模型/effort 确认。未来正常策略模板需要在新实验前根据真实意图审阅这些文字，本次已暴露记录不回写、不补做调用。
