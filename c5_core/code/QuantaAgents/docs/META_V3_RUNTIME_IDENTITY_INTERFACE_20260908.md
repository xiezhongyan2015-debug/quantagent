# 运行时身份接口核对：App Server字段的证据边界

本轮没有找到可用于确认原4次调用的逐次模型/推理强度凭证，也没有修改网关。具体排除了把App Server线程配置或账户验证通知当作模型执行身份证明的做法。这个结论限定于本机导出的协议及所核对的官方说明，不断言所有其他受支持接口均无此能力。

[官方App Server文档](https://learn.chatgpt.com/docs/app-server)支持从本机可执行文件导出与版本对应的协议结构，并区分线程、轮次与通知。本机版本为codex-cli 0.153.4，一次带experimental字段的导出得到416份JSON文件、4,137,012字节；每份文件的哈希均已保存和核验。

逐字段证据见`validation/runtime_identity_interface_001/schema_findings.json`：

| 字段或通知 | 当前证据含义 | 不能据此声称 |
| --- | --- | --- |
| Thread.model、Thread.reasoningEffort | 已加载线程的配置或最近保存的设置；说明明确排除逐轮执行遥测，允许空值 | 该次回答实际使用了指定模型及推理强度 |
| ThreadStartResponse | 返回线程配置，含model和可空reasoningEffort | 对供应商实际完成响应的独立证明 |
| TurnStarted、TurnCompleted中的Turn | 所定义对象含状态、时间、条目等，没有model/effort字段 | 原调用缺失的身份已由轮次对象补齐 |
| model/rerouted | 通知服务宣布的模型改道，含轮次和前后模型，无effort | 没收到改道通知就一定有正向身份证明 |
| model/verification | 账户附加验证通知；本机枚举为trustedAccessForCyber | 已验证模型身份 |
| allowProviderModelFallback | 控制静态目录模型不可用时是否允许替换 | 供应商完成响应的执行记录 |

官方文档同样把model/verification描述为账户附加验证，把model/rerouted描述为请求改道通知。未将名称中的verification误作逐调用模型认证。

阶段预先限制1次schema导出、0次项目模型调用、0次新研究任务或轮次启动、0次账户执行。实际没有启动App Server握手：无研究轮次的握手不能补出缺失的生成证据，协议已足以判定上述字段的边界。帮助命令共4次（其中1次在范围计划前），另有1次版本读取。最初的官方搜索连接失败已记录，随后读取已知官方页面，没有重复搜索或付费重试。

原authentic_001的75份文件及第023阶段18份交接材料均未变化。V3仍57次调用、1,427,801已知token、0研究未知预留；旧V2账单另存。原4次提案调用仍为身份未确认，旧范围继续关闭；正式成功分母0。

这一步推进的是接口选择依据，没有交付新身份传输层或完成模型准入。后续进入全栈资源与跨目录试验登记等独立必需工作；若再研究身份接口，必须有明确的逐调用返回证据契约，不能只把配置字段改名后放行。历史税务、来源覆盖、共享执行、真实成本样本外及前瞻验收仍按原协议推进。
