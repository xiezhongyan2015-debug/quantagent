# A 股 L2 数据契约：固定 8 股、3 日有界审计

本次已经跑通真实数据审计，可据此实现一个**收盘后生成、最早下一交易日使用的量价与盘口日因子 adapter 草案**。样本中逐笔与最终快照的量额能够对齐，但买卖方向、委托事件类型、数据到达时间及真实股份执行仍有缺口。当前 `t_plus_one_execution_ready=false`、`formal_target_success=false`、`promotion=false`。

这不是收益实验。没有计算策略收益、挑选高收益股票、发起模型调用或修改主 `src`；没有读取 2024–2025 行情。132 天是本地 L2 整体覆盖，本次验证范围只有 **8 股 × 3 日 = 24 个股票日**，不能将局部结果写成全市场或半年数据已经验收。

## 固定样本与读取成本

选择只使用 2026-01-05 的 `quotes` manifest 代码名单。分别保留 `60*.SH`、`00*.SZ` 主板代码，对完整 ASCII `wind_code` 计算 SHA256，按摘要升序各取前 4 个；没有使用成交额、形态、价格或收益排序。这里“主板”只是代码范围，不表示已经完成 ST、停牌、退市、历史成分或可交易性筛选。

| 所属范围 | 固定代码，按组内 SHA256 次序 |
|---|---|
| 沪市主板 | 600006.SH、603786.SH、600653.SH、600741.SH |
| 深市主板 | 002296.SZ、002377.SZ、002576.SZ、002527.SZ |

审计日期固定为 2026-01-06、01-07、01-08，读取三类表。冻结计划 SHA256：`ce78d8409c628c794705b03834a456952fa45c143e395b81fb1c59f21f1c5392`。

来源为 `F:/2026(QQ群1097616051后续增量更新)/l2_a_share_parquet`。相关 manifest 的完整内容 SHA256、选中物理文件的大小/修改时间，以及 manifest 声明的文件内容 SHA256，都已保存在 `plan.json`。manifest 内旧路径仍指向 E 盘，实际读取使用 F 盘相对目录。原压缩包记录为已删除，不能在本地重新对照原始源文件。

成本核算来自 Parquet footer 的 `total_compressed_size`，**是本次所读取列块的压缩载荷估计，不是操作系统实测磁盘读取量**；不含 footer、文件系统预读及元数据开销，也不代表内存解压量。

| 阶段 | 估计压缩列载荷与处理范围 |
|---|---|
| 初始 min/max 粗筛 | 45 个物理文件、1,228 个候选行组；若直接读取必要宽列，约 3,133.69 MB |
| 代码列预扫 | 197,878 字节；检查约 2.878 亿行的代码列，按行组逐块处理，不整表驻留内存 |
| 精确命中后 | 只对 90 个行组读取必要字段，并立即按固定代码过滤 |
| 主审计含腾讯日线投影 | 255,596,024 字节，约 255.60 MB |
| 针对异常的补样 | 22,883,329 字节，约 22.88 MB；首个沪/深股票日及已经发现的时序异常 |
| 两轮合计 | 278,479,353 字节，约 278.48 MB，小于冻结的 1.5 GiB 上限 |

完整物理文件 SHA256 **没有重新计算**，否则会为校验重新读取多 GB。新计算的是选中投影行的内容摘要；文件身份仍有“manifest 声明 + 大小/修改时间”的限制，不把二者混称为完整文件内容复验。

## 已核实的覆盖与数据质量

| 表 | 实际选中行数 | 与 manifest 的 24 个股票日计数 |
|---|---:|---|
| quotes | 104,712 | 24/24 一致 |
| orders | 696,111 | 24/24 一致 |
| trades | 564,923 | 24/24 一致 |
| 合计 | 1,365,746 | 72/72 表级计数一致 |

各表的 `(wind_code,date,source_row_no)` 在样本内无重复；去掉 `source_row_no` 后，完整投影记录也没有重复。关键代码、日期、时间和数值列未发现空值，但若干语义字段有结构性空值，见后文。代码中 `code` 如 `sh600006`、`wind_code` 如 `600006.SH`；`exchange_code` 的样本值为 `600006` 这样的六位证券代码，不能把它当成 SH/SZ 市场标识。

所有 `time_raw` 均能按 `HHMMSSmmm` 还原到 `event_ts`，日期一致。Parquet 类型是 `timestamp[us]`，实际源精度由保留的毫秒值约束，不能因为存储类型是微秒就宣称有微秒级撮合顺序。时间戳未携带时区；按中国本地交易时间解释与样本时段一致，但供应商转换说明与接收时间尚未取得。

## 量价单位与日线对照

有效成交采用以下明确过滤：

```text
trade_price_x1e4 > 0
AND trade_quantity > 0
AND (trade_code IS NULL OR trade_code != 'C')
```

本样本中，沪市正成交的 `trade_code` 为空，深市正成交为 `0`。扩大样本时，未认识的新非空代码应进入隔离区，不能仅凭“不是 C”就接受为成交。当前 88,419 条非正价记录恰为深市 `C` 类；其价格为零但有正数量，不能将数量加进成交量。

过滤后共有 **476,504 条正价、正量成交**。24 个股票日均满足：

- `sum(trade_quantity) == 最终 quotes.cum_volume`，差值全为 0。
- `sum(trade_price_x1e4 × trade_quantity) / 10000` 与最终 `quotes.cum_amount` 的绝对差最大为 0.5，符合累计额整数舍入的经验表现。
- 有效成交价、连续交易有效一档报价的 `_x1e4` 值均为 100 的整数倍；除以 10,000 后形成 0.01 的报价步长。
- 腾讯日线 `volume × 100` 与 L2 数量差在 −50 至 +47 之间，且腾讯样本数量为整数。这支持“腾讯数量按整数手保存、L2 为股数量”的经验解释；不是对供应商正式单位说明的替代。

对照文件为 `data_cache/periodic_active_buying/tencent_qfq_daily_20260101_20260722.parquet`，通过代码和日期过滤，仅输出上述 24 个股票日。其总体覆盖 132 天、5,133 股及 3,362 条公司行动注释的盘点见 `META_ASHARE_DATA_AUDIT.md`；本次没有据此确认全市场完整性。

**腾讯前复权价不能直接当 L2 原价，也不能先验地按一个乘数恢复四价。** 例如 01-06，603786 的腾讯 OHLC 均比 L2 原价低 0.62，600741 均低 1.00，002296 均低 0.13，002576 均低 0.079。四价的比例因此不同；同日四价比值最大跨度约 0.00160。这是样本内可观察的加性平移，未据此推断所有日期的复权算法。可执行价格应使用已核实的原始价，公司行动应另记权益与现金账。

5,561 条正成交的数量不是 100 的整数倍。成交拆分和零股卖出可能产生此现象，不能删去这些真实成交，也不能强行把全部历史成交量向整手取整。策略买单的整手约束与历史成交打印的数量约束是不同检查项。

## 三类表不能按字段名直接合并

### quotes：快照方向字段不可用

`quotes.trade_flag` 和 `quotes.bs_flag` 的 104,712 行全部为空，不能用空值补成中性方向或拿来计算主动买卖额。

累计量、累计额在排序后没有回退；本样本连续交易的一档报价没有负数量、交叉盘口或单边零报价。每个股票日观察到的最大连续交易快照间隔为 6–42 秒。此处没有核实是“无更新不发快照”、采样频率变化还是遗漏，因此不能把相邻快照之间的盘口无限期前向填充。

同一时间戳及之前的正成交累计量，与每条 quote 累计量的完全一致比例仅为 **56.4%–95.9%**，瞬时最大数量差为 1,175,800。最终日累计量一致，不代表逐毫秒可以对齐。快照批次和逐笔源的时间标记/发布时延不同均可能造成差异，目前不能从这些数据唯一归因。

### trades：深市 C 类与 B/S 的边界

深市包含 263,860 条 `trade_code=0` 和 88,419 条 `trade_code=C`；C 类的 `bs_flag` 为空。补样 002296.SZ 的 C 类价格全为 0、数量为正，且 ask/bid 订单号恰有一侧为 0，表现为撤销类事件。它们应单独保留供后续核实，不能当普通成交。

可比较的正成交中，`B` 均对应 `bid_order_id > ask_order_id`，`S` 均对应相反关系。与严格早于成交、至多 3 秒前的一档报价比较，也存在预期方向的一致性，但不完全匹配。例如 600006.SH 的 B 类约 96.4% 在先前卖一或以上，S 类约 93.6% 在先前买一或以下。

这支持“B/S 是一种与订单序号/主动侧相关的标记”的经验解释。尚不知道它来自交易所原始字段还是转换脚本推导，也没有跨通道序号规则。**没有投资者身份字段，不能将 B/S 写成主力建仓、机构交易或真实资金流入。** 下一版公共因子接口的 `aggressor_direction` 与 `active_buy_amount` 应先为 null；原始 `vendor_bs_flag` 仅作审计字段保留。

### orders：订单事件流需要按市场分别解释

24 个股票日的 `order_id` 各只有一个不同值，无法作为订单连接键；三个补样进一步确认其全为 0。

- 沪市出现 `order_type=A/D/S`，合计分别 223,043 / 84,421 / 48 行。S 类包含 `order_side=I/O/J/C`、零价零量，表现为状态记录，不是买卖委托。
- 深市出现 `order_type=0/1/U`，合计分别 388,168 / 311 / 120 行。它们的正式含义与零价处理规则尚未确认。
- `exchange_order_id` 比 `order_id` 更有用，但沪市同一订单会有多个事件，不能用任意 `drop_duplicates` 删除。仅连接唯一事件时，样本沪市成交订单号覆盖不完整；深市首个补样两侧均能连到 B/S 对应委托。这是局部连接证据，不是完整订单生命周期重建。

下一版最小 adapter 暂不输出净新增委托、撤单率、订单簿重建或排队成交模拟。应先取得事件编码、订单标识范围、频道/序列号及更正规则，再分别实现两所的状态机。

## 排序、重复时间与交易阶段

物理读取顺序存在回跳：quotes 23 次、trades 22 次、orders 38 次。行组文件不是可直接顺序回放的撮合流。

按 `source_row_no` 排序后，quotes 和 trades 没有时间回退；orders 有一次：600741.SH、01-07，源行 45,876 的 `14:57:00.050` 状态 J 后，源行 45,877 是 `14:57:00.040` 的 A 类委托，回退 10 毫秒。补样原值保存在 `semantic_samples.json`。

逐笔有 290,463 个重复时间戳，委托有 144,268 个重复时间戳，但它们不是相同事件。**不可用 `event_ts` 去重。** 对每个 `(table,date,wind_code)` 稳定排序 `(event_ts,source_row_no)` 能给出可重复的聚合顺序；它不能证明同时间戳的 quotes/orders/trades 谁先谁后，`source_row_no` 也不是跨表全局序列号。

样本有盘前、开盘集合阶段、连续交易、午间、收盘集合阶段和 15:00 之后的记录。15:00 之后共有 quotes 15 行、trades 1,480 行、orders 12 行。不要用简单 `time <= 15:00:00` 删除全部尾部记录，再把丢掉的收盘成交解释为数据缺失。日末总量验收应包括完整当日源文件；具体收盘事件归属需要上游时间定义。连续交易盘口特征则应显式分开两个交易时段，并隔离集合竞价与盘后记录。

## 下一版最小日因子 adapter 的明确接口

机器可读草案在 `adapter_contract_draft.json`。这是下一步实现要求，**尚未声称 adapter 已实现**。

| 输出字段 | 类型与含义 |
|---|---|
| `wind_code, trade_date` | 证券代码与该批数据对应交易日 |
| `last_event_ts` | 当日源时间最大值；不冒充本地接收时间 |
| `available_at` | 可空时间戳；当前缺少真实到达时间，保持 null |
| `trade_quantity_native` | int64，有效成交数量；股单位属于经验确认，官方待核 |
| `trade_amount_price_x_quantity` | sum(价 × 量)/10000，候选人民币成交额 |
| `trade_vwap_price` | sum(价 × 量)/sum(量)/10000，原价口径 |
| `quote_median_spread_bps` | 有效双边连续交易快照的价差；质量未过则 null |
| `quote_depth_imbalance_l1` | (买一量−卖一量)/(买一量+卖一量) 的拟议时间加权聚合；不跨午间、集合竞价或大间隔延用 |
| `aggressor_direction, active_buy_amount` | 当前 null；方向契约通过后再启用，null 不等于 0 |
| `order_imbalance_or_cancel_rate` | 当前 null；两所订单事件契约未通过 |
| `quality, feature_status, reason_codes` | 来源摘要、计数、重复键、时钟、阶段、覆盖间隔、量额残差及拒绝原因 |

adapter 应由可信执行器读取原始字段，模型只拿到允许的日因子与质量状态。第一步可以研究普通成交活跃度、原价 VWAP、连续交易价差和一档深度不平衡，不预置“主力”解释，不向模型提供未验证的主动资金流或订单重建结果。

最低数据门如下：

1. manifest 完整，所有申请股票日/表有明确预期与实得行数。缺失股票日保留在覆盖分母中，输出拒绝原因。
2. 必需身份、价格、数量字段非空，源事件键唯一，原始时钟与日期一致；未知事件类型不进入计算。
3. EOD 有效成交量与最终快照累计量一致，金额误差在明确舍入容差内。当前建议金额门为一个候选元；扩大样本前冻结此标准。
4. 盘口时间特征先冻结有效时长覆盖、最大延用时间、集合竞价处理。当前只测得最大间隔，**没有核验“覆盖率达到 95%”之类结论**；未计算覆盖率时保持该门未通过。
5. 方向及订单类字段契约未通过时为 unavailable/null；不得用 0 填补后继续产出看似正常的信号。
6. 收盘日 t 的特征最早在 t+1 交易；t+1 新买的股票，最早 t+2 才具有可卖资格。实际交易日历、逐批可卖库存和公司行动另行管理。
7. 对完整当日文件的可用时间、ST/停牌/涨跌停、原始股份与公司行动现金账、执行价格和容量保持独立门。此次均未完成，不得因为日终量额能对齐就打开真实执行或正式收益验收。

本地历史档案由之后集中采集转换，`event_ts` 是事件标记，不能证明相应记录当时已经送达。历史 t+1 研究必须显式列出数据可用性假设；如要验证真实时间约束，应从新的采集数据记录接收时间与完整性标记。

## 产物与复跑

- `scripts/audit_l2_contract_sample.py`：只读脚本，含 `plan`、`audit`、`supplement` 三个入口。
- `experiment_traces/meta_l2_contract_audit/plan.json`：预先冻结代码、日期、字段投影、输入身份及事故读取上限。
- 同目录 `read_plan.json`：代码预扫后的实际命中行组与压缩列载荷估计。
- 同目录 `result.json`：24 个股票日的完整计数、时间、单位与跨表对齐摘要；不保存全部原始行。
- 同目录 `semantic_samples.json`：少量 C 类、状态类、订单号与时间回跳原值。
- 同目录 `adapter_contract_draft.json`：下一版接口与数据门草案。

在项目虚拟环境中执行：

```text
python scripts/audit_l2_contract_sample.py plan
python scripts/audit_l2_contract_sample.py audit
python scripts/audit_l2_contract_sample.py supplement
```

已有计划时 `plan` 会拒绝覆盖；`audit` 只使用已冻结代码/日期并检查身份，不重新选样；`supplement` 只读取已选样本中首个沪/深股票日及已发现的时序异常。运行器没有模型/API/回测入口，主源数据只读。

这一步做得怎么样：把“文件存在”推进到了可以重算的局部数据契约，发现并留存了撤销/状态混流、方向空值、无效订单键、物理排序和跨流快照时延等具体陷阱。下一步应实现上述日因子 adapter 的质量门及拒绝输出，再用固定样本验证确定性；真实执行仍需原始股份账、公司行动、市场状态和容量证据，不能从这次局部工程通过推导出可稳定赚钱。
