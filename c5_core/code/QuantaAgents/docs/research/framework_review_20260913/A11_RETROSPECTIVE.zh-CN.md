# A11 首轮完整复盘（2026-09-13）

范围：A 层重构后从锚定基线到 v8 的全部计算、三批模型提案与三次复盘。所有数字来自研究根目录已保存的结果，2019—2024 均为已曝光历史；2025 数值未加载；2026 年 L2 数据只读了目录与清单，未加载任何数值。旁听窗口转达的观察已逐条核实，认同处采纳，不认同处给出证据。

自评等级说明：A 做到且有证据；B 部分做到；C 没做或做反；D 做错。

| v1 | 全池 90 成员，原始目标 | 0.0769 | 0.0565 | +0.002：成员从 50 到 90 几乎无用 |

独立重放（从表达式重算全部成员、换随机种子）：v3 为 0.1121 / 0.0998，v5 为 0.1134 / 0.0994。均值在千分之一内稳定；最差年（2021）在 0.10 ± 0.001 之间随种子波动。因此只能写"六年均值 0.113 稳健过 0.10"，不能写"每年都过 0.10"。

v7 的条件特征与多种子：均值 +0.001，与种子重放显示的均值噪声（约 ±0.0002）相比是可辨的正增量，但最差年 −0.001 在种子噪声范围内；两项加起来没有改变结论。转达观察全部核实无误。

问题清单：组合层只保存年度 IC，没有落盘逐日逐股分数；组合没有报告多头端超额与换手，无法判断可交易性。

## 2. 因子本身的强化与优化方式（自评 C+）

| 手段 | 状态 | 说明 |
|---|---|---|
| 去极值、标准化 | 部分 | RankIC 本身对单调变换不变；Pearson 诊断用 1%/99% 缩尾加标准化；组合特征按日百分位排名。没有把预处理当作可比较的因子变体 |
| 排序 | 已用 | 表达式语言有截面排名算子，组合特征全部排名化 |
| 市值中性化 | 部分 | 有截面中性化算子，41 个模型提案中约 20 个手工用了；没有对全池做"中性化前后 IC"的系统对照 |
| 行业中性化 | 未用 | 冻结面板没有行业字段；仓库早期提到过申万行业表的导出脚本，但本机当前没有该库，且需要点时版本 |
| 风格中性化后 IC | 未用 | 只报告与市值、换手、波动、动量的暴露，没有报告中性化后的 IC。这是低成本高价值的缺口 |
| 条件化与交互 | 部分 | 三批共 9 个交互候选；剥掉主效应后纯交互项均值 0.014、最差年 −0.003，交互家族基本证伪 |
| 平滑与换手控制 | 部分 | 报告前十分位日换手（池内中位数约 0.10—0.25），但没有做平滑变体或把换手纳入准入 |
| 池内正交化后的增量 IC | 部分 | 冗余用采样日排名相关控制；模型自行做了若干残差化候选；**没有系统的"加入池后增量"指标**。V9A 曾有固定基线 B 对 B+f 的配对增量，A11 反而丢掉了 |
| 覆盖率修复 | 已用 | 第二批后加入股票覆盖率门槛与替换通道 |
| 新数据维度 | 未用 | 本机分钟数据（2000—2026）可为 2015—2024 构造日内衍生特征，未接入；L2 只覆盖 2026 年 132 个交易日，对 2016—2024 的因子评价没有作用，只能用于交易层验证 |

评价口径偏科：核实属实。249 个已评因子中 68 个多头端超额 ≤ 0 而空头端 < 0；池内 135 个成员里 34 个多头端没有超额；池内多头端超额中位数每五日 +0.05%，空头端 −0.43%。KLEN 六年均值 0.069，但顶部十分位相对全池 −0.02%、底部 −0.52%。A 股个股基本不能做空，这些因子的 RankIC 对多头组合意义有限。组合层甚至没有计算前十分位超额。**这是本轮最严重的评价缺陷。**

## 3. 因子间组合方式（自评 B）

已做：等权、岭回归、LightGBM 学横截面排名、逐年扩展重训、三年滚动对照、市值上下文特征、多种子平均、按均值筛成员。证据见第 1 节：改模型设定值 0.02 量级，改成员数量值 0.001 量级。

未做项判断：

| 手段 | 值得做 | 预期增量 | 在已曝光历史上的过拟合风险 |
|---|---|---|---|
| IC/ICIR 加权 | 值得，作为可解释基线 | 约等于岭回归（0.086 量级），低于树模型 | 低 |
| 最大化组合 ICIR（协方差收缩） | 可做 | 不高于树模型 | 中：权重直接在曝光期上优化 |
| 排序损失或直接以 IC 为目标 | 值得 | +0.005—0.01 | 中 |
| 1/5/10/20 日多周期标签融合 | 值得 | +0.003—0.008；池内低波动/低换手族 20 日 IC 高于 5 日 | 中：周期选择本身是一次选择 |
| 树模型与线性模型融合 | 值得，成本低 | +0.002—0.005 | 低 |
| 更高频重训 | 不值得 | 三年滚动已比扩展窗差，说明数据量比新近性重要 | — |
| 样本加权（新近性） | 可试 | 未知，预计小 | 中 |
| 神经网络序列模型 | 本阶段不做 | 公开基准显示与梯度提升相当 | 高：成本大、曝光期上易调出好看数字 |

真正缺的不是模型，是组合层的评价：多头前十分位超额、多头组合换手、成本后收益。没有这些，组合的 0.113 不能转成交易预期。

## 4. 创造能力（自评 C）

核实数字：Opus 三批 41 个候选，六年均值的平均 0.031，最好 0.065；Alpha158 简化集平均 0.0305；遗传规划 60 个候选平均 0.068（含大量数值重复，去重后更低，但最好 0.094 仍高于模型最好）。模型在公式层没有胜过枚举。

所谓新机制的性质：持仓成本偏离对应文献中的未实现盈亏比例（处置效应），换手加权反转、换手集中度都是券商研究里已有的写法。它们是已知异象在本表达式语言里的重新表达，不是新信息。但这也是设计使然：机制目录要求引用已知条目，覆盖图奖励填格子。

配额式提示词是否压制创造力：部分是。"每批 10—14 个、至少三分之一用某些字段、优先填未探索格子"把模型推向按表填空；三次复盘里模型自己两次指出"这个格子可以结案"，说明它有判断，但提案阶段没有"少提甚至不提"的选项。更根本的限制是信息集：日频价量六到十二个字段、受限算子，池内 120 个因子只有约 8.5 个独立方向（第三次复盘计算）。在这个空间里，创造力的上限就是重新组合已知方向。

模型真正强的地方是诊断而不是生成：样本缺失、t 值幻觉、自我证伪、维度计数、"最差年是指标假象"。这些都是被复盘提示词的研究问题引出来的。

## 5. 迭代洞察力（自评：洞察 B，落地 C）

做得好的（已核实）：预测并验证了样本修复幅度；"成员数量不是瓶颈"被 v4—v8 五次验证；第二批提出的"2021 是长窗口年"在第三批用一半名额检验后被干净证伪（七条 250 日候选 2021 年相对自身均值平均 −0.010）；测出约 8.5 个独立方向；指出按 ICIR 看真正脆弱的是 2024 而非 2021。

问题：第三次复盘最关键的三条建议没有落地：准入改为"加入后独立方向净增"、并列风险调整后的最差年口径、评价表加入中性化前后相关、两端超额是否异号、年度 IC 趋势斜率。实际做的是把入池上限从 120 提到 160、再跑一个遗传规划种子、再加成员，与"成员数不是瓶颈"的结论相反。

原因（诚实说明）：编排者（本会话）在追一个具体数字——让 2021 年稳过 0.10——于是选了当时最便宜、能立刻出数的动作，而不是需要改评价合同的动作；框架里有"假设执行台账"约束提案，却没有"框架建议执行台账"约束编排者；复盘的产出是 JSON 文件，没有任何机制要求下一批之前必须对每条建议做出"采纳/拒绝并给理由"。闭环断在编排者这一环，不在模型。

决定权问题：研究模型只有批次内自主，不能要新数据、改标签、转去交易层、宣布方向结案。这确实偏离了"模型负责洞察与决策、程序负责计算记账"的初衷。其中一部分是有意的（协议、标签、验收器不能被搜索过程改掉），但"申请"通道本可以开放：模型可以提出改指标、要数据、关方向的请求，交用户批准。这一版没有这个通道，所以模型的最强能力（诊断）只能影响下一批提案的措辞。

## 6. 元框架方向是否走偏（自评 B−）

是否在为一个已曝光指标做越来越细的优化：v4 之后是。v5—v8 四个版本总共改变均值 0.001，却消耗了大半计算时间与三次内存失败。

研究层过拟合的严重程度：所有入池决定都用了 2019—2024 的六年均值（准入门槛 0.015 或 0.03）；八个组合变体在曝光期上比较后选出最好的；"最差年"本身是在曝光期上定义的选择目标。0.113 里有多少是选择膨胀现在不知道，需要做"只用训练期口径选成员再看曝光期"的对照实验才能估计。这个实验没做，是下一阶段第一件事。

对照项目愿景：项目总目标是可交易、样本外成立、年均夏普大于 1 的策略。A11 完成了此前缺失的度量合同与信息集上限估计，这是推进；但如果继续在日频价量池上追 2021 年的千分之一，就是在局部指标里打转。正确的动作是冻结、转交易层、把 2026 年 L2 留作唯一一次样本外检验（是否启用由用户决定）。

## 7. 问题清单（按优先级）

1. 组合与因子评价缺多头端超额、多头换手、成本后收益，可交易性未知。
2. 入池与组合选择全部使用曝光期，选择膨胀未量化。
3. 第三次复盘三条建议未落地；复盘建议没有强制执行台账。
4. 没有中性化后 IC、行业字段、加入池后增量指标。
5. 组合没有逐日逐股分数落盘。
6. 提案配额压制"少提或不提"，模型没有申请改指标、要数据、关方向的通道。
7. 分钟数据未接入；L2 只能用于 2026 交易层验证。
8. 内存：同时跑两个以上重计算即失败，提交内存约 9GB 可用。
