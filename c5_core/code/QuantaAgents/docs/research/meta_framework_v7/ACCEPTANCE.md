## 实证中修掉的问题与仍然有限的地方

真实流程中有两次上下文准入停止：首次把全因子发现摘要与四臂账户一起传给复盘，第二次又把已复盘的全部账户细节带入下一轮因子选择。两次均在新的付费调用前被 32KB 上限拦下，已经完成的模型响应和账户没有重算。修复为按阶段组装摘要：当前复盘保留原假设、组合结构、年度、成本及配对区间；新一轮选择保留既有复盘结论与简短结果，并恢复因子发现摘要。完整因子和账户结果保持可检索。新增生成数据回归同时覆盖这两个阶段，最终回归全部通过。修复后的两个实际上下文分别为 19,437 和 27,441 字节。

六次真实研究调用合计输入 94,362 token、输出 8,439 token，其中 reasoning output 为输出的 6,504 token 子集，不能再次相加。它比旧研究有更多因子、轮次和后期检验，不能拿这两个不同任务的总量宣称固定比例节省。下文的 33.68% 仅来自相同候选与训练数字的小规模呈现对照。

本轮仍暴露了值得继续做的软件改进：

- 第三次模型调用仍用于查询一个已有对照规格。可增加“基于 run_id 的受限修改”动作，由程序继承未变参数，降低重复输出和配置漂移。
- 第二轮把持股数由第一轮的 40 改为 20、风险 epsilon 也改变了；两轮之间不能被解释为只删除一个因子的配对实验。每轮内部软件生成的控制组仍保持其他参数一致。今后应由程序明确标记跨轮额外变化。
- 本轮没有证明任何真实日历因子的条件或交互增益，模型仍偏向熟悉的动量/反转路线。弱因子交互发现能力目前由合成反例验证；真实研究上限需要更多预声明、多种机制和独立种子的评估。
- 因子库共享定义、数值缓存和试验曝光记录，但跨研究的完整因子证据检索、主动多样性搜索、风险/仓位匹配控制、更多因子适配与网页入口仍未完整覆盖。
- 已验证时间截断与禁用未来表达式，不等于证明所有上游历史发布时间、复权版本、公司行动现金流与执行细节都没有偏差。

## 固定数据范围

- 原始数值授权范围：2015-01-01 至 2024-12-31。
- 2015 年用于历史窗口预热；模型的因子和组合研究视图限制在 2016–2020 年。
- 2021–2024 年只作预先声明的时间外诊断。这些日期已有研究曝光，不能称为独立保留集，诊断结果不得回灌本次模型重选。
- 2025 年只允许来源、日历和文件元数据；不得加载到返回的数值数组、因子标签、账户或统计。Parquet 页可能跨日期，不能把逻辑日期谓词说成物理页完全隔离。
- 股票轴使用旧声明的沪深300历史成员完整并集，按每日成员资格过滤，不按后续收益或可用性替换股票。

声明同时保留日历年请求边界与实际首末交易日。旧账户依赖日历年请求边界识别完整年度，不能因把首日改成首个交易日而漏掉首年。

## 准备阶段

`scripts/accept_meta_v7.py prepare --output <新的绝对目录>` 创建独立验收目录。旧研究、失败记录、资产定义与模型原始回执保持原样。

准备会验证日历、成员名单、旧来源清单与旧模型验收文件的哈希，保存当前实现来源哈希、成本策略、训练截止日与因子诊断语义，并从旧 V6 来源导入因子定义。`--catalog` 可登记因子日历元数据；`--calendar-root` 可登记已逐函数验证的 35 个固定默认参数公式。目录条目不自动成为可执行公式。HF0280 在通用算子缺失时保留 unavailable。

`research_config.json` 给出 V7 controller 可读的训练/诊断 split、项目共享资产和账本目录、原始数据范围、账户政策与有界预算。资产导入 `project/assets`，与该配置一致。配置保存不初始化研究，不消费其中模型或账户预算。

准备只读元数据。原行情文件逐项核对存在性与大小，保存旧清单中的完整哈希；实际数值工人必须再次核对完整来源哈希。准备阶段的模型调用、因子计算和账户执行计数都是零。

`verify` 会重新验证准备回执、冻结声明及来源哈希。`self-check` 只使用临时生成数据检验独占写入与哈希拒绝行为。

## 数值验收

`scripts/accept_meta_v7.py numeric --output <新的目录> --timeout-seconds 300` 通过有界子进程监督器执行固定策略的四个账户，即旧账户/V7包装各跑训练与诊断两个区间。它不运行模型，不改变固定策略。要求：

1. 在任何真实因子数值读取前保存阶段声明和源码哈希，使用新的阶段目录、单次尝试、硬时限和零自动重试。
2. 使用相同初始资金、费用、滑点、成交约束、固定资产公式和原方向，对照旧账户与 V7 截断包装后的每日净值、交易、年度表及目标权重。
3. 因子训练诊断只消费冻结训练截止日之前的数据，末端每个期限保留 `h+1` 个未知信号日；风险标签不成为交易表达式字段。
4. 原因子、条件和交互结果全部保留，包括失败、缺失和负结果。交互候选只作为待检验声明；部分相关不等于已构造的可交易残差信号。
5. 明确账户仍为复权单位开发近似，非独立原始现金分红税账认证；开盘成交、昨日日成交额容量和价格可得时间限制继续披露。

## 两种子、两模式模型试运行

`scripts/accept_meta_v7.py pilot --output <新的目录>` 使用已冻结的 `make_synthetic_task` 构造接口，先保存协议、两个种子、所有单元上下文和隐藏答案哈希，再执行四个真实调用。所有单元使用同一 `gpt-6-astra/xhigh`，通过真实 gateway 保存 prompt、request、原始 events、response、receipt 与本地运行身份。

此处比较同一训练证据的呈现方式，不使用 deterministic benchmark 两种不同候选菜单。种子固定为 20260909、20260910；每种子含三个隐藏类型的合成任务，训练 40 日、验证 80 日、32 只合成股票。两种模式都允许四个单因子和全部六个 `(rank(A)-.5)*(rank(B)-.5)` 交互，共十个候选；每任务最多选一个候选或放弃。

`soft_raw` 给出每候选的逐日 IC、六对因子的逐日秩相关；`V7_compact` 从同一份先保留五位小数的数字计算均值、样本标准差、有效/缺失日数、正值比例和固定前后半段均值。日期与缺失保留，无额外候选或答案提示。两个模式采用同一 24KB 输入、8KB 输出准入、900 秒时限，每单元一次调用，总上限四次。输出字节限制是生成后的准入限制，不能称为供应商 token 硬上限。顺序为种子一 raw→compact、种子二 compact→raw；模型看不到 task kind、生成参数、隐藏答案或验证标签。

准备阶段不发起付费调用。`pilot` 需要独立授权；本次四次调用已获明确授权。单元失败保留原件并计入预算，完成的原始响应只能离线恢复，不为了恢复再调用模型。全部决策终态后才通过 `score_discovery` 和冻结方向的验证期 IC 离线评分。数值生成检查确认：两模式输入均小于 24KB、相同训练数字、末端空标签保留、未来数值扰动不改变训练证据、未知候选被拒绝。

比较报告保留全部四个单元、真实模型用量、时长、冻结选择、隐藏类型评分、验证期 IC、失败与可见数据范围。该表示方式试运行不执行真实市场账户，与另行授权的真实 V7 研究闭环分开计数。四个单元是小样本工程试运行，不能据此证明研究上限、盈利、统计显著性、因果优势或无过拟合。旧不同任务的 token 节省仅作为历史观察，不能冒充受控同任务对照。
