# QuantaAgents V5 开发版

V5把跨年度、跨标的差异接进研究决策。单年或单窗口高Sharpe仍可作为线索，但不能单独决定候选采纳。版本标识为 `quanta_research_v5_001`。本版新增独立代码与入口，复用正在开发的V4执行内核，没有修改旧研究、既有结果或正式评估托管。

当前验收：391项工程测试全部通过，36个原保存账户的1260项指标复核通过，三个完整profile经最终代码重算一致。新入口已实际创建只读c007复盘计划，未调用模型。详见 [VALIDATION.md](VALIDATION.md)。

## 为什么必须改

原框架的问题涉及三个环节：观察侧缺少完整年度/标的分布；决策侧重视当前窗口总分；反思侧没有要求逐项回应差异，也没有把下一次实际实验与反思绑定。只给提示词加一句“注意过拟合”，或在结尾补年度表，都不足以修复这条反馈链。

年度不稳定本身不能证明策略过拟合。框架应把它转成需要检验的问题：相对同口径基准是否仍有增量，差异是否与事前可观察的市场状态一致，费用/换手/资金暴露是否解释表现，以及数据和估值是否足以评价。不能通过删掉坏年份来回答这些问题。

## 迭代如何改变

初次探索允许研究者提出新机制或机制未知的异常，并在冻结预算内登记首个候选或首批。执行后，全部候选进入诊断义务，不能只对选中的赢家生成年度表。研究者读取完整年度与标的差异，分别登记未知、竞争解释、反证、停止理由与区分实验。

继续研究需要先登记 `register_stability_revision`，引用已验证反思中的一个可执行区分实验，同时冻结后续 `develop_strategy` 或 `register_batch` 的完整参数。执行时通过 `v5_revision_evidence_id`核对，不能换程序或另扫参数。新结果必须回到原范围比较，并显式回应变差/未知单元。实验登记、实际执行、结果评估与机制成立分别记录，不能互相替代。

“反思已通过校验”只表示引用、范围和声明结构有效。自然语言解释是否正确，预测是否具有辨别力，新的机制是否成立，仍须看真实实验结果。V5允许承认未知；对不支持的解释允许停止，不强迫编造故事。

## 与正在开发的V4如何衔接

V5通过新的 `V5Runtime` 和 `V5ResearchTools` 继承现有工作循环，调用原有来源准入、执行、账户、预算及恢复接口。V4的公司行动、T+1、税费、交易约束、条件风险工具和历史来源检查继续决定哪些数据能执行。两个开发任务已协同划分目录，本轮没有编辑 `meta_v3` 或冻结v18内核。

V4正在完善的完整市场来源/到达时间证明、公司行动覆盖、正式OOS托管和同资源比较准入仍需独立完成。V5不把来源文件存在、工程测试通过或结构化反思合格当作这些工作的完成证明。

当前V4股票执行后端的既有上限仍包括16股票、512交易日。V5可读取已保存六年账户做连续诊断，但没有擅自扩大执行内核，也没有把六个重置本金的年度短回测拼成六年实盘账户。新策略要在原16股与2020—2025完整范围重跑，需要V4正式接入同范围、连续资金的长区间执行适配；当前不足时会拒绝比较/采纳。这个限制不能靠改scope名称绕过。

本V5入口是有界开发运行。证据准备费用另存测量记录；它尚未被纳入V4/V5同资源、同任务、隐藏重复试验的正式比较协议，不能据此声称V5更省钱或研究能力更强。

## 入口与可复现产物

- `scripts/run_research_v5.py create --root <新目录> --spec <控制器JSON>`：验证并冻结，不调用模型。
- `scripts/run_research_v5.py status --root <V5目录>`：检查当前来源、研究义务和调度状态。
- `scripts/run_research_v5.py run --root <V5目录>`：通过V4既有身份验证和预算运行模型。不会自动迁移旧V4计划。
- `scripts/demo_research_v5.py --root <新目录>`：生成工程例子，走真实catalog、分页、反思、保存证据和下一动作；不调用模型或行情回测。
- `scripts/build_v5_c007_evidence.py --output <新目录>`：从原36个保存账户复现c007诊断，不扫描参数或重跑策略。

控制器spec精确包含 `tasks`、`controller_policy`、`stability_policy`、`bundle_paths`、`closing_policy`、`duration_seconds`、`identity_route`。每个task保留V4的 `idea/documents/case/case_hash`，增加 `v5`：六个新动作的配额、`required_scope_id`、`execution_scope_id`、`execution_unit_id`、预先允许的 `benchmark_program_hashes`、`revision_baseline_profile_id`、`priority`。已有该范围的候选资料时，必须显式指定原基线。实际模型运行可使用V4支持的 `{"version":"codex_session_v1"}` 身份捕获路线；每次响应仍需独立验证。

策略实际执行由V4准入case决定，catalog是开发诊断输入，不能从模型传入任意NAV或路径。没有持仓/费用/估值证据的路径不能获得干净数据结论。所有输入只允许development；正式留出不经此入口开放。

### 可选的逐股连续资金诊断

新建任务可在 `task.v5` 增加 `unit_execution`。未配置时，原单账户接口和结果保留。配置后，`profile_execution` 在完整原股票范围上计算同一个程序，再将非目标股票的目标权重置零，分别运行每只股票的完整日期资金账户。原目标权重不放大，每股诊断本金必须等于主账户本金；这些账户是分别投入本金的诊断，不能相加解释为主账户收益或可部署组合。年度切换不重置本金、持仓、费用或公司行动权益。

例如两股、主账户本金100万元的开发任务可冻结以下配置：

```json
{
  "version": "v5_independent_stock_accounts_v1",
  "codes": ["sh600004", "sh600006"],
  "initial_cash_per_account": "1000000.00",
  "weight_policy": "preserve_original_weights_zero_other_targets",
  "max_account_runs_total": 8,
  "max_wall_seconds_per_profile": 900,
  "max_wall_seconds_total": 2400,
  "max_retained_bytes": 268435456
}
```

逐股账户复用当前V4原始股数后端及其限制，支持既有 `zlib_records_v1` 保存格式，不扩大股票/日期准入。相同来源、程序、资本和政策的基准账户只执行一次，后续复用经过原始文件哈希核验的记录。已启动、失败、未知和达到限额未启动的账户都保留；未知账户不填零，也不重新派发。子进程受剩余时间限制，保存输出量是轮询停止阈值，并非操作系统硬磁盘配额。计量保留子进程墙钟、目标计算/执行CPU、准备CPU及原始输出量；解释器/导入启动CPU未计入该CPU小计。

逐股profile的分母始终是事前固定股票。实际主账户另生成 `main_portfolio_profile`，其完整年度单元在创建profile和读取summary时同时送达模型，不作为另一只独立股票计入覆盖比例或收益集中度。全部逐股原始账本、请求、源码身份、失败、用量、缓存清单与主账户结果仍分别保存；新增接口不提供实盘、执行认证或独立样本外结论。

## c007与验收结论

详见 [C007_REASSESSMENT.md](C007_REASSESSMENT.md)。原36个10bp保存账户拆成16单股、16股等权、中证500历史成员等权三个范围，共108个年度单元；1260项年度/全期指标独立重算一致。三个范围都没有通过开发门。单股只有6/16全期超过对照，年度平均超额仅2023年为正。

这些结果证明单窗口高Sharpe不足以支持此前的泛化判断，也说明V5新诊断能保留相反证据。它们没有单独证明过拟合的具体原因。保存账户仍是复权单位近似，部分持仓采用陈旧估值，正式执行认证保持未知。官方指数择时的既有结果仍在原跨年度研究报告中；本轮V5账户导入没有把指数代理路径当成第四组完整资金账户。

“有根据”在本版成为可执行的证据要求；“有创造力”通过允许未知异常、竞争解释和区分实验保留探索空间。是否同时提高发现质量和创造性，需要之后用新冻结任务和未暴露证据比较，当前不能仅凭框架升级宣布已经达到金融研究目标。
