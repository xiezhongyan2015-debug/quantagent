## 执行与信息边界

- 恰四次真实启动，零自动重试、零新市场账户；四个进程均观察到退出码 0。原回执均验证为本地 `gpt-6-astra/xhigh`，原会话工具调用数均为 0；这不是供应商服务端计算认证。
- 四份 response、usage 与各自原回执一致，逻辑 prompt 与冻结输入一致；生成两模式 schema 和候选菜单相同。真实两模式共同数据与指定父账户相同，操作分别为完整规格与补丁，属于能力接口比较，不能称纯呈现因果比较。
- 本审核在四个单元全部终态后才读取隐藏真值与验证数组。真实数据仅使用保存的六个 2016–2020 训练账户证据，未读市场价格数组或 2025 数值，也未重跑旧账户。
- 未来合同修订前，54 个输入/源码 pins 全部独立核验一致。此后仅为未来 pilot 修订了提示合同；原源码与输入在 `frozen_execution_bundle.zip` 中逐项复核，54 个哈希全部匹配，归档中的原 intent/report 与当前原件相同。不能用未来源码覆盖原运行身份。

## 生成题：相同选择、相同误报，没有观察到增益

两模式对全部八题的候选与方向完全相同：四个正来源题全部找到；两道纯噪声题中误报一道、正确弃权一道；两道单日稀疏题都正确弃权。合计为四次正确发现、一次误报、三次正确弃权，没有遗漏预声明正来源。

独立用保存的隐藏数组重算十个已选候选的日度秩相关及平均值，与原报告全部一致。两个弱交互候选的验证 IC 为 0.03434、0.06906；两模式都误选的纯噪声交互验证 IC 为 -0.02955。这些是生成数据上的方向与来源评分，不是账户收益。

每模式仅一次真实模型调用打包两种子×四类题。任务之间共享构造和随机来源，八题不是八次独立模型或市场重复。V8 增加样本量/缺失支持信息后仍误选同一道纯噪声题，表明“补足证据字段”本身没有解决这次误报；不能据此宣称一般能力下降或提高。

## 真实训练证据：归因正确，接口比较合同不完整

两份原回答均指出逆波动回撤变化伴随仓位变化，无法识别独立风险信息；均识别持股数 40→20、风险 epsilon 1e-6→1e-8，并明确 0.5×rank(F1) 与 rank(F1) 的正缩放不改变排序。两者也选用了指定的 omit_2 父账户。这里观察到的是对既存证据的归因和指定规格遵循，没有自主产生并执行新市场策略。

V7 完整规格通过原冻结评分。V8 原回答的 `changes_json` 使用 `allocation.weighting` 和 `risk_score`，评分器要求 `/allocation/weighting` 和 `/risk_score`，因此原结果为 `invalid_decision`。

原 V8 pilot prompt 只写了字段名及“两个 path/value changes”，没有定义 JSON Pointer、合法路径或示例；原 schema 只要求 `changes_json` 为字符串。实际产品的 `V8_CONTRACT` 则已明确斜杠路径。因而这里确认的是**pilot 给模型的合同不完整**，不能把原失败直接归因于实际 V8 修订 API 或模型的机制推理能力。

审核仅作离线解释：把原回答中的两个字段名按明确的一对一映射解释为评分器路径，所得规格与原预声明期望完全一致。该解释记录为事后诊断，未修改原回答、原报告或原状态，不算原单元通过，也没有给实际 API 新增别名。最小修复是补全未来 pilot 的路径合同与实例；无需为修复本次评估再调用模型。
