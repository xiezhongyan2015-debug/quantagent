## 三个判断及优先级

1. **已确认：修订行为未绑定到复盘中的实验意图。** `meta_v7/controller.py:174-190` 只检查上一批已复盘、因子已有覆盖与轮数预算；`201-232` 对复盘结论只要求非空字符串。原第一轮复盘称下一轮仅改配置，而原两次 `propose_batch` 响应的持股数为 40→20、风险 epsilon 为 1e-6→1e-8。程序接受它们，跨轮结果不能当单因素修订。模型曾主动查询上一轮纯动量控制的规格；`protocol.py:143-154` 在已复盘阶段删除了旧账户 strategy，造成额外付费查询的具体原因可定位。最小价值是保存父账户身份、允许变化和实际变化，不需要恢复 V5 全部文字表单。

2. **已确认的能力边界：权重比较没有识别风险与缩仓。** 轮内 `research_kernel/controller.py:42-69` 从同一规格复制控制，能够固定其他显式字段。但 `meta_v6/portfolio.py:99-105` 先归一化再逐股限额，限额后的剩余资金不再分配。第二轮 `top_n=20`、`gross_exposure=1`、单股上限 0.05，非均匀逆波动权重必然伴随目标总仓位下降，等权则可恰好满仓。这是既定账户语义，不是必须修正的错误。两股票生成反例权重从等权 [0.5,0.5] 变为 [1/3,0.5]，总仓位从 1 降到 5/6，足以反驳“只有权重方式不同就隔离了风险配置价值”。原模型复盘已经识别这项混淆，不能据此指控其错误宣称增益，也不能把后期亏损归因于这一点。

3. **已确认的验收范围限制：测试和小 pilot 没有测一般发现能力。** 原 XML 是 V7 162 + research_kernel 157 = 319 项，并非全仓库测试或 319 次真实研究。`tests/test_meta_v7_model.py:1-4` 明示假传输和生成阶段证据；名称包含 `real_model_action_sequence` 的用例也使用 FakeGateway。原两种子 pilot 的交互收益构造为 0.008*x*y + 标准差 0.004 噪声，冗余代理噪声仅 0.025（`benchmarks.py:57-65`）；可以测试零边际强交互与呈现，但难以判断弱信号、低覆盖或条件信息损失。不能拿继续加同类强信号题证明 V8 发现能力改善。

## V5 到 V7：应恢复什么

V5 的 `meta_v5/tools.py:206-218` 将最新反思、可执行鉴别实验与精确 proposal hash 绑定，且拒绝重复提交；`350-396` 强制保留退化/未知单元并作修订复盘。`meta_v5/reflection.py:196-269` 检查 profile 及冻结 cells、问题响应、反证与实验依赖。V7 没有自动继承这些能力。

保留 V7 的阶段制、程序对照、强模型、紧凑上下文、冻结候选和最终失败关闭。恢复一个紧凑的“父 run_id → 最新复盘 → 允许路径 → 程序生成规格差异”链条即可；不应为每个候选搬回所有 V5 逐项文字，结构合法也不保证语义反思正确。父账户允许是已完成的控制臂；本次最相关父账户是上一轮纯动量删项臂，不能由软件默认选择混合 proposal。

## 最小实现验收建议

受限修订入口接受已完成父 run_id、与其所属 batch 绑定的最新 review、精确路径 patch 和目的。程序继承其他字段、输出变化报告、保留旧 run_id/evidence_id；名称及元数据变化单独显示，不能伪装经济变化。禁止改数据、账户政策、执行来源、预算、验证冻结状态。允许模型声明多个变化，但将其标为复合实验，不能仅凭说明文字声称单因素。

必要的鉴别检查：重放两份原响应的规格差异；当允许变更只有 weighting/risk_score 时拒绝 top_n 或 epsilon 的额外改动；基于 control run_id 派生能保留原持股数；同一请求恢复不得多消费账户；直接重新提交旧规格应复用现有数值；未完成父账户、已封冻验证、错误 review 归属必须拒绝。再检查旧 CLI/协议兼容、阶段摘要大小与闭环收尾。无需重跑固定四账户，因为这些改动不应改变账户内核。

风险归因的最低交付可以是解释性状态 `not_identified` 加确定性反例，不必立即新增 allocator。若决定增加匹配控制，必须在收益出现前用同一时点可知的候选、风险值、限额与目标仓位构造；禁止用全期平均实际仓位或已知净值做事后缩放。匹配目标仓位仍不能自动匹配成交后仓位、换手和成本，须分别报告。

## 原验收证据实际证明什么

- 原固定数值报告确认训练、诊断两个区间的新旧 daily/trades/annual/targets 内容哈希逐项相同，交易计划、政策及除耗时外汇总相同，共四账户。证明该固定规格的包装一致；不证明任意规格一致或搜索更好。
- `release_acceptance.json` 核实 stopped=true、pending_stages=0、6 次模型调用、两轮复盘及 8 次账户执行。没有理由恢复旧研究。
- 原第二轮模型明确说 Sharpe 增量区间包含零且缺少仓位匹配；最终验证否定稳健性并关闭。研究失败被正确保留是流程价值，金融表现失败不直接确定框架根因。
- 数据只沿用已曝光 2015–2024 范围；2025 数值未读。本次建议不提供新的独立市场样本。

## 有界验证建议与实际设计预算

正式设计已选择 `DESIGN.md` 的四调用、零新账户方案；以下验证建议在该预算内执行，实际调用前另存冻结协议与源码身份。旧 V7 余额不继承。本审核没有调用模型。

零账户，最多四次本地真实 gpt-6-astra/xhigh 调用，两个任务包各比较冻结 V7 和 V8，顺序交叉。每包包含弱交互/低覆盖、同源冗余、无信号负控，以及一项使用现有真实训练证据的修订/归因决策。两版本每包的数值、操作集合、最大输出和每次选择数相同；只变更拟测软件提供的证据与动作表达。新种子用于重复生成，不称新市场样本。先离线检查弱交互不再是原 pilot 的近乎必答强信号，预存隐藏答案与不确定/弃权标准。记录发现、误报、弃权、误归因、额外查询、不可执行动作、token、时间和全部失败。若 V8 只少字节而相同调用预算内未增加有效决策，不宣称能力改善；若遗漏覆盖信息、增加误报或错误归因，回退摘要变化。

当前问题能用保存数值判别，无需新增市场账户。若模型明确识别了值得计算的全新实验，后续应另冻结候选、父账户、匹配控制、预算和时限；当前预算不自动扩充。使用旧真实证据的模型研究决策与完成新市场账户闭环分别记载，不能冒称后者已经完成。2021–2024 始终是已曝光诊断，不用于本次候选重选。

设计预算为四次模型调用、零新账户，单次模型 900 秒、总墙钟上限 3900 秒，32KB 输入/12KB 输出准入、零自动模型重试；输出字节是生成后准入而不是供应商 token 硬上限。每次回执与使用量即时保存；原始响应先离线恢复，身份或未完成状态只阻断依赖该调用的单元。未开展新的市场账户闭环时，保留该项未验证状态。

已存在入口是 `meta_v6.gateway.CodexGateway` 加 `verify_saved_completion`/`capture_saved_session`，及 V7 `model_step` 和 `scripts/run_research_v7.py`。`meta_v7/model.py:14-18` 验证 gpt-6-astra/xhigh 和本地 runtime identity，`53-76` 优先离线恢复且不发隐式重试。旧 `scripts/accept_meta_v7.py pilot` 固定为旧两种子/两模式/四调用，不能直接启动后冒称 V8 试验；应复用 gateway 和冻结/回执原则，采用新的协议与新目录。身份是本地配置验证，不是供应商服务端计算认证。
