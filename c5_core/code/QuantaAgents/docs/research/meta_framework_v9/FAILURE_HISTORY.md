# V9 本轮保留的失败与修复

## 9.0.0 真实选择被缺失资格证据阻断

最初闭环的15个市场开发账户全部完成，最终全训练段拟合状态为 `fitted`，四套完整策略均已保存。但 `selection_packet` 只发送最终选中因子，没有发送最终拟合状态和可用规格清单。模型按“必须最终拟合成功”的规则正确拒绝；这是程序遗漏证据，不是策略无效的金融结论。

原研究保持关闭，保存于 `output/research/meta_v9_20260909/study`。其选择结论为“缺少final_fit成功记录，无法确认晋级资格；本轮不冻结候选”。原始输入、响应、本地身份、用量和15个账户均未覆盖。最初共2次调用、33,259 token。冻结20项源码/输入另存 `initial_source_bundle.zip`；修改前已对15个账户完成独立净值/逐笔费用核验，记录为 `initial_release_verification.json`。

9.0.1 补充 `final_fit_status`、各方法状态、完整可用规格清单及各折/最终交互系数与缩放。失败状态和零系数原样保留，不能推断成功。定向状态机检查16项通过，其中3项专门覆盖此缺陷；不将它们与原447项直接相加冒充新的全量运行。

续接写入 `study_context_repair/context_repair.json`，复用原15个开发账户与全部原拟合规格。数值、账户代码按原冻结哈希检查未改变。原2次调用记入总分母，为修复接口额外允许1次模型调用，使总上限由3变4；账户总上限仍18。初始筛选仅重新计算早期2016–2017摘要并要求与原件逐值一致，用于绑定新代码/配置来源，因子数值全部缓存命中；没有重新运行开发账户或进行新参数搜索。

修复后的真实选择输入23,026 bytes，低于24,000上限；模型选择 `ridge_augmented`。冻结规格与原最终候选完全相同，然后才解锁2021–2024已曝光诊断。F2×Amihud系数为正，和原预期的负向调节相反；交互在三个开发年度也没有稳定净增量，因此原交互联合假设被否定。

## 准备与迁移中的可恢复工程问题

- Windows项目虚拟环境的既有可编辑安装路径使用系统编码，强制UTF-8启动会在项目代码运行前失败。使用普通Python启动并单独设置输出编码，不改安装文件。
- 早期摘要在新增来源绑定前已计算。补绑定时重新计算并强制与原摘要相等，保存 `previous_unbound_result_recomputed_and_equal=true`，未据结果修改规则。
- 上下文修复迁移脚本最初引用不存在的 `first_material_resolution.json`，在模型调用前停止。改为只复制实际必需的不可变证据，对半完成目标逐文件核对后续接；旧研究没有写入或覆盖。

工程缺陷已修复不等于架构效率优势、策略盈利或独立样本外验收。最终金融结果以 `ACCEPTANCE.md` 和诊断原件为准。
