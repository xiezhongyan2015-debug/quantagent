# 下一轮架构实验：先消除搜索次数差异，再检验诊断决策机制

状态：2026-09-06 设计稿，未实施、未启动模型。此文档只读取现有代码、协议和已结束的 8 项开发轨迹；未读新行情、确认或最终时期，未改业务源码。正式启动前必须把下列设计变成控制器配置、权限、计量和验证规则，再冻结清单。文档本身不构成已经实现的能力。

## 决定

**先做同工具配额的短消融。暂不再直接启动一批自由分配动作的百万 token 比赛。** 当前候选的指导改变了工具选择；它的作用可能包含“避免不合适的诊断”“把诊断机会改成更多组合搜索”及其他研究路径变化。不能只根据候选最终分数高，就归因为期限对齐改善了机制推理。

下一轮仅比较原基线指导与已经冻结的旧候选指导，在相同工具时隙、调用机会和成本上限下的行为及开发结果。新的“预承诺解释 → 区分诊断 → 根据证据改策略”机制另成一个后续实验；两项不能同批一起改。执行器、工具报告或上下文整理如需修复，先成为双方共同的环境版本，不算候选独有优势。

需要同时保留以下判断：

1. **这是开发证据。** 7 份最终开发成绩全部低于 1；全部完成项 `execution_valid=false`。有效正式策略成功数为 0，分母为原计划 8，不是 7。短消融也不能通过换分母使目标达成。
2. **名义调用数相同，研究机会不同。** 旧代码每个模型调用只返回一个动作，诊断与组合回测消耗同一个轮次。完整基线和候选都是 12 轮，但候选多得到 4 次可反馈的组合策略检验。12 轮不等于相同搜索机会。
3. **不能倒推“全部优势就是多回测”。** 从已存候选轨迹作描述性截断：第 02 项前 7 次 backtest 的最高开发 Sharpe 为 0.375607，第 06 项为 -0.066320，第 07 项为 -0.190496；因此早期路径差异也存在。最高前缀分数不是模型在被提前停止时会真正提交的结果，不能作为随机消融结果或重新提交策略。
4. **任务逸出会夸大跨题能力。** 第 02 项最终是 `rolling_mean(float_market_cap, 60)` 配 `close > 0`，已去掉原“相对强势延续”的条件。它可以作为开发中发现的另一个策略存档，不能未经机制归属审查就算完成相对强弱任务。不得在看到本次成绩后临时惩罚旧组；新规则从下一批双方共同采用。
5. **重复结果不等于独立市场证据。** 第 06/07 项最终策略仅在 `0 - x` 与 `-x` 的写法上有差异，其他规则相同，收益完全相同。两个模型独立启动仍保留为两个运行结果，但市场收益证据没有因此翻倍。现有策略哈希识别 JSON 字符串，不能识别所有经济等价策略。
6. **自检文本没有自动形成约束。** 现有 `hypothesis`、`expected_observation` 和 `self_check` 是自由文本；控制器检查表达式和动作合法性，没有执行“先声明的失败分支必须被遵守”。漂亮解释不是机制闭环的证据。

## 3. 实验 Q：同工具配额的旧指导消融

### 3.1 唯一处理变量

Q-A 使用原基线指导全文；Q-B 使用已冻结候选“诊断期限事前对齐执行机制”全文。不删掉 Q-B 的规则以适应新实验，不加入新机制承诺模板。完整提示词中除这段指导及架构标识外，其余内容、工具定义、上下文装配、数据和起点一致。双方都是 `gpt-6-astra / xhigh`，没有评审/小模型代理，禁止降级。

工具配额由**可信控制器**固定，而不是只在提示词里请求。主比较估计的是“在同一固定工具日程下，旧指导带来的条件效果”。它不等于旧自由调度环境中的总效果，也不能单独量化有多少效果通过工具分配传递。若要正式量化这种中介，之后需另冻结“指导 × 调度政策”的完整四格实验；当前不支付该成本。

### 3.2 最小日程和案例

固定沿用两个已暴露开发题 `relative_strength`、`volume_expansion`，各 1 个独立重复、两个架构，共 **4 个运行**。每运行上限 **6 次模型调用**，合计 24；先按代码排序执行相对强弱的 A/B，再执行放量上涨的 B/A。顺序和全部四项在开始前登记，不能只在第一对盈利时才扩到另一题，也不能负结果后换题重来。此规模只检验控制与机制可执行性，不估计可靠跨题成功率。

| 模型调用 | 强制时隙 | 作用 |
|---:|---|---|
| 1 | diagnose | 对共同普通起点提出一个诊断请求 |
| 2 | backtest | 根据已有证据提出第一份策略检验 |
| 3 | diagnose | 对当前主要未决解释提出第二个诊断请求 |
| 4 | backtest | 第二份策略检验 |
| 5 | backtest | 第三份策略检验，可保留原策略或做反证 |
| 6 | submit | 冻结单一、已经有有效组合证据的策略，或合法报告证据不足 |

选择短日程是开发阶段的工程/方法消融，不声称它等同原 12 轮研究能力。后续如恢复 12 轮，必须另冻结双方相同的 4 diagnose + 7 backtest + submit 日程，不能把短日程结果直接当正式 12 轮结论。

关键约束：

- diagnose 时隙不能兑换为 backtest。每次仅一个表达式和一个事前声明期限；不许通过一次请求偷偷批量扫描期限、阈值或多个组合。表达式/期限错误消耗本时隙，保留原请求及错误。
- Q-B 若无法建立期限与执行的对应，可提交 `diagnostic_not_identifiable`，明确欠缺依据；此时隙仍消耗，不返还搜索机会。Q-A 也有相同弃权能力。两方获得相同诊断机会，不强迫模型捏造持有期依据或为了用完配额做无意义诊断。
- `backtest` 也可提交保留当前策略；重复请求消耗机会，缓存只省重复计算，不能返还模型或查询预算。
- 普通起点的首次回测由双方共享且在模型开始前冻结，为每方同等信息。准备、提交复现和最终复核都登记计算次数；其中不向模型返回新反馈的同哈希复算不是新增搜索机会。
- **submit 禁止首次提出未测试策略。** 提交哈希必须属于本运行此前有效组合结果（含共同起点）；另一合法终态是 `no_supported_strategy`。终态不触发自动选取历史最高 Sharpe，更不能补交代理模型猜出的策略。这个共同规则修正现有 submit 会执行任意新策略的漏洞，但不归功于 Q-B。
- 不限制基线自然产生竞争解释，也不向其隐藏原本拥有的工具。两方都能提出日线字段间的新组合；固定的是获得证据的机会。

### 3.3 工具能力不能被假定已经具备

现有 `AShareCase.diagnose` 返回开发期整体分位组、逐年组收益、同日高低组差；它是固定期限的下一开盘事件毛收益描述，不是逐笔库存的真实退出归因。分组边界来自全开发期，只可用于描述，不能作为点时交易阈值。它没有真实持有期分布、条件匹配、行业中性化或完整交易成本归因接口。

启动 Q 之前，两方共同起点至少需要可核对的实际成交批次/退出期限摘要；若尚缺这个摘要，Q-B 的“期限无法对应”是有意义的负结果，不允许偷偷从调仓间隔推导答案。诊断保持描述性时，过程试验仍可进行，但金融分数只作开发联调，不承担“真实执行下收益改善”的证明。

如果新增实际成交归因或新的诊断统计，在 paid run 前使其成为双方共同、版本化且通过数值/因果验证的工具；不得给 Q-B 悄悄增加报告内容。不得在 Q 的一半运行后更新执行器或扩充数据。

### 3.4 成本政策

固定工具机会、同 effort、同调用上限与同 token 上限，比要求双方最终 token 数字完全相等更可操作。实际推理用量由模型决定，不能通过无意义填充 token 获得“等成本”。因此报告两个维度：同机会下的结果，以及实际花费/时长。成本比率只作描述，不让低成本除法替代收益有效性。

建议 Q 的开发预注册值：每运行软提醒 300,000 token、事故上限 600,000 token、6 次调用、每调用 30 分钟、每运行 4 小时；四项批次事故上限 2,400,000 token、24 次调用、16 小时，研究模型并发 1。上限不是消费目标，正常负实验不触发停止。旧完整运行约 43.3–44.6 万 token/12 次调用，粗略线性估计短批约 86–89 万，但上下文增长和推理随机性使该估计不是保证；启动前以当前网关回执再次冻结预留口径。

在途预留和未知用量继续沿用已有账本，不能把未知当零；上限决策含在途预留。全量测试或数据扫描不与研究模型并发争抢内存。付费调用失败不自动重试，原状态和费用保留；恢复只复用已经落盘且身份一致的回执。若将来允许供应商故障补跑，另冻结双方一致规则，原四项分母不被擦除。

预算不足或模型未能提交是该日程下的失败，不得单方面增加轮数。只能在第一对出现数据/模型/配额/恢复约束失败时暂停整批修工程；财务分数高低不决定是否完成其余已登记运行。

### 3.5 事前判断表

Q 的主检查是 **处理实际生效与约束完整性**：双方是否遵守相同日程；Q-B 是否真正提出可核查期限依据或诚实弃权；失配是否在动作前识别；提交和成本能否完整追踪。两题各一对不作显著性或稳定性判断。

| 观察 | 可以得出的下一步 |
|---|---|
| Q-B 仍无可对应诊断，时隙均弃权 | 现有诊断工具/策略退出合同不足，原候选主要实现的是回避诊断；先修共同工具，不能称期限对齐已被验证 |
| Q-B 与 Q-A 路径/结果接近 | 原自由调度优势在同配额条件下未重现；搜索次数/调度是合理解释，但不是已证明的唯一原因 |
| Q-B 在两题均有不同、可复核的期限处理且提交改善 | 值得下一批同日程重复；仍只是短开发样本的方向证据，不晋级、不读 final |
| Q-B 诊断更漂亮，金融开发结果无改善或更差 | 机制约束可执行，但尚无策略效用证据；不要用过程分数取代 Sharpe 目标 |
| 任一方越权、未知用量、身份或数据漂移 | 停止合并，保留失败；工程修复后建新版本，不接着拼成原冻结批次 |

所有 4 项均在 denominator。另报合法提交率、明确放弃率、失败率及有效提交的开发 Sharpe、回撤、成本和机制归属；失败 Sharpe 为缺失，不造一个负无穷数，也不把失败从整体效果报告中删除。

## 4. 实验 M：只增加“可执行的证据分支承诺”

Q 完成归因盘点后，才决定是否实施 M。M 不自动继承 Q-B；默认从共同简单指导作为 M-A 对照。M-B 的唯一变化是：**在查询新证据之前，绑定待比较解释、判别统计和结果对应的下一动作；查询之后控制器检查动作是否遵守承诺。** 不同时引入多角色辩论、长期记忆、模型评审、提示词集成、自动更多回测或更强数据。

M-A/B 继续同样的 2 diagnose + 3 backtest + submit 短日程、同 Astra/xhigh、同工具和成本政策。共同工具升级如已完成，其版本对双方一致。M-A 仍可自发预注册；不禁止自然推理能力。M-B 检验的是预先承诺与执行约束的增量，不是提供更多信息的增量。

### 4.1 最小承诺对象

每个 diagnose 时隙前，M-B 输出一个可校验的 `experiment_contract`，与请求一起写入不可覆盖日志，先保存哈希再执行工具：

- `parent_strategy_hash`、`prior_evidence_hashes`、`failure_type`：明确当前解释针对哪个策略与已见证据。实现错误、数据错误、执行缺口优先返回修复/停止，不把它们当经济因子失效。
- `hypothesis_A` / `hypothesis_B`：两个有不同可观察预测的解释。例如“现有毛收益主要被换手成本抵消”和“未扣成本时已没有足够收益”对同一份成本分解有不同预测；仅把同一句话改写两遍不合格。
- `diagnostic_request`：仅一个已实现工具、同一明确样本、一个预先指定主统计量/方向、最低有效日期/覆盖以及期限依据。无法识别时明确 `not_identifiable`，不默认通过。
- `prediction_A` / `prediction_B`、`result_partition`：给支持 A、支持 B、两者均不支持、信息不足定义互斥规则；有数值门槛则在结果出现前写定。阈值选择来源要可解释，不能由控制器按“能让哪一边赢”调优。
- `allowed_next_actions`：对每类结果预先指定保留、单一机制修改、反证或停止。可直接冻结下一份策略 JSON；不能只写“看到好结果就优化”。参数可以在承诺前合理提出，但不能在结果后临时换另一个有利阈值。
- `expected_cost`、`stop_condition`、`task_relation`：本次工具机会和后续预算、何时停止、与题目普通定义的机制联系。

诊断返回后，控制器根据已冻结统计规则计算 `result_class`，模型在下一 backtest 时隙解释已有证据并请求允许的动作。偏离承诺必须显式记录为 `contract_violation`，本时隙消耗且不执行越界查询；不能默许它覆写门槛后继续获得市场反馈。合理的新发现可写为下一独立合同，不追改旧合同。

这些合同只包含模型公开假设和简明决策，不要求读取或展示隐藏思维链。GUI 展示合同、哈希、观测、分支、自检与成本的链接即可。

### 4.2 一次完整循环如何发生

1. 共同起点给出失败报告。调用 1 在看新数据前保存首份判别合同，然后执行 diagnose。
2. 调用 2 读取结果及程序判定，遵守分支，仅改一项明确机制，再执行第一份 backtest；也允许保留或放弃。
3. 调用 3 回答两问，把新结果无法解释之处作为第二份合同，执行第二次 diagnose。
4. 调用 4 根据第二个结果执行第二份 backtest。
5. 调用 5 做第三份组合检验，优先检查已声称有效改动的去除对照；其选择应在调用 3 的合同中约定。M-A 拥有同等第三次机会。不得偷偷额外调用原策略对照；共同起点或此前同哈希结果可复用。
6. 调用 6 从已经有效检验的策略中冻结一份，或明确没有支持。提交前保存家族关系/逸出和反例；隐藏评测不再回传研究进程。

“单一机制修改”须由有限策略变更合同来实现：例如只更换评分、只增删一个过滤条件、只改调仓/退出规则或只改持仓数。表达式内一次替换可能实际上改变许多因素，所以仅检查 JSON 顶层差异不够；日志保存 AST 差异和公开机制声明，声明与真实信号可由离线审查核对。第一版不通过额外付费评审模型“判真”，数值分支由程序判定；语义可辨识性不足时结果为未证明。

### 4.3 哪些诊断才具判别能力

下表是候选工具合同，不表示现代码已支持。只有共同工具先验算完成，才允许模型请求对应类型。

| 待区分解释 | 能改变决策的证据 | 不能拿来替代的东西 |
|---|---|---|
| 毛优势存在但成本过高 / 毛优势本来不存在 | 同一实际持仓与成交路径的毛收益、明确费用与滑点分解、换手与持有期限；若改变执行重跑则消耗 backtest 槽 | 把某个事件毛收益直接减固定平均成本后称组合收益 |
| 特定环境有增量 / 只是市值、波动或市场暴露 | 事前指定协变量、同日期共同样本的分组或匹配对照，完整覆盖与成本；新统计需先做数值验证 | 最差 20 笔交易、不同日期/资格样本的高低组平均 |
| 出场早于机制兑现 / 信号快速衰减 | 实际可卖库存、真实持有期分布与固定窗口诊断；无法对应则明确不可识别 | 把每 5 日调仓等同每笔持有 5 日，或扫描 1–20 日挑最佳 |
| 规则有广度 / 少数日期或标的支撑 | 预先固定日期子期、留一已登记机制组件的反证；所有失败保留 | 看完结果再删除亏损年度、股票、极端事件或改本金 |

当前事件分组工具单独不能完成上面所有判别。先做到其中一种能影响下一步的诊断，例如从真实执行账本派生持有期和成本分解，并对两方同时提供；这比给 M-B 更多提示词但仍只有不匹配的观察更值得优先实现。

## 5. 避免把调参偶然性变成“架构进步”

工具预算按每次实际请求的策略/表达式/期限计量，失败也占机会。禁止工具暗含未登记网格搜索、自动挑最优年份或替模型选阈值。调用一次工具返回成百上千个候选，与调用一次单策略回测不具有相同机会；manifest 必须写清一个查询究竟暴露多少结果。

预注册保存全部查询和承诺，包括被否定而没有进最终策略的尝试。默认最终策略只能来自已检验集合，但不能以“历史最高 Sharpe 自动胜出”替代模型的单一提交；模型必须报告支持、反例与自己使用的选择规则。对共同开发期反复尝试的门槛不能产生正式显著性。

小实验主结果分成三个独立表：

1. **控制是否生效：** 数据/工具/成本越界率、合法冻结率、合同分支一致性、明确弃权率、任务逸出率。约束导致的形式合规不算机制正确。
2. **研究是否有效：** 在同机会下，多少预先判别能排除解释、多少修改在后续已登记反证中失败、单一最终策略的完整开发表现与成本。过程好但收益无改进时，结论必须为金融效用未证明。
3. **真正目标是否达成：** 按原协议的完整资金、净 Sharpe > 1、风险/活动门槛、执行有效性和冻结样本外定义统计。Q/M 小试不能满足稳定性要求；这个表持续保留“未达成”，不因另两表好看消失。

不得在看完四项结果后补到显著。若值得重复，另冻结固定批次与终点，一次性评价；不把多次开发挑出的最佳架构同时冒充预先唯一候选。最终需要原协议所要求的真实跨家族题目与独立启动；同市场的日期相关和同题重复相关必须保留，不能把四项短试验当四份独立金融样本。

## 6. 数据、题目和执行前置条件

每批在任何付费调用前锁定并验证：题目和输入模式、普通起点、基线/候选指导、调用日程、工具 schema、可见报告字段、上下文上限/裁剪规则、模型/effort、数据投影与股票资格、费用/滑点/日历、环境源码、提交规则、失败处理、时长/token/内存上限、顺序及评估规则。恢复过程同样核验，不能只在首次创建时看一次。

Q/M 开发小试可以继续标记 `integration_only`，但任何真实净收益归因和正式晋级，必须先完成全组合执行层及其股票池的公司行动、停牌/状态、原价库存、容量与日历验证。9 股现金分红链路通过，不能替代 1,079 股历史池全期覆盖。V5 执行层的接入是双方共同环境升级，应重新冻结数据/执行版本；不得把旧近似分数与新真实账本分数混作一条架构提升曲线。

时间边界保持：2017–2021 已暴露开发；2022–2023 已被本项目联调查看，今后只可标记已暴露确认/回放；**2024–2025 继续封存，本设计不打开。** 切换题目不会让已看年份重新未知。旧项目是否看过 final 的污染审计仍需保留；之后冻结的新时期模拟观察不能被历史检验代替。

Q 两题已经开发暴露。未来 M 如采用新普通任务，可从已有题库事前选价格修复和突破等不同机制，先核对全项目暴露记录；题目一旦用于修改架构便转为开发题。正式跨题验收维持至少 6 个真实案例、至少 3 个家族、每题至少 3 次独立研究启动的原建议；现有“5 真题 + 1 负对照”并不足 6 真题。负对照单独衡量无信息下的拒绝和诚实归因，不能凭其随机多头收益计入策略成功。

L2 数据在字段、方向、时点、原价执行及资格未完成前，不加入 Q 或悄悄只提供候选。先在自己的共同数据合同上做可执行回放，再冻结日线与同日期 L2 增量比较。当前 132 日 L2 不能单独满足至少 252 日最终观察要求。

## 7. 实施顺序与停止条件

1. 结束并独立归档旧 8 项结果，完成第 2 节的无模型轨迹盘点。保留失败及成本，原指导与结果不可覆盖。
2. 共同控制器实现时隙配额、弃权、提交哈希门、查询计量、终态/恢复和数据身份校验。用离线 fixture 检查错时隙、变更 final 参数、重复恢复、预算未知、伪造提交和跨运行证据注入；fixture 只证明工程。
3. 固定 Q 的四项清单和预算，按已登记顺序运行，监控只处理异常与终态，不在中途给任一方反馈其他运行成绩。普通负结果照常完成批次。
4. 独立形成 Q 结论。没有可识别诊断，就优先改共同工具；有可复现条件效果，才预注册扩大重复。不要因为结果不满意立刻自动生成无限新指导。
5. M 的合同与判别工具先离线验证，再决定其独立小批；若从 Q 吸收任何新经验，清楚登记 M 的来源和已暴露题目。冻结后不边跑边改。
6. 工具、执行和开发机制均达到前置要求后，才实施完整跨题正式批次。隐藏结果仅由独立评测器查看一次；不向研究 agent 回传同一批次再修改。

事故熔断包括反复相同请求、未知用量、模型身份漂移、数据/代码哈希变化、错误恢复、资源不足或工具请求越界。连续几次否定假设是正常研究，不等于死循环；停止应依据是否重复相同证据而没有新判别，或已用尽预注册机会。

## 8. 本轮两问

**这一步做得怎么样？** 现有 8 项结果显示旧指导改变了搜索分配，但没有足够证据把开发分数改善归因为期限对齐或稳定创造力。设计把同配额消融、共同工具修复和新的证据承诺机制拆成可独立检验的步骤，保留任务逸出、重复策略、失败、成本与未达成目标。没有重新读取最终期或花新模型 token 来补写一个好故事。

**下一步该做什么，如何改进？** 先完成无模型轨迹归因及共同配额/提交/工具审计，再以 4 项短批检验原指导在同研究机会下是否还有可观察增量。若诊断不能改变决策，优先增加双方共享、来自真实执行的成本/持有期证据；之后才检验控制器约束的机制承诺循环。小试证据不足时保留不足，稳定样本外 Sharpe > 1 的完整目标不变。
