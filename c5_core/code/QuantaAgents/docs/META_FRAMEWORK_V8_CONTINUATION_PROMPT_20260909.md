## 独立判断的重点

请从原调用与实际代码解释“模型看到了什么、能选择什么、为什么采取下一步、程序有没有约束非预期变化”，给证据位置。至少审视以下问题，但不必把它们全部变成 V8 功能：

1. **发现能力的实际瓶颈。** 为什么给了新因子和交互证据，研究仍集中在熟悉的少数因子？检索、菜单、摘要、预算、推理、配置或市场本身缺乏信息分别能解释多少？不要把“模型不够聪明”或“库不够大”作为未经检验的答案。
2. **流程完整与研究质量。** 因子已计算、复盘已填写是否真的改善决策？哪些旧 V5 约束在 V7 中被简化，哪些是合理去重，哪些可能造成反证/修订脱节？加强约束也有成本，要用可判别证据决定。
3. **弱因子和真正多因子组合。** 如何发现低边际 IC 但有条件、交互、风险或互补价值的因子，并减少冗余与搜索爆炸？MA5 是动机案例，不是固定必选因子。不要简单只留高 IC，也不要只穷举二因子乘积。
4. **长期研究知识的复用。** 库应该保存什么可复用信息，才能跨种子检索、去重、判断适用条件、记住失败而不过度淘汰？区分公式身份、行为相似、机制相似与独立信息。已共享账本不等于已经可用的知识检索。
5. **组合归因与修订。** 如何区分预测信息、持股范围、仓位缩放、风险配置、换手和成本的影响？基于已有 run_id 的受限修改、自动变化报告、匹配控制只是可选方案。选择最少而有区分力的实验；不能用事后结果构造可交易控制。
6. **更强且更省的接口。** 摘要是否删除了做决策必要的弱信号、覆盖率或结构差异？哪些重复查询和输出可交给软件？不要以字节越少越好替代“同预算下有效研究更多”。
7. **可否证的 V8 验收。** 什么结果会让你承认 V8 没有优于 V7？区分因子发现、误报/弃权、归因质量、泛化和成本。不能只增加单元测试、强信号合成题或专门挑有利案例。

对每个主要问题区分“已确认缺陷”“已知能力边界”“待验证假设”“暂不值得做”。用少量针对性反例或离线轨迹分析确认根因；不要为了评审重复付费调用或重新计算已保存的账户。
