# 原始工具测量回执与离线入账恢复

2026-09-08，第 029 阶段。第 028 阶段独立复核已通过。本阶段补足工具执行已经结束、费用汇总更新中断后的保存证据恢复，不重新执行工具估计原消耗。

工具原调用期间只测量一次。控制器保存原始 wall、进程 CPU、保留输出净增长，以及当时的输出路径/字节数/哈希清单。回执绑定原 study、trial、task、工具调用、请求、逻辑配额、开始时刻、stage plan 和原模型回执指纹。原始测量先在 canonical `tool_measurements` 保存，再更新 `tool_actions.metrics` 汇总。该回执来自控制器测量，不是供应商身份或金融执行证明。

未更新汇总的已保存测量，已经进入 trial 和整个 study 的实际消耗判断，不能靠汇总中断隐藏超额。`unresolved` 包含待汇总应用；新增 `unknown_measurements` 区分没有原始共享回执的未知消耗。配额和原调用次数不因恢复而增加或释放。

恢复只使用共享账本内已经保存并绑定的原始回执。重复恢复不重复计费，不修改模型 token、原应用状态或策略结论。本地 `tool_measurement.json` 只是副本：缺失或改写不会清掉 canonical 已知成本，恢复结果会报告副本状态。原工具产物后续缺失，也不能让已发生消耗变成零；恢复费用不认证这个产物为有效研究证据。

没有共享回执时继续保留未知，包括执行途中中断，以及本地测量文件写完但 canonical 保存尚未成功。不能仅凭可修改的本地副本补猜历史数字，不能用重新执行得到的时间或文件大小替代原测量。旧关闭范围没有自动生成、补签或迁移回执。

普通 `ResearchRuntime.run` 在每次后续模型准入前先恢复已有回执。控制器入口新增 `reconcile-tool-measurements --root ... [--call-id ...]`，可恢复指定原调用或当前范围全部可用原始回执；不派发模型或工具，没有回执的项目明确列为未知。恢复原失败调用的费用后，其历史 failed 状态仍在；本阶段没有把其已保存工具产物重新发布成成功工具结果。

预注册验证保存在 `validation/tool_measurement_recovery_001/plan.json`：最多 40 次测试、零真实模型、零账户/策略 worker、零真实或封存行情读取。单轮实际 13 项全部通过，包括 10 项新检查和 3 项受影响旧路径。

- 真实原工具生产者在生成输入上运行一次，随后人为打断汇总更新；共享原始回执已存在，恢复及重复恢复得到同一费用，原 failed 状态与模型费用不变。
- 改写本地副本、移走本地产物或本地回执，均从原 canonical 回执保留费用；不会重扫当前输出目录、恢复文件或改变金融证据状态。
- 执行中 KeyboardInterrupt，以及本地副本后、canonical 写入前中断，都没有可收养的原始共享回执，未知占用不释放。
- canonical 回执内容损坏，以及重算哈希但换成别的工具身份，均拒绝更新费用汇总。
- 整个 study 在汇总仍未更新时就看见已保存的产物超额，使另一 trial 进入 close_only；恢复后超额数量不变。
- 原 runtime 启动路径确实先恢复，再到下一次模型准入检查。测试在该点停止，没有调用模型；worker identity 记录的是当前测试控制器进程，没有新建后台研究进程。
- 实际控制器命令入口完成指定恢复和幂等空恢复；原 horizon、超额后输入弃权及费用中断路径继续通过。

新捕获包括输出清单读取/哈希期间的控制器消耗。canonical 回执写入、汇总更新等测量元数据开销仍未全部覆盖；child CPU、物理 IO、初始化、提示构建、最终验证和独立控制生产者的全栈计量也未完成。当前控制器进程 CPU 不是可跨并行进程/线程无重叠相加的完整计算账；保留字节数也不是物理读写量。
