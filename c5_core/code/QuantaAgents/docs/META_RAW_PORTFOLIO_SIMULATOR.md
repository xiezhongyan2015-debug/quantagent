# 原价组合执行模拟器：Revision 5

此模块把原价日线、事前目标仓位、原股账本和现金分红适配器连成完整组合现金路径。它服务于执行链路验证，尚不能证明订单可成交或策略夏普达标。主运行包以及正在进行的冻结 Astra/xhigh 对照实验没有修改。

实现位于 `experiment_traces/meta_ashare_revision5/src/quanta_agents/raw_portfolio_backtest.py`，测试位于同级 stage 的 `tests/test_raw_portfolio_backtest.py`。接口为 `simulate_raw_portfolio`。调用方必须明确设置 `allow_incomplete_for_integration=True`；返回值始终包含 `execution_valid=false`、`formal_target_success=false`、`company_action_coverage_complete=false`，且不生成用于晋级的策略指标。

## 开盘决策和成交口径

输入目标必须指定证券、信号日、交易日、带时区的可用时间和目标权重。信号日严格早于交易日，目标在交易日 09:30 前可用；同一股票同一交易日不允许多份目标。每天明确提交的权重合计不超过 1。遗漏证券维持原持仓，显式权重 0 才清仓。失败证券的预算留为现金，其他证券不获得重新归一化的预算。

开盘使用当日原始开盘价、供应商原始除权参考价，以及严格上一交易日的成交量和名称代理。目标预算来自前一日扣税预留后的模拟净资产。当前日的最高价、最低价、收盘价、成交量、成交额、综合 `accepted` 标志及当日名称不决定当天开盘成交；这些字段的未来扰动测试覆盖此边界。当日持仓收盘价仅用于当天日终估值，然后才能影响后续交易日预算。

默认 `slippage_fraction="0.001"`，可以显式设为 `"0"` 做纯账目隔离检查。买入按 `raw_open × (1 + slippage)` 向上取到 0.01 元，卖出按 `raw_open × (1 - slippage)` 向下取到 0.01 元。仓位数量、可用现金和费用均按实际模拟成交价计算。滑点可能使小幅调整不再需要成交，但不会反向产生一笔相反方向成交。

目前只支持普通主板的名称代理价格带：正常名称 10%，ST 名称 5%；IPO、退市名称代理和其他板块拒绝。参考价直接使用供应商 `raw_prev_close`，不重复扣分红。参考价乘价格带后按半入舍到分。买入滑点价触及或越过涨停、卖出滑点价触及或越过跌停时整笔拒绝，不把价格截到涨跌停价假设成交。这些仍是模拟假设，不能替代历史交易状态和排队证据。

容量上限为上一明确交易日股数乘 `participation_rate`，默认 5%，仅为容量估计。买入整百股，部分卖出整百股，已有零股完整退出可保留。先卖后买，同一方向证券按代码排序。买入数量通过有界二分搜索满足货款、全部费用及税现金预留；不会因逐手递减造成无界循环。卖出只消耗已满足 T+1 的实际成交批次，按获得时间 FIFO 分配。周末按下一明确交易日处理。

## 成本、税和每一天的资产

冻结模拟费用采用佣金 3 bp、每笔最低 5 元；将交易经手费用包含于佣金是明示假设。过户费在 2015-08-01 起为成交额的 2/100000，2022-04-29 起为 1/100000；卖出印花税在 2023-08-28 前后分别为 1/1000 和 0.5/1000。各项目单独半入舍到分。这里的费率表不声称复原某个券商账户的实际收费回报。

每笔成交保存原始开盘价、滑点后成交价、股数、滑点每股/金额、费用明细以及开盘依据。**滑点已经包含在成交价中，不能再从现金或净值扣一次。** 日终保留累计费用以及“已包含于成交价的累计滑点”诊断字段。

所有明确日历交易日都估值，包括没有调仓的日子。持仓证券任何一天缺少有效原始收盘价会失败并要求修复输入，不会丢掉持仓、跳过亏损日或伪造沿用价格。失败和输入由调用方的不可覆盖尝试目录留存；此函数不在输入不完整时返回貌似完整的净值。

公司行动由 V5 现金分红适配器生成登记、激活、到账和税事件。未持有登记权益的事件明确记录跳过。现金到账前的应收不成为可交易现金。实际股息税按适配器的完整日终净变动/FIFO规则在 15:05 计算，不能把单笔成交批次直接等同税务批次。详见 `META_CORPORATE_ACTION_ADAPTER_V5.md`。

开盘可支出现金扣除前一日估计未付税，并减去期间已实际支付的税，避免同一已付税被预留两次。新激活的分红此前尚未进入日终税估计，因此激活日额外按所支持的最高短持税率向上取分预留现金；这是保守资金限制，不写成实际税额。日终仍按实际已处置权益税额和剩余权益假想处置估计计算净资产，税估计变化不算现金收入。

## 样本和验证范围

真实缓存试验由根目录 `scripts/run_raw_portfolio_pilot.py` 驱动。固定 9 股，2019-06-24 每股目标 10%，2019-06-26 清空，初始资金 100 万元；63 个请求股票日完整保留。其中当时未上市的 `sh603786` 保留拒单和闲置资金，不替换股票或缩减本金。原先未计滑点的尝试 `20260905T185839345618Z` 保留为旧实现证据；新实现须生成新的尝试目录，不能覆盖旧结果。该案例不做策略搜索，不计算用于目标认证的夏普。

定向测试覆盖默认滑点下的现金/NAV恒等式与只计一次成本、零滑点隔离账目、触限/越限拒绝、非法滑点参数、当日质量及未来数据扰动、缺持仓收盘价、整日无数据、上一日容量、未上市预算保留、先卖后买、跨实际批次 FIFO、T+1 周末和日历末端、非调仓日分红、激活日税现金预留、税到账后预留释放，以及账本重放。这不等同市场全覆盖压力测试。

仍欠缺：整个股票池完整公司行动、送转/配股与税务谱系、历史点时证券状态、真实盘中订单与撮合、正式可成交容量证据及历史数据到达时间证据。完整交易日历目前由调用方提供并检查唯一性和范围；外部完整性没有被本模块独立认证。收盘字段质量、停牌和特别交易状态不能靠名称代理普遍解决。所有这些限制保留为晋级阻断项。

## 本轮自检

**这一步做得怎么样？** 原先默认零滑点的成本遗漏已修正，实际成交价驱动仓位和现金；新激活分红的税现金预留空隙也已补齐。真实案例的目标、股票分母、失败和原尝试保持不变。

**下一步该做什么，如何改进？** 由主任务在冻结后的源码上重放固定真实缓存，独立重算现金、费用、滑点、税、拒单和净值；随后扩大公司行动与交易状态覆盖。通过这一步只代表组合账目路径更完整，稳定样本外 Sharpe > 1 的目标仍需正式冻结策略评测证明。
