# 已记录税额超过现金预留上界的修复

2026-09-08。父任务针对 checkpoint_018 指出的资金保护缺陷已复现并修复。最新 **18 项定向检查通过**，包含 7 项新增评税边界和受影响的原 11 项现金预留检查。独立复核是否关闭该问题仍以父任务记录为准。

## 缺陷与影响

旧模块只核对已付税款是否超过包络，未核对账本当前记录的总应缴税额。生成账户保留完整 100 万元本金，分红后现金 1,100 元、预留上界 60 元。记录应缴税额 61 元时，它仍允许花 1,040 元；若这 61 元随后全部须付，剩余现金将少 1 元。

已付 10 元时也存在同样问题：现金 1,090 元、预留 50 元，但当前未付税额为 51 元。两种情形在最终和非最终评税标志下均复现。修复前的 4 项失败、账户状态、完整事件和旧源码归档全部保留，没有改写原结果。

这属于已实现现金保护层的具体缺陷。输入税额尚未通过历史规则认证，也不能成为默默忽略账本中较大负债的理由。本次均为生成账户，没有真实资金或策略执行。

## 修复后的行为

模块版本提升至 v2。若当前总应缴税额超过未扣付款的原始包络，直接拒绝给出可花金额，不论是否已经付款或标为最终税额。原有实付金额上界检查保留。

比较的是**总应缴税额与原始包络**。例如总税额 60 元、已付 10 元时，未付 50 元和预留 50 元相符，应当通过；不能错误地把总额 60 元与剩余预留 50 元比较。

合法返回现在同时显示账本当前的总应缴与未付税额。总税额低于包络不会释放未核实预留；未知评税保持空值。本模块仍不修改账本、不认证评税算法，也不输出税后净值。
