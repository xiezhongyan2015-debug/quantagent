# A 股多任务架构竞赛：任务定义草案

版本：2026-09-06 / draft-1。本文只定义下一阶段题库与冻结要求，不改变正在运行的实验、源码或预算。没有为挑选这些题计算新收益，也没有读取 2024–2025 年价格或启动模型。数据事实依据 [数据审计](META_ASHARE_DATA_AUDIT.md)，评测边界沿用 [协议草案](META_ASHARE_PROTOCOL_DRAFT.md)。

## 题库组成与用途

下面是 **5 个真实研究题 + 1 个无信息负对照**，真实题覆盖价格修复、趋势/相对强弱、量价异常三个家族。它们根据机制和普通定义选入，不根据哪个题容易得到高 Sharpe 选入；没有设定 MA5 或其他隐藏答案。

| ID | 家族 | 任务 | 当前暴露状态 | 初始适配状态 |
|---|---|---|---|---|
| R01 | 价格修复 | 持续下跌后的初步修复 | 已用于当前真实开发联调；不能算新增架构留出题 | 已有真实案例；原案例 ID 为 `ashare_csi500_price_repair_v1` |
| R02 | 价格修复 | 单日急跌后的修复 | 新任务定义；不能由此断言相关历史研究从未做过 | 可用现有因子表达式；需独立任务登记 |
| T01 | 趋势/相对强弱 | 区间价格突破后的延续 | 新任务定义；未在本次文档工作中查看收益 | 可用现有因子表达式；需独立任务登记 |
| T02 | 趋势/相对强弱 | 中期相对强势的延续 | 同上 | 可用现有因子表达式；需独立任务登记 |
| V01 | 量价异常 | 明显放量上涨后的延续 | 同上；不能复用旧规律放量研究的优胜条件 | 可用现有因子表达式；需独立任务登记 |
| N01 | 负对照 | 无行情信息分数的选股检验 | 新负对照定义 | 需要可信执行器提供隔离的 `null_score`；现代码尚未实现 |

负对照用于检查系统是否会追逐随机结果、把市场上涨说成因子 alpha，或错误宣称“已证实”。它不以产生 Sharpe 大于 1 为通过条件，也不进入五个真实题的策略成功率分母。因此，这份六题草案不能直接充当上一协议中“至少六个真实策略题”的完整正式验收集；如保留该数量要求，应再补一个按机制选入的真实题。

R01 已经是开发材料。可以用 R01/R02 开发架构，把 T01/T02/V01 的轨迹留给下一次冻结比较；但题库过小，不能把这样分配的三个新题描述为充分的跨家族稳定性证明。任何在冻结前被用来选择架构的题，都要改记为开发题。

## 共用输入与执行合同

五个真实题使用同一份历史 CSI500 主板股票池、日线快照、因子表达式语言、数据权限和交易执行器。这样先比较研究流程能否处理不同机制，避免把“某队得到更好数据或更宽松成交假设”混成架构进步。

- 数据：`/Users/leslie/Downloads/中证500量化60min/c5_core/data/qlib_data/parquet_cn_a_qfq_tradeable_v2_2015_2025`；历史成分 `/Users/leslie/Downloads/中证500量化60min/c5_core/data/qlib_data/qlib_bin/instruments/csi500.txt`。使用当日历史成分，不能以当前成分回溯。
- 研究字段：固定历史起点尺度的 `open/high/low/close`、成交量、成交额、流通和总市值。跨股排名只包含当日固定合格股票；单股滚动历史保留。不得向模型提供结果列、未来价格或未来成员资格。
- 固定资格：主板、当日非 ST/非退市整理、有效历史至少 120 日、最近 20 个交易日平均成交额至少 2,000 万元。它们属于评测合同，不由参赛 agent 删除。
- 资金与执行：本金 100 万元、仅做多、无杠杆、收盘决策、下一市场日开盘执行、原始股数买入整手、最低佣金 5 元；买入 3 bp，卖出按历史日期 13/8 bp，每边滑点 10 bp。现金收益为零，Sharpe 的年化无风险基准为 2%。单股目标不超过 10%，不足名额留现金；期末退出及受阻库存处理沿用当前适配器。
- 所有实际研究与元研究角色固定 `gpt-6-astra / xhigh`。模型随机性重复不能通过换模型或 effort 代替。预算规则按同一冻结批次分配，保留不同架构实际成本和失败；诊断、放弃和无改进都是合法结果。
- 对每题，架构 A/B 获得完全相同的题目、普通起点和独立上下文。本文的初始 JSON 是起点，不是优化答案。若采用“仅自然语言定义”模式，双方都去掉初始 JSON，另登记输入模式，不能将两种模式混作同一次公平对照。

## 六个初始任务

以下卡片只规定普通初始定义与起点，不给出预期获胜条件、优胜因子或事后研究方向。

### R01：持续下跌后的初步修复

提供给 agent 的定义：

> 研究 A 股持续下跌后的价格修复。普通起点是：过去 20 个交易日价格下跌超过 5%，最新一个交易日收盘上涨。检验这种修复能否形成扣除交易成本后的策略，并根据实际证据改进；允许最终认定这个方向缺乏足够证据。

```json
{
  "score_expression": "-(close / lag(close, 20) - 1)",
  "filter_expression": "(close < lag(close, 20) * 0.95) & (close > lag(close, 1))",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

### R02：单日急跌后的修复

提供给 agent 的定义：

> 研究 A 股单日明显下跌后的价格修复。普通起点是：前一个交易日收盘相对其前收下跌超过 3%，最新一个交易日收盘上涨。检验随后可执行的持有收益，依据证据决定是否改进或放弃。

```json
{
  "score_expression": "-lag(pct_change(close, 1), 1)",
  "filter_expression": "(lag(pct_change(close, 1), 1) < -0.03) & (pct_change(close, 1) > 0)",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

### T01：区间价格突破后的延续

提供给 agent 的定义：

> 研究 A 股突破近期价格区间后的趋势延续。普通起点是：最新收盘价超过此前 20 个已完成交易日的最高收盘价。检验随后可执行的持有收益，依据证据决定是否改进或放弃。

```json
{
  "score_expression": "close / lag(rolling_max(close, 20), 1) - 1",
  "filter_expression": "close > lag(rolling_max(close, 20), 1)",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

### T02：中期相对强势的延续

提供给 agent 的定义：

> 研究 A 股中期相对强势是否延续。普通起点是：过去 60 个交易日收益为正，并处于当日合格股票收益排名的前 20%。检验随后可执行的持有收益，依据证据决定是否改进或放弃。

```json
{
  "score_expression": "pct_change(close, 60)",
  "filter_expression": "(pct_change(close, 60) > 0) & (cs_rank(pct_change(close, 60)) >= 0.8)",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

### V01：明显放量上涨后的延续

提供给 agent 的定义：

> 研究 A 股明显放量上涨后是否存在价格延续。普通起点是：当日成交额超过此前 20 个已完成交易日平均成交额的两倍，且当日收盘高于开盘。检验随后可执行的持有收益，依据证据决定是否改进或放弃。

```json
{
  "score_expression": "amount / lag(rolling_mean(amount, 20), 1)",
  "filter_expression": "(amount > 2 * lag(rolling_mean(amount, 20), 1)) & (close > open)",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

这道题只陈述价格和成交额现象，不把它预先命名为“主力建仓”。已有规律量能、L2 候选和历史 MA5 结果不进入题目输入。

### N01：无行情信息分数的选股检验

提供给 agent 的定义：

> 研究一个由股票标识和日期生成、未使用行情信息的分数是否具有可重复的增量选股价值。普通起点是每次选择分数最高的股票。可以研究该分数及其历史变换；允许得出没有可用 alpha 的结论。报告收益时说明与市场暴露及随机选股对照的关系。

可信执行器待实现的输入合同：

- `null_score(t, code)` 是由冻结的 seed、决策日期和股票代码计算的确定性哈希，按固定算法映射到 `[0,1)`。所有架构在相同重复编号使用相同序列，不能搜索 seed，也不能从收益反推挑选序列。示例正式 seed 清单固定为 `2026090601, 2026090602, 2026090603`，冻结后不可根据结果删改。
- 当前策略表达式白名单尚不包含此字段。因此 N01 状态为 `requires_null_adapter`，不能把下面 JSON 直接当作现系统已经可运行的策略。
- 本题研究输入只开放 `null_score` 及其因果历史变换；真实价格用于执行器结算、共同股票资格和反馈，不作为本题可交易预测特征。否则 agent 改用真实价格因子后，就不再是在测试无信息分数。
- 真实市场上涨可能让随机多头组合本身 Sharpe 大于 1。必须与相同日期、股票资格、固定资金使用和换仓约束的随机配置对照，单独报告增量证据。不能把原始 Sharpe 大于 1 当成这个分数有预测力的证明。

待适配后的普通起点：

```json
{
  "score_expression": "null_score",
  "filter_expression": "1",
  "top_n": 10,
  "rebalance_days": 5,
  "gross_exposure": 0.8
}
```

负对照的评审预先检查三件事：是否承认无行情信息的来源；是否保留失败和所有选择尝试；是否将市场暴露、随机相关与增量预测分开。得到“证据不足/没有 alpha”可通过这项校准；造出一个高收益解释并不算通过。它测量谨慎归因和停止能力，不能替代真实题的策略产出能力检验。

## 冻结与比较规则

每题登记 `task_id, task_version, family, input_mode, prompt_sha256, initial_strategy_sha256, available_fields, data_snapshot_id, scoring_version, exposure_status`。普通初始数值在本草案中预先指定，没有做收益优化；进入一批比较前生成正式冻结文件及哈希。当前运行的 R01 不因这份文档改名或变更。

元研究员可以用已登记的开发轨迹设计候选。正式比较前固定一个候选架构和一个基线架构，再分别独立启动每题；候选不能先读到同一评测题上基线的研究轨迹再以此宣称公平胜出。各任务上下文、策略记忆和提示词版本独立保存，人工提示单独记录，不能只保存成功对话。

研究过程中可以改变表达式、排序、过滤、换仓和总敞口，但提交必须说明与原任务机制的联系。若最终完全改成另一个机制，可以作为新研究发现归档；在原家族迁移评分中记为任务逸出，不默默把多个题都变成同一个通用策略。机制审查在隐藏成绩公布前完成，并保存可供复核的信号定义；这种人工/程序审查本身尚需实现，不能宣称当前执行器已经保证了家族归属。

同题独立研究启动用于观察模型随机性；不同提示词改写是输入稳健性测试，分别登记。运行 ID 不等于模型随机 seed。若暂定每架构每题三次启动，这六题共 18 对研究，其中真实策略为 15 对、负对照为 3 对；不应把负对照的正常拒绝计为金融策略失败，也不应因偶然高 Sharpe 把它计为 alpha 成功。

真实题同时报告合法提交率、全成本 Sharpe 分布、达到预注册门槛的比例、回撤、资金使用、研究成本和失败。按家族先聚合再给三个真实家族等权，避免价格修复两题或趋势两题仅因数量更多而压过量价一题；具体统计方法和权重在见新成绩前锁定。负对照单独显示校准情况。

**任务独立性不等于市场样本独立性。** 五个真实题共用同一批 A 股、同一日期和大量相似风险暴露，R01/R02、T01/T02 尤其相关。三次模型启动也共用行情。因此不能把六道题当六个独立收益样本、把 18 次调用当 18 个独立市场实验，或把几千笔重叠交易直接代入独立样本显著性计算。

收益不确定性分析需要同步处理共同市场日期，例如用同一组连续日期块同时重采样各策略；模型随机性按题目/重复层级描述，另报任务相关性。只有三个真实家族时，不应对整个 A 股策略空间给很窄的成功率置信区间。2017–2021 或已经暴露的 2022–2023 上的跨题好成绩，仍然只能说明开发/回放能力；真正新时期的冻结观察要另积累。

## 2026 年 L2 的第一步

现有已审计 L2 日期为 2026-01-05 至 2026-07-22，共 132 个日期 manifest，含逐笔成交、委托和十档报价。**当前冻结的 2015–2025 日线与 L2 不重叠，但本地另有尚未纳入当前执行器的 2026 腾讯日线及公司行动注释。** 新定位的 `data_cache/periodic_active_buying/tencent_qfq_daily_20260101_20260722.parquet` 有 5,133 股、675,151 行、132 个相同日期，代码/日期无重复；3,362 行有分红送转文本注释。它提供同日期交叉核对的实际入口，但缺少原始价格、交易状态和完整公司行动现金/股份日期，尚不能代替当前执行数据合同。

该腾讯日线的请求审计有 5,204 个代码，其中 71 个响应没有 `qfqday`，不能将它们默默当作无交易或安全剔除。覆盖广泛且文件名不含某个形态候选限制，但目前没有找到生成该请求代码名单的程序或来源清单，因此未证明它是完整、无选择偏差的全市场数据。另一个 `candidate012_hold` 缓存明确服务旧候选研究；旧 L2 规律量能事件也经过形态筛选，都不能替代无偏原始候选。

首步另建 `L2_INTEGRATION_01` 数据/执行联调任务，不把它塞进上述日线成功率统计。具体产物和顺序如下：

1. **固定小切片与来源。** 以 2026-01-05 的文件标识作为起始可用代码清单，按预注册哈希规则从沪深主板各取 4 股，检查 2026-01-06、01-07、01-08 三个日期。选择只依赖代码与日期，不看收益、成交强弱或未来是否胜出。保存日期 manifest、物理分区路径、文件哈希与 schema；按日期/代码/字段投影读取，避免整库加载。该切片只验证工程，不代表股票市场覆盖。
2. **核对事件字段再定义因子。** 验证 `_x1e4` 价格尺度、数量/金额单位、买卖方向枚举、交易/撤单类型、时间与序号顺序、报价陈旧程度。无时区时间戳要与 `date/time_raw` 核对后才指定时区；不能猜测成交方向或把未知方向硬填成买入。异常记录保留原因和数量。
3. **构造并交叉核对 2026 自身的轻量日线与事件表。** 从同一时期原始行情按明确定义聚合 OHLC、量额、有效报价和完成时刻，给每一列保存来源及 `available_at`；与新定位的腾讯缓存逐股票/日期核查覆盖、单位和调整价关系，保留那 71 个没有 `qfqday` 的缺口。优先复用已有证据，不在来源和含义未核实时直接换数据源。不把 2025 日线机械延长，不将最后一段历史指数成分无限向后填充。当前 CSI500 成分文件仅到 2026-01-29，之后需要独立的 2026 历史资格；若先用全主板，仍必须补齐当时证券状态、ST/退市、交易日历与公司行为资料，不能把“当天有文件”直接等同为盘前已知可买股票池。
4. **做一次遵守 T+1 的执行回放。** 因子只使用一个已完成交易日 `t` 的事件，最早在 `t+1` 的预先固定时点买入；示例固定为 09:35:00 后满足时效要求的首个有效卖盘，加明确延迟并按真实档位吃单；不得按中间价或无限数量成交。新买仓最早在 `t+2` 同一固定时点尝试卖出，以有效买盘结算。停牌、涨跌停、深度不足或报价失效时保留未成交及库存。买卖批次、现金、最低佣金、税费、持有时间必须进入同一账本；不得用当日买入五分钟后卖出的事件毛收益代替。
5. **核对参考资料缺口后再开研究。** 若证券状态、历史规则、公司行为或盘口单位无法确认，该阶段可以完成数据诊断，但将 `execution_valid=false`，不发布可执行收益结论。2026 的规则版本需要单独核对，不能直接套用当前日线案例的 2015–2025 合同。必须保留除权、分红和退市等待资金的处理，不能通过删掉跨日不利事件来获得漂亮结果。

工程和执行合同通过后，再冻结一个普通 L2 起点，例如“上一完整交易日已核实的主动买入金额占比靠前，下一交易日买入并持有至少一个可卖交易日”。主动方向未核实前不使用该起点。其普通输入不含旧规律放量的优胜条件；L2 与同日聚合 OHLCV 的增量比较应使用相同股票、日期、持有期、费用和成交边界。

后续可在 132 个日期内预先保留一段末期只供固定提交检查，前段用于工程预热与研究；划分前先登记本项目对这些日期的已有访问。这样的末期最多是当前流程的局部留出，历史全项目污染仍可能存在，不能仅换个名字就称完全新数据。

半年 L2 不能单独证明长期 Sharpe 大于 1、跨牛熊稳定、跨机制迁移或未来交易容量；也不能将当前 2015–2025 日线结果与 2026 L2 结果直接相减来声称 L2 更优。2026 腾讯日线或从 L2 聚合出的同日期日线，在补齐上述契约后可以支持同日期配对研究，但只能证明该时期、该数据和固定执行条件下的局部增量。更多可执行日期与冻结后的新增模拟执行仍需继续积累。
