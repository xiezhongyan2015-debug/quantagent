# 有资金上限的初始建仓测试

此模式只适用于已授权的Choice比赛模拟账户，从空仓建立PCF跟随组合。它不支持卖出、借款、共用账户子账或自动追价补单。股票池与单股上限仍检查；最低股票仓位/中证500占账户净值比例只作为报告项，因为小额测试可能只动用全账户一小部分资金，不能把它宣称为比赛仓位达标。

配置必须同时设置`initial_build_test=true`、`capital_limit`和`allowed_execution_date`。例如200万元上限不等于必须买足200万元；PCF现金部分、100股整手、科创板保守200股最小买入及不可交易标的可能使实际金额更低。不得为了凑满预算重新分配空缺权重。

生成目标时按批准预算而非账户全部现金计算。每笔在实际限价下计入本金、千分之一费用预留与`execution_fee_buffer_per_order`附加缓冲，向SQLite资金表先持久预约再提交。累计预约超过上限即拒绝；取消、拒绝或超时订单的预约不循环利用。附加缓冲是执行现金保护，不是研究收益中的手续费，也不冒充已支付费用。研究费率仍为买卖各0.001。

获授权模拟测试已确认提交响应的委托号路径为`Data.orderID`，查询订单字段为`orderId`，撤单可通过确切委托号查询到状态8。可卖数量及通用成交编号映射没有因零成交测试而获得验证，因此`validated_with_authorized_test`仍不能默认设为true。

初始测试可用单独受限契约：`initial_buy_only=true`，并在实际验证提交和撤单后设置`validated_submission_with_authorized_test`、`validated_cancel_with_authorized_test`。此时可卖数量保守记0，卖单无条件拒绝；一般调仓入口也拒绝使用这个受限适配器。

成交确认要求该证券在账户当日只有这一笔委托，其确切编号、状态和累计成交量有效，并且持仓数量、该证券买入成交明细数量与累计成交一致。任一来源滞后时继续等待；发现同证券多笔委托、卖出或数量冲突时停止。此约束依赖空仓起步、逐笔执行、单证券单日一次及账户独占，不能移植到存量持仓或高频重复委托场景。

超时或核验异常时仅对本批次已取得的确切编号尝试撤单一次，并查询终态。若在撤单期间成交，记录新增成交量；未知回执不重发。日志绑定账户，批次按日期唯一，失败批次不自动重跑。启动器还应约束明确的启动窗口及一次性运行标志，错过时间不补跑。

回归测试包括实际响应大小写、资金跨重启持久化、不回收撤单预算、卖出阻断、订单/持仓/成交三方数量核验，以及报价源时间戳。离线整篮子演练与周末模拟接口测试都不能替代交易日真实撮合验证。
